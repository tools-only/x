# Git-lite for ARC run workspaces

The ARC thin extension exposes one structured `git` tool. Its process uses fixed Git argv and the run's `workspace` as both worktree and repository parent; the runner does not initialize or commit. `git init` is explicit and only succeeds when `.git` is absent. `status`, selected-path `add`, one-line `commit`, bounded `log`, and bounded `diff` are supported. Remote, branch, tag, checkout, reset, clean, rebase, arbitrary configuration, and shell operations are unavailable.

`add` accepts only specific relative ordinary workspace files. It rejects options, traversal, dot paths, globs, absolute paths, and `data/` or `results/`. The normal `Workspace.path()` policy is unchanged. `.git` remains invisible to ordinary file tools; the Git interface checks it is a real directory under this workspace. The subprocess clears inherited `GIT_*`, disables system/global config, hooks, pager, external diff and text conversion, uses no shell, and applies a 10-second timeout and bounded output.

Git history is optional agent-authored scratch history. Binder continues to validate, version, and load workspace components. A commit does not imply successful Binder validation. The intended loop is: write/edit and inspect the Binder receipt; when a revision merits a checkpoint, explicitly add selected paths and commit a short summary; later inspect status/log and use the Binder-loaded artifact as useful. The next task action is the feedback; stop committing when it adds management cost without useful continuity. No automatic init/commit or persistent obligation is introduced.

Local focused checks establish command behavior and a Binder rescan in an isolated temporary workspace. They do not establish provider adoption or net benefit. Those require separately authorized real-provider runs and matched comparisons.
