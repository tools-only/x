# 下一步决策

启动一条有界研究线：研究“依据动作条件和时序证据识别受控对象，并在证据不足时保留候选”的方法。三次误判是方法失效的案例，不把复述轨迹作为研究目标。题设说明尚无相关研究线；此次建立一条线，后续证据回到同一线。

下一次移动需要可靠的自我定位，而现在可安全等候，因此选择一次 blocking 研究，使用一次性干净上下文中的只读 child。其预期收益是修正会反复影响动作选择的识别规则；首轮只分析已有证据，不消耗新环境动作。不因错误次数或组件空缺创建更多 child。

## 工作包与分解

main 提供三次案例的原始动作前后帧、帧顺序、准确动作及可获得的连续帧。注明动作是否成功执行、缺失信息及当前状态。先让 child 独立列候选，再提供“计数器动画”“碰撞不动”的已知标签，并注明标签依据；不能把 parent 的误判当成视觉事实。当前题目没有实际帧，不能声称已定位对象或验证方法。

研究分三步，在同一 child 内完成：

1. 比较候选解释：最大变化来自受控对象、界面动画或其他环境变化；受控对象也可能因碰撞没有位移。变化面积只生成候选，不能独自确认身份。
2. 产出可执行方法：输入动作与连续帧；列出多个对象候选，记录跨帧外观、位置、持续性、界面区域及与动作方向的相容性；对动画、遮挡、镜头移动和碰撞解释保留不确定性。界面位置和对象外观属于随游戏变化的条件，动作与响应的关系也须按当前规则确认，不能假定按方向必然位移。零位移不能直接排除“自己”。输出候选、支持／反对证据、置信依据和弃判条件。
3. 给出一个新案例的判别方案，以及旧规则与新方法的不同预测。首个里程碑是一份能处理计数器误导和碰撞零位移的方法及其失败边界；不要求立即生成组件。

child 无控制、回放、回滚或私有评估访问权限。它只能分析传入材料、请求具体补充证据和建议测试；main 决定并执行每一次实际动作。

## 有用结果与验证

有用报告须说明适用条件、输入、判断步骤、输出、不确定性、失败边界及下一判别测试。它应解释为何计数器不能仅凭变化面积被选中、为何碰撞时应保留候选。若现有帧无法区分假设，明确不可辨识条件和最小缺失证据也是有用结果；只重新讲述三次经历不算达标。

main 先核对报告是否适用于当前关卡和状态。若仍需证据且当前规则与安全条件允许，由 main 在可通行方向执行一个低成本动作，保留前后帧：受控对象应呈现与动作相容的响应，计数器变化可能不具相同空间对应；若动作受阻、存在联动动画或多个候选同样相容，则结果仍不确定。child 不得自行执行此测试，也不能将动作相关性直接当成充分因果证明。已有日志若包含尚未用于设计方法的案例，优先用它检验，无须假装拥有回放能力。

实际使用后回传精确输入、候选输出、main 的采用方式、错误／弃判和动作及延迟成本，在新案例上与最大变化规则比较。区分“报告已交付”“方法已采用”和“效果有改善”；child 与 main 意见一致不能增加证据强度。

## 持久化与停止

现在不创建持久 subagent、skill 或 Pi task-local tool。持续复发且多轮独立研究确有收益时再考虑持久 subagent；方法在新案例中有可说明的收益且边界清楚时再考虑 skill；仅当出现明确、可重复的机械处理需求时考虑通过 pi.registerTool／项目声明式 substrate 建立工具。memory 也不固化“最大的变化块是自己”或未证实身份；仅在研究线的 agenda/checkpoint 记录问题、备选解释、已知反例、当前不确定性和下个测试，避免形成重复研究。

预算为一轮报告，必要时仅追加一轮携带新证据的反馈，以及最多一次经 main 确认安全的判别动作。方法达到上述里程碑即结束首轮；缺帧或无法安全区分时暂停并记录所需帧／动作条件；预算耗尽或新增材料不再改变判断时停止。保留未决问题及重新启动条件，不将暂停、空结果或未验证的方法包装成成功。
