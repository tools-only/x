# Develop a task capability

Main chooses whether development is worthwhile, its content and its carrier. Memory holds scoped knowledge; Skill holds agent-executed steps and decisions; Tool holds executable computation; System Prompt holds scoped behavioral guidance; a saved Subagent holds a reusable responsibility and independent context. A candidate can be provisional or local; keep its uncertainty explicit.

Submit complete content through task_harness_create. It saves and selects by default; assembly=false saves only. Tool trial can return the first computed value in the same call; ARC trial={current_grid:true} supplies input.grid. Saved Subagent run can return its first answer. Research, review and a separate development_intent are optional.

For short Memory text use task_memory_pool(action="capture",items=[{content,scope}],select=true); omit select for archive only. For temporary independent work use delegate_task(task,output_contract,stop_when,budget), with tools/context_recipe specifying evidence. No saved role is needed. If either entry is hidden, activate its exact name with task_harness(action="activate",enabled_tools=["<tool name>"]).

Minimum candidates: Memory {component:"memory",key:"stable-name",atom:{subject:"...",predicate:"...",value:"authored fact or hypothesis"},validity:{scope:"task|episode|level|state"}}; choose one scope and runtime binds omitted task/instance IDs. validity_bindings is not validity. System Prompt {component:"system_prompt",name:"stable-name",content:"authored policy",scope:"when this applies"}. No creator read is required for these two kinds.

For Skill/Tool/Subagent, author complete content using the current contract; creator templates are optional references when details are needed. A supplied creator_ref must match the current version. Publish with task_harness_create or task_harness(change); no prior manual read is required for valid content. Reuse the same conversion intent when resuming. If new evidence, task priorities or remaining cost change its value, narrow it, defer with a reason and reconsider_when, or drop it with a reason through task_harness(action=development_intent). Preparation is not a commitment to keep investing; existing validation still applies.

task_harness_create installs by default, retaining eligible existing selections; assembly=false stages only. task_harness(change) without assembly only writes the pool. An explicit assembly with expected_assembly_revision and selected_resource_refs selects the written versions plus existing versions to retain. Check publication, installation and trial receipts; if selection fails after writing, repair assembly without recreating the written versions.

Follow the receipt's use entry: apply Skill instructions already in context, reading only to recover missing text; invoke the Tool and check its value, or delegate to the selected Subagent and inspect its answer. Selected Memory and System Prompt refresh on the next provider request in the same run. Descriptive Prompt scope text is not automatic expiry; exact task|episode|level|state scope or explicit validity binds its lifetime. Creation, exposure and citations alone do not prove use or help.

Distinguish a correct local effect from a correct goal or solution. Preserve counterevidence and revise affected checkpoint beliefs, objectives and next steps; return useful trial evidence to the relevant research line. Retain, revise or retire based on task benefit and cost. Permissions, budgets and environment boundaries still apply. Full development guidance is available with task_harness(action=contract,topic=development,section=all).
