# Development reference

Minimum candidates: Memory {component:"memory",key:"stable-name",atom:{subject:"...",predicate:"...",value:"authored fact or hypothesis"},validity:{scope:"task|episode|level|state"}}; choose one scope and runtime binds omitted task/instance IDs. validity_bindings is not validity. System Prompt {component:"system_prompt",name:"stable-name",content:"authored policy",scope:"when this applies"}. Complete valid content requires no prior creator read for any kind. Skill/Tool/Subagent templates are optional references; supplied creator refs must match their current version. A failed batch returns indexed independent repairs before component writes; repair them together and retain valid explicit refs.

Operation-specific instructions retained from the pre-optimization prompts.
These apply under their stated conditions; on-demand delivery does not make
required steps optional. Runtime receipts supply current references and state.

Reconsider capability development when an event exposes an operation gap: a
reliable causal relation, repeated manual calculation or error, a falsified
strategy, a material goal-model change, a level transition, or a parent-authored
planning_gap. Ask what operation would be made repeatable or independently
checkable. An absent component type is not itself a gap, and this check is not
a pre-action gate. A single informative probe may already justify a Skill,
Tool, Subagent or scoped system-prompt policy; no review window is required.
If the objective remains unclear and Auto-Research is available, a bounded question about its
representation or evaluation can be more useful than repeating identical probes.

When an operation would help the next task decision, submit its complete candidate
directly through task_harness_create. Runtime records the authored operation and
installs exact written versions. A pure Tool trial returns its result in the same
call; on ARC, trial={current_grid:true} supplies input.grid. Check the value against
the observation before using it. Creator details are optional references; an
initial conversion-intent call is unnecessary. Research candidates are optional
inputs to the same parent choice. Reassess development when evidence, priorities
or remaining budget change; direct task work can have higher value.

You can save a provisional, scoped system_prompt through task_harness_create,
which selects it by default. State how to
work across its applicable decisions and when to reconsider; a level/phase policy
need not last the whole game. Selected content refreshes on the next provider
request in this run. Descriptive scope text does not expire it; exact scope or
validity controls expiry. Keep concrete facts separate, preserve platform
constraints, and revise or replace the selected policy as the strategy changes.
Skills can implement planning as well as observation; small computations can merit
tools for reliability or saved reasoning; the same evidence can merit an independent
Subagent context. No cross-level reuse or heavy-computation threshold is required.
Inspect publication, installation and use receipts. Preserve any committed version
when repairing installation or a failed trial. An existing development intent can
be revised, deferred with a resume condition, or dropped through
task_harness(action=development_intent,development_intent=...). A creator read or
related Memory write alone does not perform the chosen operation. Retain a useful
capability; revise or stop investing when evidence no longer supports its value.
