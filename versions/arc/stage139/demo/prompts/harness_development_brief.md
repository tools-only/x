# Develop a task capability

Main chooses the operation, authors the component and selects its use. Start from a concrete uncertainty, repeated computation, error or missing planning step; an absent component kind is not a gap. Exploration, objectives, competing hypotheses and solution planning are valid work. Compare likely task progress and reliability with development cost and remaining budget. First-use and local procedures are valid; research and review are not prerequisites.

Choose by job: Memory stores scoped facts or provisional conclusions; System Prompt guides decisions within a scope; Skill teaches a procedure; Tool executes a supported computation with checked inputs/outputs; Subagent provides a reusable independent context. Memory does not finish a chosen procedure or computation, and an ephemeral delegate is not a saved Subagent.

Minimum candidates: Memory {component:"memory",key:"stable-name",atom:{subject:"...",predicate:"...",value:"authored fact or hypothesis"},validity:{scope:"task|episode|level|state"}}; choose one scope and runtime binds omitted task/instance IDs. validity_bindings is not validity. System Prompt {component:"system_prompt",name:"stable-name",content:"authored policy",scope:"when this applies"}. No creator read is required for these two kinds.

For Skill/Tool/Subagent, read the matching creator once, reuse its creator_ref and fill the returned template. A prepared creator supplies the publication contract; no other development contract is needed. Publish with task_harness_create or task_harness(change). Reuse the same conversion intent when resuming. If new evidence, task priorities or remaining cost change its value, narrow it, defer with a reason and reconsider_when, or drop it with a reason through task_harness(action=development_intent). Preparation is not a commitment to keep investing; existing validation still applies.

To publish and select in one call, include optional assembly with the current expected_assembly_revision and selected_resource_refs for existing versions to retain; the call's successfully written versions are added from native receipts. Omit it for pool-only creation, then assemble exact kind:name@vN refs separately. Check both receipts before use. If selection fails after writing, repair assembly without recreating the written versions.

Follow the receipt's use entry: load and apply the Skill, invoke the Tool and check its semantic value, or delegate to the selected Subagent and inspect its answer. Selected Memory and System Prompt enter later parent context. Cite the exact component in a task decision, make a checkable prediction and compare the actual outcome. Creation, exposure and citations alone do not prove use or help.

Distinguish a correct local effect from a correct goal or solution. Preserve counterevidence and revise affected checkpoint beliefs, objectives and next steps; return useful trial evidence to the relevant research line. Retain, revise or retire based on task benefit and cost. Permissions, budgets and environment boundaries still apply. Full development guidance is available with task_harness(action=contract,topic=development,section=all).
