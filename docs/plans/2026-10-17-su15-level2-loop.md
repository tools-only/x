# su15 to level 2: measure, diagnose, optimise (2026-10-17)

User request (2026-10-17): "check and optimize until the version can solve ARC in the certain level". The request names
no level; the target below is chosen here and can be changed.

## Target

- **Rung 1:** su15 level 2 completed within the game's own budget for it (210 actions, 5x the baseline of 42) in at
  least 2 of 3 runs. Every recent su15 run stalls on level 2. Level 1 is completed in most runs (R1: 3 of 3 base forks
  within 40 actions; the fork-test source at #33).
- **Rung 2**, once rung 1 holds: level 3, with a held-out game checked alongside, so the gain is not su15-specific.
- **Version:** `claude/r03b-repeat-20261016`, which is `r03b` (base, better than the r03b-simple branch on su15 in R1)
  plus three fixes:
  - collapse of repeated calls in the history;
  - a stop after 3 identical provider errors;
  - a loop guard that counts repeated calls that succeeded.
  See [the refusal record](2026-10-16-provider-repeat-refusal.md).
- **Constraint:** general mechanisms only. Nothing in code, prompts or tests may name su15's objects, colours, layout
  or goal (`docs/development-workflow.md`, and the project rule against task content).

## Iteration L0: baseline (no change)

- Three full su15 runs from the start on the version above. Pilot settings: `0 6000000 0 SNAPLEVEL=1`. That means no
  action cap beyond the game's per-level budgets, a 6M budget-token safety cap per run, no time cap, and a snapshot
  after the decision that completes level 1, for later forks.
- yibu / qwen3.8-27b, thinking off (Completions, qwen dialect), text+image. Launched together.
- **Measures per run:** levels completed; actions per level; budget tokens; GAME_OVERs per level; refusals and
  restarts; and on level 2 the beliefs about what actions do, against what the level needed.
- **Budget:** at most about 15M budget tokens (3 runs, each 6M at most; the fork test's runs used 2.4-4.7M for level
  2).
- **Decision:** if rung 1 holds (2 of 3 complete level 2), go to rung 2. Otherwise read the level-2 failures, choose one
  general change, and test it with paired forks from the L0 runs' level-2 snapshots (iteration L1, its own budget
  recorded before launch).
