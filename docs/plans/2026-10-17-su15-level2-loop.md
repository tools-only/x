  - collapse of repeated calls in the history;
  - a stop after 3 identical provider errors;
  - a loop guard that counts repeated calls that succeeded.
  See [the refusal record](2026-10-16-provider-repeat-refusal.md).
- **Constraint:** general mechanisms only. Nothing in code, prompts or tests may name su15's objects, colours, layout
  or goal (`docs/development-workflow.md`, and the project rule against task content).

## Iteration L1: identical calls that change nothing get a reason and an end (built 2026-10-17)

- **Claim.** If repeating an identical action that changed nothing is refused with the reason, an unavailable action is
  refused with what is available, and the history shows a call repeated across decisions once, then:
  - no run loses 10 or more consecutive actions to one identical action that changed nothing;
  - no run stops on the gateway's refusal;
  - levels per run are no worse than L0's.
- **Design (one factor: repeated identical calls that get nowhere).**
  1. `arc_action` refuses an action identical to each of the last three played (same name and arguments) when each of
     those changed at most 2 cells. The refusal names them: "ACTION6(31,15) was played 3 times in a row (#249–#251) and
     changed at most 2 cells each time; it changes nothing here. Play a different action first." Any other action
     lifts it. The refusal reaches the loop guard as a failed call, so three identical refusals end the decision.
  2. An unavailable action is refused by the tool's argument preparation, which runs before schema validation, with
     the reason: "action 'RESET' is not available now (available: …; last action played: #240 RESET)". The enum
     stays per-state, and no unavailable action reaches the bridge.
     `tests/arc_thin_action_surface.test.ts` keeps its intent; its "Validation failed" text check becomes a check of
     the new reason.
  3. The history collapse treats a run of identical calls as continuing across decision prompts, since the gateway
     does. The prompts stay; only the repeated calls are dropped, and the kept one shows the count. The smoke's
     imitation gateway counts across prompts too.
- **Negative cases.**
  - A game where an action that changes 2 cells or fewer must be repeated: the refusal lifts after any other action, so
    such play costs one extra action per 3.
  - The agent keeps trying the refused action: the loop guard ends the decision after 3, and later decisions are refused
    the same way until another action is played.
- **Test.**
  - Offline first: unit tests for each part, the refusal smoke (gateway imitation across prompts), the full TS suite and
    the native smokes against `33f4c5bf`.
  - Then 3 full su15 runs with L0's settings (≤6M each; budget ≤18M). They are compared with L0's runs: levels per run,
    runs of 10 or more identical do-nothing actions, provider stops, RESETs and budget tokens per level.
  - Keep L1 if levels per run are no worse than L0 (5 in 3 runs), no run has such a streak, and none stops on a
    provider refusal. Rung 2 (level 3 in 2 of 3, then a held-out game) is checked on the same runs.
