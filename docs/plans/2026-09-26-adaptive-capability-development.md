# Adaptive capability development

Status: implemented; verification results are recorded in the linked report below.
Work remains on the current branch. Existing runs and unrelated changes are preserved.

## Ordered change

1. Broaden component purposes and trial space before changing the reasoning workflow.
   A single-situation or tentative method can be a Skill. A small computation can
   justify a Pi Tool for accuracy, consistency or reduced reasoning cost. A first-use
   clean/prepared context can justify a saved Subagent. A scoped, provisional
   system-prompt segment can reconfigure the parent's planning behavior for a
   phase/level; task-wide permanence is not required. Memory remains scoped facts,
   hypotheses and concrete state-independent conclusions, not the default home for
   all behavioral methods. Keep executable contracts, creator provenance, exact
   versions, permissions and actual component scope; do not add semantic admission
   scoring or require previous research/evaluation.
2. Change the parent workflow from retrospective extraction alone to adaptive
   task-solving capability development. When the environment/objective is unclear,
   gather evidence and form local methods without inventing a global goal. When
   evidence supports a working objective, compare current methods against it and
   choose strategy, representation, computation or context work worth developing.
   These activities can coexist and can return to exploration after counterevidence.

## Decision and alternatives

Use parent-authored decisions in the existing checkpoint, reviews, components and
research records. No new Harness kind, phase state machine or runtime maturity
classifier. Fixed stage progression would fail on uncertain or changing objectives;
prompt-only permissive wording would leave system-prompt followup and compatibility
admission gaps intact. Therefore update guidance and the existing reachable public
paths together, keeping the runtime semantic-neutral.

The parent may reconfigure its work through an exact-version system-prompt segment
and explicit assembly. Scope and reconsideration belong to the authored policy;
facts and plans do not automatically become system authority. Main owns experiments
and component changes, child research is read-only. Platform constraints are not
overridden. No quotas, compulsory research, compulsory role creation or ARC action
gate. Compare discovery value, task progress, error risk and actual cost, not merely
whether an operation is difficult or has repeated before.

## Flow and failure handling

Known/unknown objective -> next worthwhile learning or solving operation -> choose
direct action / component development / research -> author and explicitly assemble
if selected -> trial -> distinguish local prediction, goal progress and method cost.
Reconsider when the parent's own deferral condition is met, an assumed target fails,
or manual reasoning errors accumulate. A supported local step cannot certify a
strategy or completion criterion. Unknown goal and uncertain strategy are legitimate
inputs, not failed readiness gates. Research can produce problem formulations,
alternative strategies or test designs before decisive environment checks exist.

## Implementation ownership

- Root: process/index/ARC/research prompts, preinstalled creator guidance, this plan.
- SOL: system-prompt followup/native and compatibility reachability plus regression
  diagnostics, without invented creators or automatic component selection.
- Verification: behavior at Pi/provider boundaries, final real-SDK smoke; autonomous
  real-provider method/strategy quality remains distinct from deterministic wiring.

## Acceptance

- An unknown goal can coexist with an exploratory method/policy; no complete
  success-condition dossier needed for admission or actions.
- A later parent-authored level policy enters the pool, is selected and appears in
  the actual system overlay; a revised policy replaces its old selected version.
- System-prompt development can remain pending independently of Skill reuse and
  Memory writes; no need to fill a carrier table before continuing.
- Scoped one-use candidates and small computations remain structurally admissible;
  candidate status is not a quality endorsement.
- Real SDK smoke covers five kinds and both length-continuation routes per AGENTS.
  Diagnostic tests do not prove natural policy adaptation or competitive research.

The deferred research backlog B/C/D remains relevant (question continuity,
parent-owned probes and cognitive continuity), but is not wholly implemented here.

## Implementation details

The existing `capability_extraction_process.md` filename is retained for callers,
but its body now describes adaptive task capability development. ARC entry,
opportunity, research and creator guidance use the same broader purposes. The
periodic reminder no longer tells the parent it must extract a new method from
the last five actions before acting; its evidence window is an entry point into
the task problem, not the boundary of the problem or a phase classifier.

An explicitly nominated system-prompt carrier now survives as a followup, with
callable change/assembly preparation and no Skill creator dependency. Conditional
system projections no longer require `always`, task-wide scope and stable status;
source/authority checks still apply. The exact selected version reaches Pi's next
parent turn and declared validity governs expiry. Main must author and select a
revision: runtime never infers the strategy or changes phase on its behalf.

Guidance exposure and provider telemetry derive the process heading from its
source instead of duplicating an old literal. Regression checks compare the full
body, hash and provider delivery, including wrapped text and periodic contexts.
