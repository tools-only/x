## Problem and falsifiable claim

The PPT path already executes components and orchestration from LiveAgentSelf, but reflection activates within a response, and delivery uses a fixed self-review form. It has no general review-routing lifecycle, validation windows, or reflective memory/context policy. Claim: one request-boundary transaction on this existing object can change the next actual tool schema, input and control relation while retaining one serial continuation and rejecting unauthorized, stale and half-committed changes. This removes manual publication and remembering to recover evidence. It does not claim autonomous adoption or better task outcomes.

## Design and cost

Extend the existing root and component executor; do not add agents, registries or binders. Explicit user manifest supplies protected boundaries, capability grants, budgets and acceptance. A serial request pins active definitions; reflection prepares a candidate and activation happens before the next request. META routes objective events to modes/evidence/same-root ledger only. Same agent owns all conclusions and adoption. Modes keep protocol entries available; schema and execution entry both enforce their surface. Historical evidence, costs, permissions and knowledge are never restored backwards.

P0 acceptance facts enter the next Mirror and validation window without prompting. P1 capsules index complete recoverable evidence, with bounded pure replay. P2 snapshots are inactive data and restore creates a new revision. P3 memory policy, tool source and context policy affect subsequent retrieval/schema/input. P4 request cost is counted once with participating versions and prediction/observation records. P5 is lineage metadata, never automatically inherited. Completed windows retire from active projections; ledger and snapshots remain readable. No component-count or reflection-rate reward.

Additional resident cost: protocol tool schemas, compact structural header and dynamic tail, and contract-mandated boundary requests. No heartbeat, review worker, minimum spend or mandatory modification. Compare reuse of existing self/NativeRuntime with a separate implementation: reuse keeps a single executing object and preserves old PPT regression coverage. Baseline remains available without the explicit v1 manifest.

## Pre-run protocol

Stage 0: bounded Node protocol tests plus real Pi/scripted-provider PPT integration and existing PPT regressions. Negative cases: stale/unauthorized/protected writes, transaction-chain failure, active-step migration, schema/entry mismatch, replay isolation, failed watch/projection, budget stop, plain-text exit and crash coverage gaps. Unknown environment dependencies stay explicit.

Stage 1: exact az / qwen3.8-27b only, existing registered configuration; inspect registration without revealing credentials. Freeze an existing real financial PPT task with 8–12 distinct content units and source hashes. Calibration A up to 30 min/60 requests, then B twice from the same seed, no inherited defaults. Numeric total resource caps need explicit authorized values before provider calls; requested asynchronously during implementation. No paid request until prerequisites and stage 0 pass. If az is unavailable stop the run part and preserve response evidence, never switch providers. No retry-to-success, no in-run developer steering. Stage 2 requires a complete autonomous-change/use chain; otherwise do not launch it. Stage 3 deferred.

Primary observations: unit coverage/numeric/citation matching, renderer facts, failures, review lifecycle and actual post-change use; total tokens/cost/time/storage separately. Semantic completeness, aesthetics, cognitive continuity and net benefit stay unverified where no suitable evidence exists. Independent comparable A/B/C trials are required for net benefit. Failure to reach the next request using new definitions falsifies the wiring claim. Legitimate keep does not falsify autonomy, and does not demonstrate hot modification.

## Implementation and validation

Implemented SelfRoot on the existing LiveAgentSelf, scoped PPT extension integration, a separate v1 seed prompt and bounded experiment runner. No runtime agents were added. Request-boundary commits run after all response tools settle and before Pi refreshes its executable tools. Pi pre-execution schema rejections are collected from turn receipts before committing; a failed reflection aborts the whole chain. Failed compensation pauses. The same Agent owns review/validation decisions and its own compaction summary. Generic component-storage writes are refused.

Commands from the checkout (`PYTHONPATH=src` for Python):

```powershell
node --experimental-transform-types --test --test-concurrency=1 tests/self_root.test.ts tests/live_orchestration_core.test.ts
python -m pytest -q tests/test_evo_ppt.py tests/test_evo_ppt_pi.py --basetemp=runs/evo-v1/stage0-verified
```
