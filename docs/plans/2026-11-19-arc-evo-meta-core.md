# ARC 七焦点 Evo Meta 主路径

日期：2026-11-19。状态：ARC 主路径已接线，真实模型效果待验证。

> 前段保留七焦点建立时的设计与证据。文末“上下文窗口与缺口路由”是当前默认行为；`ARC_THIN_META_ROUTING=sweep` 可恢复七焦点以作比较。

## 问题与命题

`runs/su15-selfloop-evo7-20261119-az-qwen` 为了开启旧七焦点，关闭了 Agent 自身运行状态对象。该运行在首次任务动作前遇到 provider 容量错误，不能说明七焦点质量。旧七焦点读取 Binder 和 `data/self`，ARC 的 CH 观测、紧凑任务视图、组件版本与使用回执却进入另一条路径。默认任务运行因此需要一个可直接检查的主路径。

命题是让生产 ARC 使用 Evo Meta 的阶段视图、七个专项焦点与唯一版本账本，并把现有 CH 观测和任务输入压缩接入该路径。若实际请求重复投递棋盘，专项无法修改并激活组件，或复盘打断任务而无法恢复，命题失败。

## 设计与成本

- ARC 的 `SelfRoot` 对象保留为运行状态存储，记录 revision、组件、策略、执行位置、任务结果、用量及证据引用。Evo Meta 决定复盘触发、阶段窗口及焦点推进。
- 真实 ARC 默认使用 Evo Meta 完整七焦点。Agent 可主动请求，过关后触发，连续 50 个真实动作触发兜底。七个焦点共享一次阶段窗口。专项回合暂停游戏动作，修改在下一请求边界激活。
- 任务轮沿用 CH 当前观测、差分、最多一张有用的补充中间帧、近期记忆及按需引用。Meta 回合发送紧凑阶段状态、当前焦点与能力版本，并留出按需读取入口。普通任务回合只保留当前状态投影，不重复投递旧历史。
- 生产 ARC 入口固定此主路径。旧模式仅供历史诊断与已存在的比较运行，不作为新实验的维护目标。
- 使用已有权限、版本与请求边界。没有新增管理 worker。新增的模型开销为一次 Meta 归纳回合和确实触发的七个焦点回合，均按实际请求记账。

## 运行前实验协议

- 接线验证采用生产 runner、Pi、ARC bridge，mock ARC SDK 与脚本 provider。要看到任务动作、主动触发、Meta 入口、七焦点关闭和后续任务动作。检查最新任务观测在请求中出现一次，专项请求无需重复棋盘与图像。
- 真实模型验证沿用已授权的 AZ/Qwen 与本地 SU15，只有 provider 能受理请求时才能检验自主判断。比较任务进展、每实际动作的父子总 input/output、补读次数、墙钟时间及 review 开销。未知成本单列。
- 负例包括没有实质改动时焦点明确 `no_change`、pass 中拒绝游戏动作、provider 失败时不把零动作归因于 Agent、恢复后仍从同一任务位置继续。

## 后续设计：从任务负担发现能力（2026-11-19）

### 问题与命题

目前七焦点按组件载体组织修改。它们不直接告诉 Agent 某次 ARC 判断为何重复、失效或耗费动作。`passEntry` 已有轨迹入口，但 ARC 扩展原来未提供 `adapterTrajectory`，归纳轮因此缺少可对照的实际计算和随后动作。窄命题：补上这一材料后，Agent 在正常 Meta 轮能自主指出一次重复工作或可证伪的判断缺口，并提出能在另一输入或下一次真实动作上验证的改变。仅增加组件数量或报告文字不能支持命题。

### 任务能力与可区分证据

下表是开发侧覆盖检查，不进入游戏提示。每行的前两列用于取证，Agent 自己决定候选形式和是否投资。

| 能力 | 机会现象与竞争解释 | 最便宜的区分检查 |
| --- | --- | --- |
| 空间对象与关系表示 | 不同帧上重复分组、计数、求范围，并据此选动作；也可能是先前结果检索失败 | 用一次计算形成候选，在另一帧完成同一定位决定；歧义布局检查对象切分是否丢掉决策差别 |
| 帧差、持续性和身份对应 | 中间帧与末帧得出不同判断；也可能是环境没有提供足够采样 | 在保留帧序列上报告持续到哪次观测；缺帧样本允许未知，身份结论需额外证据 |
| 条件化动作效果 | 相似动作被反复试探；也可能是可见状态漏掉关键条件 | 遮住一条后果，只给动作前观测和动作，先预测影响再揭晓，与简单基线比较 |
| 可证伪假设 | 反例之后旧解释仍影响行动；也可能两种解释尚无可区分结果 | 在分歧处锁定两种预测，揭晓后检查下一决定是否停用失败解释 |
| 有界规划 | 反复手工展开相同状态；也可能单步模型本身错误 | 先在保留转移核验单步模型，再在固定展开预算内与手工规划比较 |
| 历史重算与环境分叉 | 为验证旧判断而重复真实动作；也可能想试当时未选的动作 | 旧输入重算、旧结果遮蔽预测可用记录完成；替代动作需先核验环境恢复，不能仅凭旧 grid 裁决 |
| 决策证据选择 | 历史很长却仍补读，或漏掉反例；也可能当前决策确实需要新观测 | 在历史决策点只给当时已有材料与固定字符预算，比同长度最近历史能否取回决定性证据 |
| 当前知识编译视图 | 修订后旧策略仍显示，或同一规则有多份副本 | 在真实规则修订前后重编视图，核查适用范围、反例和任务轮实际看到的内容 |
| 有界子任务 | 父 Agent 被独立比较打断；也可能核验子结果比亲自完成更贵 | 同模型、限定证据包和保留结果，计入父子总成本、等待及父核验 |
| 主动实验与目标判断 | 动作不能区分竞争解释，或明显改变画面却不推进目标 | 动作前锁定会改变下一步的可见结果；用真实回执和后续任务进展核查 |
| 隐藏状态与跨局迁移 | 同一可见局面产生不同结果，或新局照搬旧规则失败 | 检查少量历史是否改善保留转移预测；把可复用计算与需重新校准的局部规则分开 |

### 机制与责任

1. Runtime 从既有决策、Python 调用、动作回执提供带来源的短样本。它只转录事实，不给能力标签、语义诊断或游戏策略。Agent 可展开原日志，并挑选另一次经历比较。
2. Agent 判断重复工作、证据缺失、错误模型、错误目标或合理不投资哪一种解释符合样本。它提出最小候选和一次会推翻候选的检查。一个候选可以是工具、假设修订、检索方式或下一次探索动作。
3. 先用旧输入重算；涉及因果预测时先锁定预测再揭晓保留结果；旧材料无法裁决时回到真实游戏，等待自然出现的回执。历史状态的替代动作需要可核验的环境恢复。
4. 现有版本、绑定、试用与验证窗口记录候选的后续调用和结果。Agent 决定保留、收窄或撤下。只有替代了重复工作、改变了有效行动或改善了任务进展，才计作能力收益。

首个实现因素是补全归纳入口的事实供给：接入已存在的 `windowBlocksSince` 决策记录，展示 Python 代码与结果、随后动作和可展开的 `decision:N`。请求序号把短记录限制在本次 Meta 窗口；每次请求内的更细时间归属仍需原始日志确认。`transition:N` 可按需先读动作前 grid/动作，再用 `offset=1` 读取实际结果。沿用现有 6K 字符归纳窗口和七焦点执行，不增加常驻游戏提示、字段、worker、强制填写或管理回合。Agent 可以不投资并恢复游戏。入口不自动配对相似样本；历史转移也不能判定未执行替代动作的后果。动作紧随 Python 结果是时间事实，不自动成为因果使用证据。

### 运行前检查与证据边界

先检查脚本 provider 经生产 runner、Pi、bridge、mock ARC SDK 的 Meta 入口能否实际看到至少一个 Python 样本及其后续动作，且游戏动作仍恢复。真实模型对照固定模型、任务前缀、动作和总 token 预算，只改变归纳材料，包含重复计算、已有结果漏取、证据不足应继续探索三种情境。观察机会识别、实际修改、后续语义使用、重复工作、任务进展、父子总成本和延迟。若只增加文字或七焦点开销而没有后续使用或任务收益，修订或撤下入口。尚无授权的真实 provider 预算时，功能、接线之外的层级保持未验证。

本次运行 `arc-thin-smoke` 于 `runs/evo-capability-material-ready-20261119/summary.json`，脚本 provider 与 mock ARC SDK 的普通动作路径通过。首次运行因当前工作树缺少共享 `node_modules` 中的 Python WASI 依赖而失败；接入已有共享依赖后重跑通过。该 smoke 未进入 Evo Meta，故新增材料在 Meta 请求里的实际展示、真实 provider 自主采用和净收益均未验证。实现使用本会话可用的 gpt-6-sol，未使用用户指定的 gpt-6-luna high。

### 中间层接线结果（2026-11-19）

生产扩展在 Meta 归纳入口转录本次窗口的决策工作，并提供 `read_self` 的 `decision:N` 与 `transition:N` 按需展开。归纳结论经 `decide_exit.result.reason/carry` 进入能力轮；能力轮首个焦点现在也记录、显示第二轮入口，避免第一轮结论在七焦点之前断开。修改沿用既有组件发布、版本和验证窗口；本次没有让 runtime 根据轨迹给出能力标签或创建组件。

功能检查 `node --experimental-transform-types --test --test-concurrency=1 tests/self_root_meta_entry.test.ts` 为 5/5。最终全链路脚本运行 `runs/evo-middle-layer-smoke-v6-20261119/summary.json`：生产 runner、Pi、bridge、mock ARC SDK、脚本 provider；1 次 Python 计算后有任务动作，Agent 脚本请求 Meta，归纳入口含该 Python 代码、返回值及动作引用（分别标记 R1、R2）；七焦点逐一以 `no_change` 关闭，之后恢复任务并完成 2 次动作。总计 3 动作、10 决策、7 焦点、0 provider 错误，停止原因 `max_decisions`。`runs/evo-middle-layer-smoke-v3-20261119/pi-events.jsonl` 记录 `transition:1` 的 offset 0 实际返回动作前 grid 和动作，未包含后果；offset 1 的实际读取仍未在此运行中检查。真实 provider 自主识别缺口、创建并语义使用组件、以及任务净收益均未验证。

该链路揭示一个计数边界：`meta_pass_entry` 的 WINDOW 统计为 0 task action，`AGENT_STAGE.task_actions` 为 1；前者只数 SelfRoot ledger 窗口内特定 action fact，后者统计任务工作，归纳轨迹另有实际动作。不能以 WINDOW 的 0 推断游戏未行动。下一项单因素检查是有授权预算的真实模型短程对照：同一模型与相近任务前缀，只改变是否提供该决策轨迹，观察 Agent 是否提出可证伪候选、在后续输入上调用并改变行动，记录父子总成本和失败样本。

## 上下文窗口与缺口路由（2026-11-19）

### 机会、命题与取舍

任务轮曾挂载 `reflect_component`、`reflect_orchestration`，占据工具 schema；七个固定专项无论窗口有没有相应证据都轮转。前次变更及后续使用也未进入下一次归纳。命题：反思写入集中到自进化窗口，归纳轮基于带引用的轨迹和前次变更提出少量可证伪缺口，只为这些缺口打开执行轮，减少常驻上下文和无证据管理轮。若真实 Agent 因不能即时反思而漏掉有价值修改，或证据包丢失反例、不能形成后续能力，命题被推翻。

比较了仅缩短七焦点提示（管理轮不减）、保留任务轮所有反思写入（schema 不减）、按证据选择执行轮。本次实现第三种；`ARC_THIN_META_ROUTING=sweep` 与 `ARC_THIN_EVO_TASK_WRITES=all` 保留比较臂。任务轮仍有 `request_evolution(focus)`、普通任务记忆/文件工具；符合契约的 Python session 函数仍自动发布。版本化 SelfRoot 定义只能通过反思接口写入，普通文件工具拒绝组件路径。没有增加 ARC 能力标签、策略建议、动作字段或内置派生分析。

### 窗口与反馈路径

1. 任务窗口保留当前 CH 观测、记忆、状态和持久 Python session 名称，去掉与 CH `RECENT HISTORY` 重复的 `recent_actions`。主动请求在下一边界进入自进化轮。
2. 归纳窗口的 `PASS ENTRY` 包含本窗口轨迹与可展开引用、前次变更的版本及曝光/调用、原检查和跨轮携带内容。Agent 可在 `decide_exit.result.gaps` 提交最多四个缺口，各有观察、证据引用、候选及可证伪检查；空缺口直接恢复任务。`prior_checks` 可记录对前次变更的结论。调用、曝光及后续动作数只是事实，语义作用仍未知。
3. 每个缺口打开一个执行窗口，展示原缺口、检查和退役条件；Agent 通过对应反思接口修改，或用有证据的 `no_change` 关闭。变更下一请求边界激活，后续调用和动作回到下一次归纳窗口复查。跨窗口携带和前次变更先于最多 3K 字符的近期轨迹，旧材料用精确引用读回。

“反复手工计算、预测被反证、结果不影响后续行动 → 可证伪候选 → 在保留输入或后续真实回执上检查 → 下轮复查”构成机制与能力之间的中间层。它允许 Agent 自行选择空间表示、帧持续性、动作效果、假设、规划、重放、证据选择、编译视图等能力，不指定组件。跨窗口相似性与因果价值仍需 Agent 审阅引用；单一真实轨迹不能裁决未执行的替代动作。

### 成本、验证与下一步

脚本请求里的任务工具 schema 从约 18–20K 降到约 8–9K **字符**，不是 provider token；归纳入口按触发最多约 8K 字符，执行请求数随缺口数变化。新增选择与填报的推理成本、误选和漏选尚未测量。负例包括无缺口、空证据、无收益变更及合理不投资。

- 功能正确：现有定向检查 24 项通过。另审阅了缺口上限/空证据检查与普通文件写的组件边界；这两条新增边界尚无独立测试结果。
- 全链路可达：`runs/evo-gaps-v10-20261119/summary.json`，生产 runner/Pi/bridge、mock ARC SDK、脚本 provider，`passed=true`；15 请求、6 动作、两次归纳、一次缺口执行。`smoke-requests.jsonl` 证实任务轮未挂载两个反思工具、自进化轮有；后次归纳出现 `grid_size` 成功调用和原检查。脚本预定行为不证明自主采用。
- 自主采用：未验证，尚无本版普通真实 provider ARC 样本。
- 净收益：未验证，尚无固定模型与预算的独立对照；字符数和调用数不能证明关卡收益。

若有付费预算，先固定 provider/模型、推理设置、同一任务前缀、动作/时间/父子总 token 预算，以短诊断确认重复负担可观察，再对照 `sweep` 和单因素消融。审阅展示、展开、实际修改、语义使用、下一动作、合理不使用、任务进展和完整成本。`docs/deferred-research-todos.md` A 的 adapter 边界和 D 的跨压缩语义连续性继续开放。
