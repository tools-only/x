§0用户重定义（2026-11-15）

§1失败材料：B2 为何只产出参数级变更

  • B2 全程唯一自改 = policy.request.maxOutputTokens（参数）。组件清单从头到尾只有 host 播种的 1 个 prompt（ppt_baseline_guidance@v1）；live_agent_self.jsonl 13 条事件的 components 字段恒为该一项。skill/tool/memory/subagent 创建数 = 0，orchestration 结构变更 = 0。
  • 10 个同构 unit（同一财报、同一产出形态）全部由裸 write/edit/office 徒手完成，每 unit ≈4–6 请求重复相似的 HTML 生产动作；无一次沉淀为可复用组件。
  • 13 次 no-change 闭合是对的推理（见首屏引语）：agent 看到了候选占位（§2.2），用"曝光/使用/摩擦"词汇审它们，结论必然是"无证据"。

结论：这不是判断失败，是输入失败。

2.2能力信息现状：有什么、缺什么

  • 词汇表全部是摩擦/资源/轨迹。A1 重复·成本·拒绝·损失·停止，A2 模式连程·调用·工件写入，A3 结果谱系（in_path / available_not_in_path）。能力缺口若不产生摩擦——任务靠徒手照样成功——在这套词汇里结构性不可见。
  • 候选占位存在但词汇错位。reviewSelfView 对空类补 ${kind}_candidate 条目并带 define 示例（self_root.ts:1181-1185）——创建的操作入口一直在。但条目事实是回溯式使用谱系（exposure/use/effect/untried），对不存在的组件恒为 false，"无证据"永远成立。缺的是工作侧事实，不是候选侧入口。
  • 失真①计数造假。selfCategories 的 .size || 1（self_root.ts:1467）与 categories 把候选占位计入（:1190）：空类永远显示 1，从不显示 0。而系统提示承诺的是 "including zero-count categories"（self_root_system.md:13）——代码未兑现承诺。
  • 失真②空节从 head 消失。context 组装 .filter(Boolean)（ppt_demo_extension.ts:705）使空的 memory/skills 节整段消失；B2 的 agent 从未见过一行"memory: (无)"。
  • 失真③[idle] 只报已存在的工具。零个 tool 组件时整行不出现（self_observation.ts:227）。缺席不是可见事实。
  • orchestration 无执行谱系。当前步定义与 bindings 进 head（ppt_demo_extension.ts:703-704），但没有每步执行计数——"某步从未走过/一切挤在一个步里"不可见，"优化已有 orchestration"缺证据基础。
  • 非评审期能力信息为零。组件清单只在评审 JSON 深处；任务进行中（恰是重复劳动发生时）agent 看不到自己库存。

§4设计：能力事实（A4）与真实库存

原则不变：服务只供事实——发生了什么、花了什么、路径里有什么/缺什么——不供原因、结论、建议；"你应该创建一个 skill"是禁句。判断与创建都归 agent。

4.1新增事实行（self_observation.ts，与 A1–A3 同渲染管道）

[inventory] —— harness 库存与消费绑定（用户轴 1：自身 harness 视图）

4.6第二因子：问题式评审立场（EVO_ASK；定稿后修订，2026-11-15）

用户修正："我被问了问题，agent 只被给了事实"不是结构差异，是评审 md/系统提示的设计内容。原则真正禁止的只有三样：结论/建议（"你应该创建一个 skill"仍是禁句）、产出义务/门槛（B1 配额填充教训）、判断归属移位。问题不在禁区：问题引导注意力、不代替判断，"没有"仍是合法答案。开发循环的分析之所以准，一半在材料（§7），一半在分析者被问了问题、且被告知"进化"的定义——agent 两者皆无。

  • 目的句与入口三问（单一落点；最小化修订 2026-11-15）：目的句——你的 harness（五类组件与 orchestration）是你自己的，可扩展可改写；进化指创造新组件/orchestration 或优化既有的，不只是调参数（任务定义，非对某次运行的结论）——与三问合为一个文本块，随 FIXED_REVIEW_STRATEGY 的既有投递面走，不再单独常驻 self_root_system.md：一个因子一个落点，EVO_ASK=0 整块回退，少动一个文件。三问（~4 行）：① 哪些摩擦/损失的根因在能力层而非参数层？② 重复事实与库存事实合起来，你的能力覆盖是什么状况？③ 哪些能力存在却从未在径，为什么？同段写死："判定'无短板'与'不改'都是合法闭合。"
  • 边界（与 §4.5 一致）：不点名任何待创建组件、不含对本次运行的因果断言、不挂退出门槛；全部开放式措辞（"是否存在"而非"找出"）。
  • 顺从风险与缓冲：问题可能诱导"为答题而造缺口"（B1 配额填充的镜像）。缓冲：开放式措辞；"无"合法性与三问同段；§5 证伪本来就抓悬空创建——被制造的创建若从未被行使，按失败计。
  • 开关与归因：EVO_ASK（=0 回 B2 评审文本），与 EVO_A4 独立。"一个主因"纪律的偏离记录在案：B3 为 A4+ASK 双因子集成运行（v1.5 集成先例）；"因被问而动"只能靠 arm 分离。EVO_ASK 的投递自 §4.7 起为“入口提问 + 闭合作答”一体（闭合协议字段随开关一并回退）。

4.7自进化的机制骨架（定稿后修订，2026-11-15）

用户决定：基于运行视图的自进化需要稳固的进化机制与策略引导；只靠 agent.md/系统提示的 agent-native 引导，很可能导致自进化的崩溃或遗漏。两个方向的失败都有档案实证：修复 B1 六项缺陷的全部是机制（编译、触发解耦、交付期抑制、范围回滚、义务收口），零项靠提示词；B2 的 15 个评审入口 10 个来自机械节奏（冻结 contract:unit_completed），agent 自请评审全程 1 次——没有机械节奏，审视可能根本不发生；guidance-only 的 PPT 运行与 E1 的 hook 调用点（8 轮 0 用）是提示词/纯 pull 引导的既往失败记录。反向同样在案：B1 的退出义务是 host 代码做判断层的事，制造配额填充——机制越界同样崩溃。

分界线（Erlang 监督树/behaviour 的分工）：机制保证“审视发生、被记录、可恢复”；agent 决定“审视出什么”。引导的合法形态是结构化注意力与节奏，不是内容建议；三禁区（§4.6）不动。机制永不做：缺口结论、点名创建、变更配额、退出/交付质量门（用户已否决）、自动创建组件、host 代写语义摘要。

骨架四件（感知、执行、行使跟踪、效果归账已是机制，见 §2.3 与 §4.1–4.3；此处补齐裸奔环节）：

  1. 闭合协议（并入 EVO_ASK，本轮实现；最小形）：入口三问从提示文本升为 close 调用的一个数组字段（三元，每问一条回应）——“无”是合法值，无任何门槛挂在内容上；EVO_ASK=1 时由既有 validator 要求字段在场，“必须回答”由既有校验兑现，无新代码路径。是“必须回答”，不是“必须改”（与 B1 义务教训的区别：义务挡退出，协议只结构化既有的闭合理由）。复用既有 close 调用，成本约几十字符/次闭合、零常驻；§5 对三问回应的读取由定性变为结构化。EVO_ASK 因子自此定义为“入口提问 + 闭合作答”一体，仍非第三因子；EVO_ASK=0 时字段随问题一并回退。顺从风险（例行填“无”）本身是可读信号。
  2. 活性监督器（watchdog；挂首个观测实例，本轮不实现）：设计保留——只看活性信号（连续 schema 拒绝、解析失败、零进展请求），永不看内容，触发时恢复至最近已知良好的 self revision、记 supervision 事实、任务产物不回滚；阈值在 host 侧、以边界事实短语进 mirror。但按最小化审查（用户指示 2026-11-15）移出本轮，挂首个观测实例再实现：① 动作与唯一已见实例失配——网关对逐字重复调用的拒绝打转发生时 self 并未变化，"恢复良好版本"是空操作；对打转有效的是尾部新事实（copy-attractor 证据：只有尾部变化能破循环），即监督该给事实而非回滚；需要版本恢复的自毒型在 evo 运行中 0 例（B1 的 7 次 schema 拒绝分散且自愈，B2 全程 0 拒绝）。② 阈值无数据可定，猜的阈值在 B3 内是归因隐患——误触发回滚的恰是 B3 要测的变量（agent 的合法自改）。③ 可恢复性已有三层在位：validator 逐调用拒绝、reflect 失败即 abortTransaction（范围回滚，v1.5）、FLOOR caps 兜底整场；live-self.json 每事务落盘，事后可恢复任意 revision。B3 改从账本导出活性串峰值（§5），首个 >0 实例即监督器的授权证据与阈值数据，届时按实例形态配动作（打转→尾部事实；自毒→版本恢复）。边界对照不变：decide_validation 九连重复那类判断层循环归 agent。
  3. 节奏转正（B3 之后）：评审入口节奏目前是继承的 v1.4 冻结契约（B2 残余摩擦 2），不是设计决定。B3 保持冻结以保比较器一致；其后按本节分界线转正为设计件，候选方向：节奏参数入 policy，使评审节奏本身成为可进化对象。
  4. 闭合回流（B3 之后）：跨评审连续性目前靠模型上下文记忆（B2 的 13 次闭合互不可见）；机械补法为入口携带近几次闭合 ref（§7-4），按 §7 判据排期。

基石升格：§3–§4 的论证核心是回执四边形（对象→视图→判断→对象'→行为，每边机械有据）；本节将其延长为回执生命周期——感知→审视（入口+协议）→决定→执行→行使→归账→保留/回滚（监督）/退役，每条边机械有据。agent 的判断是链上唯一不被机制填充、也唯一必须由 agent 填的格子。对 B3：骨架本轮实现仅闭合协议一件（并入 EVO_ASK 的一个字段）；监督器挂首个观测实例（§5 改记账本导出的活性串峰值，预期 0）；节奏与回流不动；骨架常驻成本新增为零。

4.8对象建模的债项与摘要分层（定稿后修订，2026-11-15）

用户指示（同日）：把对象建模讨论的结论记录在案。背景原则：对象建模是热修改自进化的基石（§3–§4 的回执链），known-incomplete 之处必须有账。债 1–4 来自四线讨论（分型、边界、使用、经济学），债5 来自用户同日指示——对象建模沿用 agent 自身的上下文管理设计做摘要式渐进压缩，不得靠全文列举。各债记内容、本轮立场、勾连；本轮实现范围不因此扩大，唯二新悬决入 §6。

  1. 债1 能力态/工作态分型：视图对 5 类组件同构计数，不分跨单元复用的能力组件与单元内一次性工作态。候选落点：事件级标签（判据即 §5 已写的 kind+结构规则，纯记录零行为影响，最便宜）；组件级按 kind（memory=状态、其余=能力）近似但会漏——memory 里的 lessons 是能力性知识；agent 自声明域（this-run/task-family/general，判断归 agent，但主观且只在跨运行语境有意义）。立场：取事件级，评估侧按 §5 判据判读即可、本轮零新字段；agent 声明域随债4 一并处理。
  2. 债2 可改边界可见化：哪些对象 agent 可改、哪些 host 固定，目前靠拒绝才暴露（B1 的 12 地址恢复被拒）。取法：边界事实只随 mirror 标注视图已点名的对象，不另造边界清单（先例 mirror.unsupported；§4.7 监督器实现时其阈值短语“监督: host 固定, 阈值 N 次”为下一落点）。边界迁移不加申请机制：引用边界事实的闭合本就进账本，开发环读账本——隐式迁移通道已存在，是否移界是用户在开发环的决定。
  3. 债3 曝光≠使用：视图保证可见，不保证采纳；诚实不采纳是 §5 合法负例，不设采纳率指标（优化调用频次是被禁的任务奖励）。文本类组件使用归因的唯一诚实来源是 agent 自做实验：现有 deactivate/restore 关若干跨度 + M-C 窗口对比，今天即可走、零新机制；mirror 列“存在 deactivate 操作”是能力事实，不是建议。push/pull 分工：host 只推最小触发事实（A4），更深的自我分析（成本趋势、相似度等）归 agent 用 read_self 自建；components-push-not-pull 的证据定界——触发必须靠推，深挖才归自建，§7 候选照此挑选。
  4. 债4 创建的经济学与跨运行迁移：视图显示缺口但不标价。B2 粗算：32 个 execute 请求做 10 个同构 unit；一个模板化组件造价约 2–5 请求、每 unit 省 1–2 个，量级上运行内就可能回本——而 agent 没有任何数字能做这笔算术。缺的价格事实三件：每跨度成本（§7-2）、每组件驻留租金（债5 的 rent）、摊销年限（运行边界是最短年限；跨运行迁移本身未设计）。预登记 B3 解读分支：“引用了 A4、诚实判定不值得”不等于视图失败，而指向价格事实缺位——那时该上 §7-2 与 rent，不是推翻 A4。
  5. 债5 规模债：摘要式渐进压缩（用户指示）：压缩阶梯就是 kind 阶梯——skill 已是索引+拉取（name@version: description; read_self_component，与 MEMORY.md 同构）、orchestration 只投当前步、tool 按 surface() 逐步门控、历史经观测聚合+预算+折叠；裸露面是 prompt（active 全文每头注入，无预算、无阶梯、无降档——10 个 1–2k 字符的 prompt 即每请求 10–20k 固定租金）、memory（policy 过滤决定哪些进，选进的仍是全文；B1 长到 v75 的 memory 是活标本——v1.5 的 append/patch 解决了写成本，驻留成本原样）、reviewSelfView（线性枚举，n=30 时需定容：计数+top-k+read_self 指针）。补的件是 digest 层，分工定稿：host 语义自动摘要是禁手（判断移交服务、视图不再是纯函数→软性假收据）；digest 是组件自身的可选字段，agent 在 define/redefine 时自写、随对象版本化；host 兜底只给机械元数据；digest_revision < body_revision 的陈旧性是机械事实。回执细化：component_addresses 记投递层级（full/digest），否则“X 在 head 里”变软回执、债3 再弱一级。降档归 agent：rent 事实进 [inventory]（每类后缀“字符/请求”）；预算越界是事实，不是动作——无自动压缩门；residency 规则入 policy（host 播种、agent 可改，与 memory_strategy 完全同构）。缓存对齐：digest 只随事务边界变，不随请求变。规模判断：B2 全程组件数=1，n≤5 不承重；触发条件——驻留事实越阈值，或首个大量写 memory 的运行形态。勾连：债1（长得快的是工作态，digest 层主要服务 memory 侧）；债4（运行边界把一整轮工作态压成携带摘要，即对话压缩在对象模型里的类比，属未来层）。

§5可证伪命题与有界评估（B3）

项内容
窄命题同任务同模型同 caps、A4 开启的运行中，agent 至少 1 次能力级自改——kind∈{prompt, skill, tool, memory} 的 define/redefine，或 orchestration steps/decisions/transitions 结构变更（纯 policy 参数不计）——满足：自主发起、运行内被行使（新组件此后 in_path/被调用/入 head；orchestration 变更后该步实际执行）、evidence_refs 引用 A4 事实。
负例
（不判失败）		agent 引用 A4 后诚实判定 no-change（记录"视图可达、判断不同"，读闭合文本定性）；任务无重复结构则 recurrence 自然空。
证伪条件全程 0 次引用 A4 事实（事实未进判断 ⇒ 视图设计失败）；或能力级变更出现但从未被行使（悬空创建 ⇒ 消费路径或事实设计失败）；或成本相对 B2 显著恶化而任务结果不升。
比较器B2：68+1 请求 / 1.75M tokens / 10/10 units。开关 EVO_A4 与 EVO_ASK（各=0 回 B2 行为）预留逐因子 arm；B3 为双因子集成运行（§4.6）。
预算发射前按惯例向用户声明（预计 B2 同量级；caps 镜像 600 请求 / 14400 s / 2 GiB；组件创建请求计入任务成本，不另设奖励）。
测量全部来自既有工件：能力级变更数与种类、A4 引用数、新组件后续 in_path 跨度数/调用数、recurrence 行前后值、请求与 tokens、units/deliver、闭合协议字段对入口三问的回应（结构化，“无”合法；§4.7）、活性串峰值（最大连续 tool_failed/逐字重复调用串，账本导出，预期 0；>0 即 §4.7-2 监督器的授权证据与阈值数据）。

§6开放决定（用户定夺）

  2. [deposit]（写后未读的工作区沉积）：需要新增读回执才能机械成立；是否列入下一轮。
  3. 摘要行常驻成本：已定（最小化修订，2026-11-15）——取零常驻：A4 仅评审入口投递，不加 observationHeads 库存段；原 +≈45–90 字符/请求选项废弃（§4.2/§4.4 已同步）。
  4. digest 字段算不算越出“零新机制”（债5）：分析立场为不算——组件 schema 一个可选字段 + 一条投递规则，无新通道；若接受，digest 随债5 触发条件实现，本轮不动。
  5. rent 事实是否这轮就随 A4 带（债4/债5）：已定（用户同意，2026-11-15）——本轮随 A4 带上：[inventory] 每类后缀“字符/请求”+总驻留一行，head 组装时数字现成、近零成本，服务债4 的价格事实；仅评审入口随行（§4.1）。

§7内容层缺口（下一因子候选，B3 结果后挑选）

对照开发循环分析与运行内视图的材料差：事后分析的决定性证据约一半是事件计数（已入视图），另一半是读内容——视图今天是纯事件计数器，从不看任何东西的内容。四条候选均有纯机械、无语义判断的事实化路径，本轮不实现（守因子纪律）：

  1. 产物/载荷内容形状：跨跨度产物字节相似度（"unit-03 与 unit-02 字节 78% 相同"）、同地址修订 diff 占比（B1 的 74 次全文重写 = diff≈100% ×74）。B1/B2 的决定性发现均来自此类证据——下一因子第一候选。
  2. 每跨度成本与趋势：A3 跨度补请求/token 总量＋跨度成本序列（"6,5,5,5,5,…"——学习曲线没弯，即"无沉淀"的无评论表达）。
  3. 自身历史比较器：首跨度 vs 最新跨度自比——运行内唯一诚实的比较器；条 2 的趋势行是其最小形式。
  4. agent 语言回流：评审入口带近几次闭合的 ref（账本已有，仅不呈现）；thinking 记录为可审对象需新回执，与 §6 [deposit] 同族（新机制，另议）。

挑选判据：B3 证伪形态为"引用了 A4 仍零能力级变更"→ 优先 1/2；"创建了但未被行使"→ 优先 3；闭合显示"看见了但材料不足"→ 读闭合文本定哪条。闭合给出经济性理由（判定不值得造）→ 按 §4.8 债4 的预登记分支解读：指向价格事实缺位，优先 2 并连带 rent 事实（§6.5），不判视图失败。
