# ADR: ARC goal-first capability evolution and semantic-use quality

Status: partial implementation; real-provider outcome not yet revalidated, 2026-09-28.

## Context

Two real ft09 runs began from pixel-identical frames. The earlier run reached level 1 at environment action 9 and level 2 at action 40. The later 200-action run did not reach level 1 until action 183: it produced more Memory, Skills, reviews and research, but repeatedly tested unsuccessful completion models. Its successful level review arrived late, after the remaining action budget was small. The comparison describes behavior, not a controlled causal estimate of the code change.

The current parent context contains an always-recurring `GOAL-DIRECTED CAPABILITY GAP` whenever a checkpoint strategy exists and a component kind is absent. The extraction guide also asks for a capability-gap check after every informative transition. Component availability thereby competes for attention with the current solution attempt. The action decision ledger separately opens formal validation records for every ARC hypothesis/prediction, even when the parent did not elect to track a durable hypothesis.

The prior postmortem's stronger conclusion is that all five components could be pooled and assembled, but not reliably turned into solving ability. `frame-cell-query` completed five identity-like calls and had 26 snapshot-binding failures; the exploratory System Prompt never upgraded; Research produced candidate methods without a demonstrated adoption/use/feedback join; three of seven Subagent calls timed out; logical-block-to-pixel formulas disagreed; and an unlimited local action cap still encountered a runner timeout. The later 200-action run improved Memory capture (359 versions) but produced no Tool or saved Subagent and upgraded its policy only after a very late first-level success. Neither run establishes the benefit of success-path reuse.

## Decision

1. Put a working goal, best-supported solution candidate, next discriminating prediction and stopping/reconsideration condition before optional capability development. When a candidate can be completed with current evidence, try and evaluate it before expanding the search; counterevidence returns the parent to exploration. This is guidance, not an action gate or a hard experiment budget.
2. Trigger capability-development guidance on parent-authored operation gaps, unfinished selected operations, informative model changes and level transitions. Mere absence of Tool, Subagent or System Prompt is not a gap. Keep Memory capture lightweight and abundant. The main agent still decides whether to author, revise, assemble, trial or do nothing; runtime never fills a component quota.
3. Immediately after an environment-confirmed level transition, project a short, prominent online-planning opportunity with exact window/ref information. The parent reads the fresh frame, rebinds parameters and may revise a scoped planning prompt or method through existing Creator/change/assemble. Historical success steps remain archival. No review adapter, automatic method author or required review gate is added.
4. Keep ordinary action hypotheses in the action/observation ledger. In ARC, create a formal validation only when the parent supplies a stable `hypothesis_id`; preserve direct `task_validation(open)` for deliberate tests. Allow omitted `target_version` on sequential validation assessment/dispute by resolving the current version at execution time; an explicitly stale version still conflicts. Project a bounded unresolved-validation index with an inspect path.
5. Treat a testable parent-authored goal plus success conditions as an *opportunity* to reassess task-level planning before the next win. Show current constraints and alternatives, ask for predictions, falsifiers and the smallest distinguishing live experiment, and offer a scoped System Prompt revision through existing `change`/`assemble`. The parent owns the stage judgment and policy text; runtime infers neither a phase label nor a component quota.
6. Distinguish Tool registration, completed invocation, structural transformation and correct semantic output. A passthrough call remains a real invocation but is not marked as a semantic effect. For live-frame pure Tools, reuse the already-read current exact snapshot during binding rather than scan the growing JSONL twice; the parent authors a bounded point/row/region computation through Tool Creator, verifies coordinate origin against one current landmark and checks the actual value against a contrast. No runtime-generated ARC-specific query body is introduced.
7. Surface research method handoffs with exact report/method refs directly to the parent, without another review adapter. The parent chooses a Skill, Tool or scoped System Prompt, authors it through the appropriate Creator, assembles its version, trials it in a later live turn and supplies a grounded effect assessment. Report completion, pool creation, prompt exposure and method use remain separate states. A local method needs no cross-scene proof before trial.
8. Keep continuous Memory capture as a low-friction pool operation; validity scope follows the claim's evidence boundary (`state`, `level`, `episode`, `task`). Main selects only applicable exact versions for the next context. Memory quantity is not a component quota and does not substitute for procedures, computations or strategy policies.
9. Bound independent audits to one candidate/region/statistic at first, verify the child returned an evidence-linked answer, and escalate only on decision value. Every coordinate-dependent method states its logical origin and maps it to the *current* public frame; old formulas are hypotheses until checked. Saved Subagents remain parent-authored and assembled, distinct from one-off delegations.
10. Keep runner timeout, bridge readiness, provider error, native action budget and scorecard close failures as separate diagnostic outcomes; preserve the last public observation and exact component/assembly refs for recovery. Evaluate future cost reduction only in comparable real-provider runs using actions, resets, tool failures, child timeout, elapsed time and task progress. An offline smoke proves reachability, not solution quality.

## Alternatives

- Require a review or component before the next ARC action: reliable compliance, but violates the agent-owned online decision boundary and can waste task budget.
- Keep the existing per-turn capability reminder and add stronger wording: low implementation cost, but the reminder itself is part of the attention problem.
- Use the event-driven guidance above: fewer intrusive turns and no new component type, at the cost of not guaranteeing a model will create a useful capability. Chosen.

## Acceptance and limits

- Focused context tests show an explicit task operation gap is visible while absence of a component kind alone does not inject a pre-action authoring demand.
- A real-bridge deterministic ARC scenario exposes an environment-confirmed level transition to the next parent turn, with no old action replay and no new adapter.
- Validation tests show ARC action decisions do not produce formal tests without a stable id, omitted version assesses the latest version, and explicitly stale versions fail closed.
- Existing five-component smoke and creator/assembly semantics remain intact. A real-provider comparison with matched action limits is required before claiming better game performance; track actions to first level success, repeated no-progress action classes, reset/failure count, component actual use, post-success planning latency and unresolved validation burden.
- Tool tests must include a non-passthrough semantic value and an identity negative control; current-snapshot binding should succeed with one bounded scan. Research tests distinguish candidate, parent authoring, assembly, later use and feedback using exact refs. A saved Subagent test checks a bounded nonempty answer, not merely completion.
- Real ARC acceptance for closure must pass the bridge, Pi parent, child broker/process, structured child return, router, native Harness mutation, ARC action and later parent turn; cover all five components and provider-length continuation for Auto-Research and ordinary delegation. Real-provider runs are separately required for agent behavior and benchmark performance claims.

This change does not implement deferred Auto-Research visibility variants, child-initiated environment experiments, or cross-compaction semantic-quality evaluation in `docs/deferred-research-todos.md`. The current work also does not claim runner recovery and matched real-provider cost comparisons are complete until tested.
