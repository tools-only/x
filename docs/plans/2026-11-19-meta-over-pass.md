# 跨任务 Meta 开发方案

日期 2026-11-19（Asia/Shanghai）。状态：设计，四层验收均待运行。

## 问题与命题

evo 的中途 META 触发识别渲染、停滞和请求次数。现有专项 sweep 可以逐项检查组件，但进入评审、激活版本和实际试用分别需要独立证据。PPT 的 meta-enabled-05 观察到了评审入口，最终超时且未交付。该跑次无法判定评审造成了多少成本，也未证明修改获得后续应用。

窄命题是按 Pass 阶段读取已有证据，能在相同任务质量下减少相对于固定 sweep 的管理回合，并保留可验证的改进机会。无适用后续工作、无法归因或预算不足时，继续任务。若减少评审后漏掉实际有收益的机会，或任务端到端成本上升，则修订或撤下。

## 职责与生命周期

- Task Loop 组织任务步骤、转换和交付。专项 Loop 通过现有反射接口编辑它。
- Pass 是有边界的一次自进化工作。执行某项诊断、修改或评估，结论写入现有账本。七个专项是可选视角。
- Meta 依据跨 Pass 的自进化进展，决定下一步是否值得投入，以及任务 Loop 是否需要创造早反馈或后续试用机会。T0 可在显式选择时安排一次初始机会。运行期从已有事实恢复进展，所以任务内直接发生的修改也能进入观察范围。

Meta 的观察单位是两次进化评审边界之间的真实任务执行段，评价对象是实际装配的完整 Agent。七个相邻专项只交接修改与证据，期间没有真实任务执行就不生成新的能力评价。专项各自归纳证据并落地修改，已知问题可直接进入专项。复用现有归纳轮作为可选 Meta 入口。

### 输入和输出

复用 SelfRoot 的 review 视图、现有账本及引用。Meta 只看最近执行段和上次方向。详细版本和调用轨迹供专项按需读取。

- **任务表现**包含阶段目标、实际进展与结果、动作、墙钟及父子计算成本。
- **整体能力事实**包含执行段起止 SelfRoot revision 和段内实际请求装配引用、已观察到的行为变化、反证与未验证结论。任务难度或实验协议变化时标明不可比。统计激活和专项完成只用于下钻。
- **下一段试用机会**包含原定工作、可比较的反馈、剩余预算和任务返回点。
- **Meta 输出**为继续、验证整体能力或打开一个定向 Pass 三者之一。需要介入时给出能力目标、依据、正常试用位置和收束信号，复用现有 review 结论和 carry。专项自己选具体组件和实现。若任务流程缺乏反馈或试用点，选 Loop Pass，通过 `reflect_orchestration` 落地。

### 按需触发与机械兜底

- **按需触发**由 Agent 在自然反馈点识别整体能力问题并请求 Meta，例如后续任务缺少验证机会，或当前研究流程反复无法收窄方向。宿主复用现有评审入口。已定位的局部问题可直接进专项，已有候选可试用时回任务。
- **机械兜底**由宿主在现有请求边界检查。自上次实际进入 Meta 以来，任务执行请求数或活跃执行时间任一达到配置阈值，就在下一个安全边界发起一次简短 Meta 检查。第一次从真实任务开始计，复用现有计数及运行记录。首轮实验可沿用 evo 的 12 次执行请求作为请求阈值，活跃时间阈值按任务预算配置。空闲、暂停及专项评审时间不计，避免长等待制造虚假进展。兜底无需先证明有问题，也可输出「继续」并结束。
- **合并与延期**。两路同时满足时合并为一个回合，保留两个触发原因。实际进入 Meta 才重置计时与计数，普通反馈、直接专项和排队都不重置。评审在途、尚无新增执行证据或共享预算不足时不打断任务，兜底到期状态保留至下一可运行边界。任务已经终止则收束，不追加模型请求。T0 可选，依据任务合同安排反馈机会。

候选版本留在专项与账本证据层。阶段从事实推导，允许未知及跳过，无需 Agent 填报状态。

| 阶段 | 谁推进 | 可观察证据与下一步 |
| --- | --- | --- |
| 机会 → 识别 → 投入 | adapter 给出任务反馈，Agent 判断是否值得研究 | 反馈引用和剩余同类工作。重复反馈可合并，理由不足可直接跳过。 |
| 候选 → 装配 | Agent 用现有反射接口写入，宿主在现有边界激活 | 版本、触及地址、下一请求的实际装配。激活后缺席就查装配。 |
| 语义使用 → 反馈 | 后续任务回合实际使用，adapter 给出领域事实 | 版本对应的真实调用或行为，及可比较的结果。装配回执不代表使用。 |
| 保留、修订、撤下或放弃 | Agent 在需要判断时决定，宿主按现有权限执行 | 证据、总成本和决策。没有试用机会则记为未验证。撤下只影响后续执行。 |

Pass 收束时宿主合并新增证据。实际任务试用及反馈在后续自然边界补入，形成下一份整体阶段视图。宿主推进机械状态，语义归因由 Agent 完成。

## 实现顺序

1. 在 evo 的 `demo/self_root.ts` 复用 `passEntry()`、请求 pin 与 review 账本生成只读阶段投影。测试真实任务段和专项间空窗、多 revision、缺失使用证据和不可比结果。只有现有记录无法关联时才补引用。普通回合不渲染此投影。
2. 把现有归纳与固定 sweep 的顺序拆成已有 review 入口的可选路由。测试按需先到、长期无显著事件但兜底到期、双路合并、到期延期、恢复后计数延续、预算停止及回到原任务。保留直接专项、直接返回及 Meta 后单个专项。正常执行新增常驻提示和 schema 为零。短跑试验臂每跑次在线 Meta 最多两次额外模型请求，每次投影最多 300 文本 token，额外证据检索计入共享预算。长跑按预先声明的周期与共享预算评估持续兜底。固定七项 sweep 保留为对照。兜底计量单位与阈值由任务 adapter 配置，PPT 初值为 12 次执行请求，ARC 初值为 50 次真实环境动作，Kaggle 暂用 12 次执行请求作为探索配置。
3. 让三个 adapter 将自身已有的反馈与位置映射成同一阶段视图，保留各 runner 的权限、版本和共享预算。先跑一条分支的接线诊断，再用另外两条验证字段和流程没有依赖第一条任务的语义。每条分支独立验收。
4. 验证失败、跳过、候选过时、预算耗尽、压缩恢复和重复反馈。检查真实请求的增量提示及工具 schema，随后检查实际组件输出、后续任务动作和反馈。ARC 原有 provider 准入瓶颈单独处理。涉及 ARC 父子与五类组件闭环的声明仍按项目要求跑真实 runner 的验收矩阵。

## 实验与交付

每个领域在同一任务底座上比较三臂：保留直接专项但关闭在线 Meta、现有固定 sweep、按阶段进入的 Meta。固定 provider、模型、推理档位、任务条件和总预算，先做探索性接线实跑，再做独立重复对照。ARC 对齐初态并独立运行，不用离线重放推断真实动作收益。PPT 对齐 brief 和质检标准。Kaggle 对齐数据、切分和实验预算。运行前锁定样本数、质量门槛、退出条件及允许退化。T0 另做单因素对照。

报告交付质量、并入全部父子请求的总 token、墙钟、管理轮次、首次有效产出延迟和未完成成本。区分按需、兜底、合并与延期，并记录从上次 Meta 到本次的活跃时间和执行请求数。有可验证的机会时，检查语义使用和后续验证。无按需机会且未到兜底阈值时，应有零额外模型回合。兜底到期但没有值得做的改进时，应能一次收束并回任务。若评审负担减少但总成本或质量退化，不判为净收益。

功能正确、真实全链路、自主采用、净收益分别记证据。关联待办包括 ARC adapter 边界与压缩后的认知连续性。

## 2026-11-19 实施增量

第一步已把 `metaFallback` 的单位和阈值放入 SelfRoot adapter 选项。evo/PPT 为 12 次执行请求，Kaggle 暂为 12 次执行请求。ARC adapter 配置 50 次环境动作，现有 action review 调度读取该值。按需反馈与机械兜底沿用各分支现有入口。

定向检查分别通过 evo 的单位/阈值测试、ARC 的 50 动作测试、Kaggle 的专项集成测试。evo 既有 `self_root_meta_pass.test.ts` 其余断言与当前实现不一致，包括旧的 `stagnation` 触发名和 episode 触发预期，本次未扩范围修正。三个分支的真实 provider 路径、自主采用和净收益均未验证。

第二步增加 `stageView(window)`，从 SelfRoot 现有账本提供阶段请求、任务动作、起止整体 revision、变更引用、最近任务结果和已记录父请求 token。此视图只在进化检查的入口材料中出现，结果归因仍由 Agent 判断。可选路由使用既有 `decide_exit` 加可选 `next_specialist`。选择 `none` 回任务，选择一个专项只运行该专项一次。PPT 和 Kaggle adapter 已选择新路由。ARC adapter 为 `ARC_THIN_META=1` 提供实验入口，先探索后按 50 次动作检查，默认仍使用既有自进化路径。定向测试覆盖三分支的选择、返回及保留旧 sweep。真实 provider、完整 ARC bridge 链路、跨压缩连续性和净收益仍待验证。
