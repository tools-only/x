## 1. 问题与命题

### 1.1 材料

- 另一主机（基于更早提交）：同一动作/坐标循环；混淆关卡编号与预算；压缩 44/149/53 次，wa30 622 步压缩 148 次，
  反复“重新审视棋盘”；python 报错 16–28 次；wa30 L2 596 动作、vc33 L3 223 动作未过；cd82 末尾“无计可施”。
- ds 对比（层级版 vs 纯 Pi）：L1 35 vs 80 动作，但 token/动作约 126k vs 69k；6 次评审；`no_dig_under_player`
  在 44 个转移上都不适用却冻结了动作；L2 第 9 步死亡。
- 本地 su15 三次真实运行（az / gpt-6-luna / low）：defaults 0 关 110 动作；mel4d 1 关 226 动作、99 次驱逐；
  mel4g 1 关 138 动作。按“内部棋盘 + 动作”统计的重复分别为 25 / 39 / 14 次，按整帧只看到 3 / 15 / 0 次
  （第 63 行计数条每步都变）。
- 代码核对：`evict()` 的注释写了滞回，但实现每次请求都从头重算切点（mel4d 98 次相邻驱逐中切点移动 83 次）；
  压缩摘要默认关闭；`show()`（任意帧/区域出图）早已在 prelude 里，但系统提示从未提到它。

### 1.2 看法：重机制在挤占 agent

上一轮把三个核心问题（局部循环、反复重建认知、规律提炼复用不足）都归到“宿主缺少某种机制”，于是方案不断加门：
冻结评审、claims 账本、模型回测、expect 区间、STUCK 提示、放置声明。真实运行里，这些门本身成了成本和阻塞来源
（token/动作翻倍、never-applies 冻结、L2 早死），却没有测出能力提升。

英伟达系的高分方案指向相反方向（§2）：宿主几乎不规定解题方法，只保证 agent **看得见完整证据、记得住自己的结论、
每步说出预期并对照结果**。“预测→验证→排除”和规律复用由 agent 自己在笔记里完成，宿主不替它判断。

### 1.3 窄命题

在 su15 上，用一个开关关掉 review/claims/model/expect/STUCK 等硬机制，改为：短工作方法提示（行动前说预期，
行动后说全部可见变化）+ agent 自维护 `work/GUIDE.md` 与 `work/WORKING.md` + 驱逐前提醒一次、驱逐后把两份笔记放回上下文
+ 切点真正滞回 + 告知可回看历史帧。预期：相对当前配置，过关数不降，token/动作下降，驱逐后不再大段重建认知
（体现在笔记被写、被更新，以及驱逐后第一次动作所需的调用数）。

### 1.4 减少的负担

- 去掉冻结评审、放置声明、claims 守卫、模型回测门、expect 区间约束这些记账往返。
- 去掉切点每次请求都漂移造成的反复丢失和前缀缓存失效。
- 去掉“每批 1–3 步”“必须先写 world_model”等写死在宿主里的方法论；方法由 agent 写进自己的 GUIDE。

### 1.5 推翻条件

- 轻量版在 su15 low/high 上过关数低于当前配置，或 token/动作不降：轻量版不作为主干，回到逐项消融找有效的门。
- agent 在整局中几乎不写 GUIDE/WORKING，或驱逐后仍从帧重建：说明只给载体不够，再考虑 §8 的候选。

### 1.6 范围与非目标

单局在线，不跨游戏、不跨 session；不删除现有机制（开关关闭时行为完全不变）；不改 ARC bridge 和动作语义。

## 2. 英伟达系方案的证据（已更正）

- **AVO**（NVIDIA 博客 2026-08-21）：Opus 5，公开集 100.00 RHAE；通用编码 agent + 持久记忆 + 停滞监督；ARC 接口参照
  VISTA 重写。ARC 代码未公开，监督细节未知，半私有集未测，与裸模型 30% 不是受控对比。
- **VISTA**（MIT，arXiv 2610.02200）：单动作 `play`、免费的 `inspect`（历史帧、放大、多帧对比）、`read_pixels`、
  `history`；GUIDE.md（≤64K 字符，跨关）与 WORKING.md（≤16K，本关草稿）。提示只有四句：用并修订一个紧凑模型；
  每次行动前简述预期，之后简述所有可见变化；GUIDE 放持久理解，WORKING 当草稿。压缩前宿主拦住压缩，要求先把完整
  续接状态写进 WORKING.md，再从新线程以 GUIDE+WORKING+当前画面恢复。
  - 消融（GPT-5.6 Sol，依次累加）：官方文本 13.33 → 图像 47.32 → 放宽限额 51.66 → 连续会话 65.82 → 笔记 70.05
    → 无损记忆+回看 94.10 → 像素读数 99.00。消融是累加顺序的，单项增益依赖顺序；公开集有训练污染可能。
  - 程序化世界模型同样能到 100（表 1 中 Tycho），Retrodict 99.86：**世界模型不是必要条件，也不是禁区**，应由 agent 自选。
  - su15：99/123 动作通全关（人类 361）；我们 138–226 动作只过 1 关。
- **DreamTeam**（NVIDIA，arXiv 2605.09650）：六角色、可执行 predict、每步回测、错误按字段路由；38.4%。所用模型更早
  （Opus 4.6 / GPT-5.5），与 VISTA/AVO 不能直接比较，“越重越差”只是混杂推断。

对我们的含义：middle-layer 已具备“回看”（`frames_of`、`show`）和“代码载体”（`work/`），缺的是告诉 agent、
一个稳定的上下文、和由 agent 自己维护并在遗忘后放回的两份笔记。

## 3. 设计：轻量开关 `ARC_LAYERED_LITE=1`

| 部分 | 宿主做什么 | agent 做什么 |
|---|---|---|
| 预期与变化 | 提示一句：行动前说预期，行动后说全部可见变化 | 自己对照，自己决定排除哪个假设 |
| 笔记 | 提示两份文件的用途；驱逐后把两份文件放在剩余上下文最前面（取驱逐时的快照，至多 12000/6000 字符） | 决定写什么、何时改；方法论、止损、排除表都可以写在这里 |
| 驱逐前检查点 | 剩余上下文超过上限 85% 时，在状态消息里提醒一次更新 WORKING.md | 写下续接所需的全部状态 |
| 稳定上下文 | 切点只在保留部分再次超过上限时才前移，一次退到目标量 | — |
| 回看 | 提示 `frames_of`、`show` 可看任何历史帧/区域 | 需要时回看，而不是猜 |
| 代码 | `work/` 照常可用，`startup.py` 照常自动运行 | 自选是否写模型、搜索、工具函数 |

开关下关闭：冻结评审、claims 与 world_model 的提示和门、expect 检查、STUCK 提示（`ARC_LAYERED_STUCK_AFTER` 可显式打开）。
RESET 不受任何门限制。每次调用至多 16 个动作不变，不强制单步。

三个核心问题在轻量版里的落点：

1. **局部循环**：靠“预期→变化”的逐步对照和 WORKING.md 里的已排除项；循环是否减少用离线统计（内部棋盘口径的重复）看，不在运行时加门。
2. **反复重建认知**：靠稳定切点 + 驱逐前检查点 + 驱逐后放回两份笔记。
3. **规律提炼复用**：靠 GUIDE.md（跨关规律与方法）和 agent 自选的 `work/` 代码；过关时现有的 LEVEL COMPLETE 事件已要求写下能带走的东西。

## 5. 实现

- `demo/arc_layered_extension.ts`：`evict()` 增加上一次切点参数并返回新切点（缺省 0，旧行为不变）；
  轻量模式下保存切点、驱逐后在最前放回笔记快照、接近上限时提醒一次；env `ARC_LAYERED_LITE` 统一关闭各硬机制。
  LEVEL BUDGET 提示在 claims 关闭时指向 GUIDE.md。
- `demo/prompts/arc_layered_system.md`：新增只在轻量模式渲染的工作方法段（替代 Working method 1–4 和两条硬规则）。
- `tests/arc_layered_extension.test.ts`：新增一例，验证切点不漂移、笔记在最前。

## 6. 运行前实验协议（校准，不是净收益）

- 证据层级：功能正确 + 全链路可达 + 自主采用的初步迹象。
- 比较：轻量版 vs 当前配置（已有 mel4d/mel4g，low；high 需补跑当前配置）。
- 配置：az / gpt-6-luna，low 与 high 各 1 次；su15；离线 ARC；上下文上限 65536、目标 32768（与 mel4 系列一致）；
  轻量版不折叠旧结果（mel4g 折叠，mel4d 不折叠）。
- 预算：墙钟 4 小时；动作预算按 bridge 默认（人类 5 倍）。
- 指标：过关数、每关动作、token/动作、死亡、内部棋盘口径的重复、驱逐次数、GUIDE/WORKING 写入次数、驱逐后到下一次动作的调用数。
- 限制：每臂 1 次，provider 错误和随机性足以掩盖差异；只能用于决定下一步，不能宣称净收益。

## 8. 校准后才考虑的候选（来自重型草案）

只有当 §1.5 的第二条推翻条件出现时才逐项加，并且一次只加一项：

- 驱逐时像 VISTA 那样**等 agent 写完 WORKING.md 再驱逐**（而不是只提醒一次）。
- 状态消息里给一行通用事实：本局面+本动作以前出现过几次（按 agent 自己在 `work/` 里定义的状态键，缺省为内部棋盘）。
- 关卡结束时一张只报数的卡片（动作、死亡、重复、驱逐、笔记修改）。
- 宿主在每步执行 agent 写的 `predict` 并回显偏差。

## 9. 交付决定

- 已支持：轻量开关实现并通过单元测试；默认行为不变。
- 未支持：轻量版是否更好；agent 是否会自主维护笔记。见 §7 的运行结果。
