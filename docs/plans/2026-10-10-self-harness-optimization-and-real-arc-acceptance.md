# Self-harness 优化与真实 ARC 验收方案

日期：2026-10-10，Asia/Shanghai。状态：**设计方案；未实施，未启动新实验，各模块收益均未验证**。

**目标：** 优先改善 self-harness 的能力形成、实际使用、验证和维护，随后补齐知识与执行基础，最后评估台账和 critic；以真实 ARC 环境、真实模型运行中的行为与任务收益作为验收依据。

**架构：** 复用现有 Pi、ARC bridge、组件存储、Python sandbox、原生装配和研究通信路径。runtime 处理版本、作用域、权限、预算和事件；父 Agent 或已授权研究 Agent 负责语义判断。优先缩短工作路径，不增加通用“必须反思/必须创建组件”的义务。

**技术栈：** Python runner/bridge；TypeScript Pi extension；任务内 Python skill sandbox；JSONL 事件；yibu / qwen3.8-27b 作为初始真实模型比较条件。

本文是本轮统一设计和后续证据记录入口，采用 [development-workflow.md](../development-workflow.md) 与 [变更记录模板](../templates/meta-harness-change.md) 的同等栏目。实施时逐模块追加结果，不建立相互冲突的验收结论。当前授权为方案编写，不含源码修改或付费运行。

### 1.2 三种路线的取舍

1. **只加强 prompt：** 改动小，但继续依赖模型记住全部手续，难解决过时版本、预算和依赖失效；仅用于最小接口说明。
2. **复用原生能力，补少量生命周期与有效性机制（采用）：** 确定性处理交给 runtime，语义判断仍由 Agent 承担；按模块消融验证。
3. **新增常驻总控/critic 管理全部变化：** 引入额外延迟和共识错误，当前无收益证据；不作为基础方案。

### 1.3 不可改变的边界

- 同一 task 不同 level 可以继承猜想、控制候选和历史经验；旧关证据标为历史来源，新关支持度重新收集。
- 不强制每个动作创建或引用策略；初始探索和临时检查合法。
- 不通过增加调用数、组件数、反思次数来定义成功；合理不使用、放弃创建同样纳入评估。
- 不硬编码 ls20/lp85 的目标、位置、条带含义或已知解法。日志诊断知识只进入开发验收材料，不进入普通游戏 Agent 提示。
- ARC 单次运行只有一条 canonical 历史。组件回退只影响未来配置，不回退动作；RESET 是真实有成本动作。
- 完整当前网格/应提供的图像保持原接口约定。基线为 text-only，不在其他模块实验中同时切换为多模态。
- 不承诺仅靠 schema 能识别所有语义等价的改名规避。明确区分机械保护和真实模型行为验收。

## 3. 统一真实 ARC 验收协议

### 3.1 四层结果分别报告

| 层 | 允许的结论 | 必要证据 |
|---|---|---|
| F 功能正确 | 组件/协议按定义工作 | 定向单元检查、历史日志复算；只是进入真实测试的前置条件 |
| R 真实链路 | 对应路径在真实 ARC 和真实 provider 上执行 | 输入、注册、调用、输出、原生变更、后续父轮与动作关联 |
| A 自主采用 | 普通运行中出现有效采用 | 无指定组件/无答案注入的真实运行；记录机会分母、合理不使用 |
| N 净收益 | 在指定模型、任务、预算下有收益 | 独立重复匹配对照、任务指标与父子总成本，报告不确定性 |

模块的“完成验收”至少满足 R、该模块适用的 A、以及对应 N 条件。只达到 R 时标为“链路通过，收益未验证”，不可宣称优化成功。安全/完整性修复即使 N 不确定也可列为“完整性修复候选”，与性能提升分开。

### 3.2 实验类型与样本

**D：真实机制诊断。** 官方 ARC 环境、真实 Pi/bridge、真实模型。可显式要求测试某组件生命周期，但必须标为受引导诊断。不得将离线合成画面冒充真实状态。需要中后段状态时，优先自然到达；若以记录动作在新官方实例中推进，必须逐步核对状态、计入成本，标为受控前缀，不纳入自主采用结果。不能复制隐藏状态或使用可回滚分支冒充独立生命。

**O：普通自主运行。** 用户目标为解题，提供通用能力入口；不要求“必须创建 skill”“必须拒绝某猜想”。默认先在 ls20、lp85 上做诊断，再加入一个从未用来调提示的可用官方游戏 H1。ft09 已有历史开发使用，不能默认当 held-out。H1 选择清单在实验前冻结；本轮尚未指定，实施前列举可用环境并记录选择依据。

**探索阶段：** 每模块先做最多 4 次短 D 运行（每次最多 20 动作、10 分钟、20 万父子合计 reported token），检查可观测性与负例。不遇到事件则记未覆盖，不重复跑到满意为止。

**确认阶段：** 每个主要变量 A/B 两臂；三个游戏各 3 个独立重复/臂，共 18 次普通运行。AB/BA 交替安排，固定模型/provider、输入表示、推理配置、输出上限与环境版本。每次最多 100 动作、3,600 秒、120 万父子合计 reported token，任一达到即停止；环境原生终止优先。每模块该阶段上界为 18 小时、2,160 万已报告 token，未结算消耗另列。必须另设真实计费硬上限，不能把 reported cap 当账单硬上限。

这是建议的预注册实验包，不是自动运行或付费授权。模块 D+O 上界为 18 小时40分、2,240 万 reported token。不得把 14 个模块一次性跑完；上一模块判断不清时优先定位断点，不能自动扩样或堆叠下一机制。

同预算比较优先使用相同 game_id/环境版本与可控制的种子；官方服务不支持种子时记录限制并轮换顺序，不声称严格配对初态。两个实例并发可能争抢 provider 额度，初始确认采用串行或两臂同等并发。

### 3.3 预注册判定标准

以下为本轮设计的决策阈值，**不是现有实验结论，也不是通用统计规律**。运行前锁定；中途修改阈值必须另开探索批次。

- **完整性 I：** 已覆盖的版本、权限、重复环境动作、失效组件调用、状态伪报违规为 0。出现一次即停止该候选的扩展实验，保留材料修复。
- **覆盖 C：** 模块指定关键事件至少在 2 次独立真实运行中出现；关键负例至少覆盖 1 次。自主采用类事件至少在 2 次普通运行中出现，且若宣称泛化，至少有一次在 H1。否则记未覆盖/证据不足，不按成功率 100% 处理。
- **行为 B：** 针对该模块的已标注有效机会，目标行为达到至少 80%，较对照提高至少 20 个百分点；对照已超过 80% 则要求保持不退化并满足成本改善。按完整 run 聚类报告，不能把几十个同 run 事件当独立样本。机会样本过少、只有一个游戏或边界模糊时，保持探索性结论。
- **成本 G：** 成本型模块对应主要成本指标中位数至少下降 15%，且各游戏的关卡完成中位数不下降、总体 WIN 率不下降。成本比较尽量以到达同一关卡里程碑为准；只在相同墙钟未通关时计算更少 token，不能直接称效率改善。
- **任务 Q：** 质量型模块至少两个游戏的关卡完成中位数提升，其他游戏无下降；或基线已有较高完成率时，在不降低 WIN 率的条件下到达相同里程碑的父子总成本下降至少 15%。必须同时满足预算约束。
- **结论强度：** 三次/游戏/臂仅支持有界工程筛选。逐 run 结果、范围、效应估计与区间全部给出；若不确定性跨越退化方向，不作统计显著或一般净收益声明。增加确认样本需新的明确预算，不能默默续跑。
- **退化和放弃：** I 失败立即回退未来配置；目标 B/G/Q 未达标则“修订/撤下/保持实验”，不以工具次数增加补偿。无法完整计量成本时禁止宣称成本净收益。

### 3.4 统一交付材料

每个真实 run 保存：代码和依赖清单、官方环境身份、模型/provider/推理参数、启动时间、所有停止条件、父子请求与 usage、组件精确版本、装配与调用记录、工具拒绝、canonical 动作前后公开状态、官方 scorecard、后续父轮的实际可见输入（脱敏）、结果摘要。

密钥、认证头、scorecard 中的 api_key 不进入可分享报告。取消/超时请求以 unknown/已知下界表示，不能填零。输入、输出、reasoning、cache 分开；reasoning 若包含于 output 不重复累加。并发调用总计算时间与实际墙钟分别计量。

## 4. 第一类：Self-harness

### S1 机会识别到首次有效使用

**问题与目标。** lp85 反复手工追踪置换却没有计算组件；ls20 直到复盘才创建计数技能。目标是减少从发现重复负担到获得可用输出的手续，而非提高创建数量。

**窄命题。** 复用现有能力目录和单次作者调用，将候选、验证回执和调用入口一起返回，能降低首次获益的父模型轮次，并增加适当机会中的自主采用。

**设计。** 提供简短目录：可用能力、当前版本、适用目的、可调用入口；详细作者说明按需读取。创建成功自动完成机械注册与目录刷新，显式装配要求复用现有授权接口，不要求再写说明或查询确认。创建失败一次返回精确字段和可修复原因。机会由父/研究 Agent 识别，runtime 不从“重复三次动作”直接推断应写技能。剩余预算小、一次性简单计算允许不创建。

**首次路径与成本。** 识别机会 → 一次创建/试用请求 → 必要语义试用 → 后续实际使用。避免把候选、注册、列目录、确认注册拆为多轮；不新增常驻 worker，不要求逐动作填写机会表。

**实现入口。** `demo/arc_thin_extension.ts` 的工具注册/skill surface；`demo/arc_thin_boundary.ts`；`demo/prompts/arc_thin_system.md`；需要原生装配时复用 `demo/pi_task_harness_assembly.ts`。先做目录/回执单因素，不同时添加 critic。

**真实 ARC 验收。** D 中从实际当前网格构造一个计算能力，验证创建后首个合法调用能返回真实语义值，下一父轮可使用；O 中至少两次普通 run 出现自主创作并在后续两个合适机会实际调用，记录合理只用一次或放弃的例外。主要指标为首次正确结果的父轮数、墙钟、父子 token；满足 I/C/B，效率声明再满足 G。旧版和候选保持相同复盘提示，另行做“无显式创作引导”消融，避免把复盘指令当纯自主识别。

**负例与退出。** 无重复负担、现成工具已足够、候选试用失败、预算不足。若创建率升高但首次行动变慢/关卡退化，撤下多余提示和管理步骤。

### S2 可执行规则检查与组件语义验证

**问题与目标。** lp85 的错误不变量未经计算核验就固化；ls20 工具计算正确却不能证明通关目标。目标是明确每个组件能证明什么，并检验可执行模型与真实观测的一致性。

**设计。** 候选计算声明输入范围和输出含义；runtime 自动提供精确版本和公开 observation refs。用已发生动作检验计算模型，再对未来动作预先给出预测。描述性统计只验证其数值，不自动升级为目标规律。选择技能还是直接计算由 Agent 决定，简单一次性操作不强制组件化。预测与实际不符时保留反例，标记相应能力范围待复核；不因全局未通关就删除一个正确计数器。

**生命周期。** 父提出计算问题；作者产生候选；sandbox 检查可执行性；公开轨迹检查语义；父在真实后续行动中决定采用；runtime 记录版本与偏差。S2 只解决验证，不同时改目标提示或调推理强度。

**入口。** `demo/arc_thin_skill_guest.ts`、`demo/pi_task_python.ts`、`demo/arc_thin_extension.ts` 的 trial/replay/run_skill；新增验证事件复用既有 JSONL，不另建强制评审 Agent。

**真实 ARC 验收。** 对计数/定位类：在至少两个 run 的合计六个实际状态上与原始网格独立复算完全一致。对变换模型：至少两种已观察动作和三个未用于拟合的后续真实转移预测一致，或模型在第一次不一致后下调适用性并保留反例。不能用只拟合旧日志的成功冒充未来预测。O 中父必须表现为采用计算结果改变或简化后续判断，而非仅调用。满足 I/C/B；质量或成本收益另满足 Q/G。

**负例。** 混淆 grid[x][y]、改变 level 后输入形态变化、语法正确但计算错误、计算正确但目标解释错误、当前资料无法证明命题。遇到这些应得到有范围的失败/未知，而非“已验证全部规则”。

### S3 组件作用域、修订、停用与回退

**问题与目标。** lp85 overlay 中阶段任务与预算在后续持续驻留；组件已创建但缺少明确失效处理。目标是让有效配置可追踪、旧配置可停止生效，减少父手工维护。

**设计。** 为组件提供稳定 identity、revision、scope（task/level/显式条件）、active status 和内容摘要。runtime 自动填当前 level/run/version，用户不必每次输入。临时状态进入观察或 memory，不鼓励写入 prompt；含动态预算的内容由实时视图提供。level scope 在跨关时退出 active 集，可供重验证；task scope 不自动清除。改版先试用候选，成功后原子切换，失败保持旧有效版本。回退配置不回退环境历史；旧异步结果只能作为历史材料，不能覆盖新版本。

**入口。** `demo/arc_thin_extension.ts` 的 replay、prompt、skill surface；复用 `demo/pi_task_local_self_harness.ts`、`demo/pi_task_harness_assembly.ts` 的精确版本机制，避免重复注册表。事件记录是存储格式，不要求模型逐字段维护。

**真实 ARC 验收。** D 覆盖创建 v1→使用→候选 v2 失败→v1 仍有效→v2 修复后切换→停用后调用被明确拒绝/不再暴露。至少两次真实 level transition 核对下一 provider 输入：旧 level overlay 不再作为当前指令，task 能力保留。若无法自然进入新关，跨关验收标未覆盖，不能用假 level 通过。O 中确认过时组件不会继续影响新阶段；满足 I/C/B；维护成本满足 G 才宣称优化。

**负例与恢复。** 删除仍被引用组件、迟到 child 输出、没有有效旧版本可回退、错误 task scope。保留审计和替代入口，不产生无限修复循环。

### S4 五类组件、子代理与研究交付闭环

**问题与目标。** 当前 thin 采用集中于 memory/skill/overlay/预置 analyst。目标是按实际需要接通 tools/subagents，并把研究结论可靠送达父代理、组件创作和后续行动。

**设计。** 先检查现有 `arc_thin_subagents.ts` 与原生作者/路由能力是否可复用；按工具、子代理分别接入，不同时重写全栈。工具复用 sandbox 和参数校验；子代理具有最小权限、精确输入截止点、持续研究身份与有界运行预算。即时核心结论短交付，详细研究留在对应研究线。研究窗口不是必须创建的新 worker，也不要求永久模型进程。研究 child 不继承父的 ARC 动作权限，canonical 动作由父执行。可允许授权 child 产生候选，发布 active 组件仍遵守原生版本/装配路径。

**负担与成本。** 合并不必要 creator/read/status 往返；不要求所有五类每局都采用。父子调用纳入同一预算。未及时完成的研究结果在截止时取消/标过时，不能让父无限等待。

**入口。** `demo/arc_thin_subagents.ts`、`demo/pi_task_local_subagents.ts`、`demo/pi_auto_research_harness_router.ts`、`demo/pi_task_harness_route_runtime.ts`、`demo/pi_task_harness_assembly.ts`、`src/autoresearch_pi/arc_harness_smoke.py`。遵循 [Auto-Research ADR](2026-10-01-auto-research-mechanism-and-workers.md) 及 [实现记录](../auto-research-workers-implementation-2026-10-01.md)。

**真实 ARC 验收。** 在官方 ARC+真实 provider 上运行五类矩阵：system_prompt、skills、memory、tools、subagents。每类须检查实际后续 provider 输入或原生调用、语义结果和至少一个后续父动作；仅 status=completed 不通过。Auto-Research→child broker/process→结构化返回→router→原生 mutation→动作边界→后续父轮必须真实贯通。另验证普通 delegate 与 Auto-Research 的 provider length continuation；若真实服务未产生 length，标未覆盖，可用显式低输出上限的受控真实诊断，但不能归入普通采用。

**自主与收益条件。** O 中不强制五类都出现；针对真实机会至少两次发生研究/创作/采用闭环，记录父选择不采用的理由和后续结果。满足 I/C/B，扩展能力默认启用需满足 Q/G。只能证明 thin 一条路径时不得宣称完整五类闭环通过。

**负例。** 过时结果、子越权请求、候选未装配、完成无有效输出、length 后重复发布、任务结束时 child 未结束。完整性失败停止接入，不靠新增总控 worker 掩盖。

## 5. 第二类：基础知识与证据

### K1 假设版本、证据绑定与跨 level 重验证

**目标。** 保留可迁移猜想，同时阻止旧支持被直接继承为当前关的验证结论。

**设计。** hypothesis identity 与 revision 分离；证据引用具体 revision、公开观察、level 和测试条件。修改 claim 创建新 revision，旧 evidence 作为来源保留，但适用性为待复核；Agent 可明确认领仍适用的证据，runtime 不自己理解自然语言等价。跨 level 生成继承记录并设为当前关未验证。支持复合命题的局部结论时，分离可独立检验部分，避免一次 supports 覆盖整个目标结论。元数据自动填充，不强迫每轮重写全体假设。

**入口。** `demo/arc_thin_memory.ts`、memory schema、`renderMemory`、`src/autoresearch_pi/arc_thin_e2e.py` lifecycle audit。旧 JSONL 可读取为 legacy scope，不伪造缺失版本。

**真实验收。** D 包含同一关 claim 加条件、跨关继承、旧反证重引用三个情形；全部旧证据可追溯，没有自动“新关 supported”。O 中至少两次自然跨关记录新验证动作，再恢复支持；未跨关则不通过这项覆盖。复合目标中仅控制部分得到支持时，目标部分仍待验证。满足 I/C/B；记忆增量不得导致管理轮普遍增加，质量收益按 Q 或连续性成本按 G 判断。

**负例。** 真正可跨关的控制、无关旧反证、只改拼写、假设拆分合并。允许继承与轻量确认，避免全部清空造成重新学习。新版本机制导致反复验证已充分验证事实时应修订。

### K2 原始观察、解释和重要未解决事件

**目标。** 防止陈旧解释长期驻留，同时让重要未解释变化不因退出近期窗口而丢失。

**设计。** 原始观察由 bridge 确认，带 state/action refs；解释是可修订条目，事实的 confidence 不能代替来源。瞬时位置从当前状态推导，不重复写永久 memory。未解决事件由 Agent 标记用途和竞争解释，runtime 保存短摘要与精确恢复入口；不把每个像素变化永久保留在工作集。解释解决或不再相关时退场，历史可恢复。

**入口。** `demo/arc_thin_feedback.ts`、`demo/arc_thin_memory.ts`、extension 的 recentText/buildWorkingSet。先使用已有公共 delta，不在该模块同时换观察编码。

**真实验收。** 在至少两个 O run 中发现非平凡变化，超过原 recent window 后仍可定位来源，并在后续实际决策中正确使用；真实遮挡/移开或位置变化后旧状态不再冒充当前状态。以原始帧逐项核对解释引用；不要求复现 ls20 固定第13步。满足 I/C/B；完整网格信息保持，输入占用和检索轮次报告。若只证明“存得下/读得到”而没有后续正确利用，标 A 未验证。

**负例。** 常规动画、无信息重复、被否定解释、已无关关卡。事件目录无限增长或父反复读档而不行动时，缩减驻留并重测。

## 6. 第三类：执行、预算与接口

### E1 反证、依赖失效与持续计划暂停

**目标。** 已记录针对当前前提的 refutes 后，停止依靠该前提继续原计划；争议处理期间允许独立检查。

**设计。** 显式计划记录稳定 identity/revision 和前提版本。refutes 先使相关依赖失效，contested/rejected 均取消继续执行原承诺的资格；同事务改名、改 depends_on、设 active 不自动抹掉失效来源。恢复需引用处理记录：新证据、适用范围修订或明确更换为验证实验。机械检查版本和未处理失效记录，语义充分性由授权 Agent 判断并接受实际行为审计。新语义门禁先仅作用于已明确承诺的计划延续，不遍历自然语言推断所有动作归属。

**动作边界。** 不给每个动作强加 strategy_id。已有计划的 continuation 可复用上下文；自由探索可以无计划。若无法可靠判定新动作是否在换名延续旧目的，标为语义未解决，不声称硬性防止。避免反复拒绝消耗预算：一次返回失效事实、自由探索/复核入口；同一不可修复请求不进入无限重试。

**入口。** `demo/arc_thin_memory.ts`、extension 的 memory transaction/arc_action boundary、lifecycle stats。与 K1 最小 revision 结构衔接。

**真实验收。** D 覆盖 contested、rejected、同调用重激活、移除依赖、换名、合理条件化重试。已声明计划继续请求违规为0；暂停后仍能在下一轮执行合法无策略探索/复核。O 中至少两次真实反证后审查后续五个动作：旧投入停止，或有新依据与有限验证；仅策略名称变化不通过。满足 I/C/B；若新门禁阻止无关合法探索则失败。语义规避仍出现时报告未解决，不用状态测试代替行为验收。

### E2 无策略探索与有界实验

**目标。** 降低探索手续，同时避免未证实猜想无限获得动作预算。

**设计。** 探索动作无需计划；持续测试可简短表达待区分命题、预测、终止条件与投入范围。runtime 从已有记录计算已花动作/时间，不要求每步重写计数。到达实验条件时返回一次结果事件；Agent 决定结束或基于新信息修订。可检验新条件不意味着应自动继续原有几十步承诺。无需每次多选 mode 表单，优先复用计划与 note 中已经明确的信息；无法确定语义时保持未分类。

**入口。** memory strategy/test 表达、runner decision boundary；台账尚未启用时仍可运行。

**真实验收。** D 中无策略首步可以直接执行；有界测试到达终止条件后不会自动延长；合理重复取样可以说明新的投入并继续。O 中审查低信息长序列的持续时间、不同预测被区分的次数和后续行为，禁止用“动作不重复”替代信息价值。满足 I/C/B，任务结果需 Q 或成本 G；独立标注者无法判断信息价值时记未知。

**负例。** 必需长路径、多个合法连续同向动作、随机噪声需要重复验证。不能设置通用“同动作 N 次就阻止”。

### E3 预算感知与上下文连续性

**目标。** 在固定时间和父子计算预算下提高有效进展，避免管理和长推理挤占行动。

**设计分成两个独立实验。** E3a 先只增加简短实时有效预算：全局动作与本关动作取实际约束、剩余墙钟、已报告/未结算 token、子调用预留。E3b 再单独调整推理/输出分配与当前轮历史投影；保留原始内容按 ref 恢复，重要证据不随压缩消失。不得把减少输入视为减少 reasoning 的证明。取消先保障动作 exactly-once 与结算，不在未知动作已提交时直接重试。

**入口。** `src/autoresearch_pi/arc_thin_e2e.py`、`src/autoresearch_pi/pi_kernel.py`、extension context/appendUsage；复用已有预算配置，不先引入第二套调度器。

**真实验收。** E3a 每次送达模型的预算与权威记录在声明时间戳一致；不能再把每关余量当总余量。E3b 同一模型和官方任务的 A/B 中，主要成本至少下降15%，同关卡里程碑准确性和完成率不下降；后续实际决策保留反证、未结束实验和必要计算结果。真实超时/取消/length 至少各一受控 D 覆盖。满足 I/C/G；仅单步更快但关卡变差不能通过。

**负例。** 必需长计算、接近 token cap 但存在未结算请求、child 并发、取消时 bridge 仍执行。未知账单不应虚构精确剩余额度。

### E4 Memory 与组件更新的低负担恢复

**目标。** 减少格式和容量导致的模型修复轮次，同时保留原子事务。

**设计。** 复用 boundary repair，只修正无歧义机械格式；语义缺失不自动补造反证。预检给出可操作错误定位和是否任何写入生效；提供增量 patch、同事务合并/退休及预期版本。重试使用幂等身份，不能重复证据或环境动作。容量接近上限时提供紧凑机械事实，避免每轮提醒和强制清理。

**入口。** `demo/arc_thin_boundary.ts`、`demo/arc_thin_memory.ts`、对应测试和 tool receipts。

**真实验收。** 先将历史五次失败离线诊断，再在真实 ARC/真实模型 D 中覆盖 null 可选字段、嵌套错误、假设满额、证据缺失、版本冲突。可修复格式一次恢复，不能修复的请求明确且零部分写入；O 中成功更新所需修复轮数和延迟下降，语义错误没有被静默接受。满足 I/C/G。没有自然错误样本时只可宣称诊断覆盖，不能计算普通失败率改善。

## 7. 第四类：台账与 critic

### L1 统一事实台账与生命周期反馈

**目标。** 自动记录组件实际投入和使用，不把声明、调用计数当成功，也不让父重复维护台账。

**设计。** 复用现有事件汇总：机会（可未知）、候选版本、装配、调用输入状态、结果、成本、后续行为、撤下。`uses` 是声明，实际调用是 execution，结果出现在输入是 exposure，改变判断是 semantic use，四者分别记录。预测须在动作前出现才算 prospective；事后解释不得回填为预先预测。只统计可证事实；语义效果由审阅或授权 Agent 判断。默认不新增模型调用，工作集只显示当前有用差异。

**入口。** `demo/arc_thin_ledger.ts`、extension ledger hooks、runner `_ledger_stats`；与现有记录共用事件ID，不建第二个真值源。

**真实验收。** OFF/ON 单因素对照，保持 critic OFF。两次官方真实 run 的组件调用、版本、canonical动作、已知token与原始事件逐项对账；错配、丢失、重复为0。动态测量不能被记成目标达成，事后填写不能冒充预测。O 中父利用台账减少重复查询或改进投入判断，满足 C/B/G；若仅审计价值成立，标“可观测性通过、任务收益未验证”，不得强制常驻展示。

**负例。** 组件被声明但没调用、结果未被消费、同名不同版本、并发子调用、没有预测的探索、行为关联无法归因。

### C1 有范围、可核验、受预算约束的 critic

**目标。** 在高价值节点发现父可能漏掉的矛盾，并证明额外调用值得。

**设计。** 在明确异常、未处理反证或高投入低进展时按配置触发，不每步调用。critic 读取公开原始事实、精确证据和不确定性；不能只读父的结论并把它当事实。报告区分发现、解释、候选测试、未知；计算断言优先请求/使用可执行检查。critic 不自动升级猜想为事实，不直接控制环境；父可以有依据地拒绝。runtime 去重、校验引用、标记过时，停止调度由预算和生命周期控制。无需新增“总 critic”管理已有 critic。

**入口。** `demo/arc_thin_critic.ts`、extension prepareLedger/critic、usage。先复用已存在接口；固定 ledger ON，只比较 critic OFF/ON，避免两个因素混在一起。

**真实验收。** D 中覆盖正确异议、错误建议、无足够证据、过时结果、预算不足；所有引用能定位真实公开事件，错误建议不能自动写成已验证认识。O 中至少两个独立 run 发生有效检查，并审查后续五动作是否进行有价值验证/合理拒绝；不能用 suggestion_taken 或 idea_changed 单项判成功。满足 I/C/B，并且含 critic 的父子总成本/关卡结果满足 Q/G，才允许默认启用。

**负例与放弃。** 同模型产生相关错误、纯复述父观点、反复对同一事件提醒、回复晚于相关阶段。增加调用而没有可见收益时关闭，而不是靠降低验收标准保留。

## 8. 第五类：可观测性与验收

### V1 可信状态、取消请求和完整成本

**目标。** 让所有优化结论建立在一致统计口径上。

**设计。** 分离 run_completed、game_won、stop_reason、tool_failures、environment_failures、coverage、usage_known/unknown。父、analyst、critic、研究 child、普通 delegate 都使用请求关联；start、headers/first-token（若可测）、message_end、cancel/timeout 分开。summary 的 passed 不再被展示成游戏通过。原始字段保留兼容说明，不能重写历史账单。预算余量以已知下界加未结算状态表示。

**入口。** runner persist/summary、`pi_kernel.py`、extension appendUsage、研究 broker 现有计量。只补缺失事件，避免保存每 token 完整消息造成日志膨胀。

**真实验收。** 至少覆盖正常结束、deadline、工具拒绝、child失败/取消、length；每个结束的请求与usage对应，未结束明确未知。官方 scorecard、bridge 动作数、trajectory 一致。历史 lp85 的八分钟尾段只能标未知，不用估算伪造。已知 token 求和、cache/reasoning口径和并发墙钟计算可独立复算。满足 I/C；此模块验收目标为计量完整性，不以通关提升为必需，也不能因此宣称游戏收益。

### V2 分层真实验收、泛化与发布

**目标。** 让“代码正确”“链路接通”“自主采用”“净收益”各有明确证据，防止多因素堆叠。

**设计。** 每模块预注册一个主变量、比较器和负例。D 与 O 分开；模块 B 相对于最近通过的稳定基线，并保留原始冻结版作阶段汇总参照。新增 held-out 游戏前锁定提示，不看答案调优后仍称 held-out。运行失败全部进入统计，provider故障可以另分层报告但不能只删除候选臂失败。

**真实验收。** 按第3节协议提交逐 run 结果；每模块满足自己的 I/C/B/G/Q 组合，缺项明确标记。阶段组合版在三游戏独立对照中再次验收，不能把各模块单独通过推导成组合通过。至少检查五类完整链路以及两种 length continuation；普通模型未自主采用时不得宣布 self-harness 转化完成。

**完成判定。** 每项给出保留/修订/撤下/实验状态，附最大剩余风险与下一可证伪检查。禁止用增加测试次数、作者调用次数、组件数量代替任务结果。没有证据优势时允许结束方案分支。

## 9. 实施批次与依赖

| 批次 | 内容 | 单因素要求 | 进入下一批条件 |
|---|---|---|---|
| 0 | V1 最小采集、V2 预注册、冻结基线 | 不改游戏提示与决策 | 能核对实际运行和父子成本，未知有明确标记 |
| 1 | S1 | 只缩短形成/采用路径 | R/A可判，G或Q结果明确 |
| 2 | S2，再 S3 | 验证与生命周期分开 | 有真实试用、负例、跨阶段覆盖 |
| 3 | S4 工具，再子代理 | 两类分别接入，ledger/critic OFF | 五类真实链路与长度恢复，无越权 |
| 4 | K1，再K2 | 版本/证据与工作集保留分开 | 真实跨关、修订、连续性有证据 |
| 5 | E1，再E2 | 依赖保护与实验表达分开 | 原计划暂停、合法探索未被阻断 |
| 6 | E3a、E3b、E4 | 预算展示、推理/上下文、更新修复分别比较 | 成本降低且任务无退化 |
| 7 | L1，再C1 | 台账开关与critic开关分开 | 审计正确，额外负担有收益依据 |
| 8 | 组合回归与V2结论 | 稳定组合对原始/阶段基线 | 提交四层结果，不剩未披露验收缺口 |

每个模块实施步骤：①保存真实失败与可证伪断言；②补最小诊断检查；③实现一个主变量与明确退出路径；④定向检查实际生效入口；⑤冻结候选与基线；⑥真实 D；⑦有覆盖后执行预注册 O；⑧汇总收益、负例和代价，决定保留/修订/撤下。不得因 D 未覆盖而无限增加运行。

## 10. 真实运行命令与配置注意事项

以下为当前 CLI 已存在参数的示例，**本轮未执行**。必须在目标冻结版本的目录运行，并验证 run-config 中 extension/source hash 指向该版本。不能只更改输出目录就声称换了基线。

```powershell
# 在已冻结、可复核的基线或候选 checkout 中运行；RUN-ID 必须唯一。
D:\conda\python.exe -m autoresearch_pi.cli arc-thin-e2e `
  --root D:\autoresearch_pi_project\runs\RUN-ID `
  --arc-root D:\arc-agi-benchmark\arc-agi-3-benchmarking `
  --game ls20 --variant treatment `
  --provider yibu --model qwen3.8-27b `
  --input-modalities text --max-output-tokens 65536 `
  --max-actions 100 --max-reported-tokens 1200000 `
  --experiment-timeout 3600 --consolidate-after 25
```

provider-default thinking 通过不传 `--thinking` 保持，实际响应配置仍需记录。lp85 与 H1 替换 game；H1 在运行前选择。各优化模块没有现成开关时用独立冻结版本比较，不能编造 CLI 参数。

- L1 比较：同一候选版、不带开关 vs `--ledger`，critic 始终关闭。
- C1 比较：`--ledger` vs `--ledger --critic`，其余相同。
- thin control 只暴露 arc_action，和 treatment 有多个差异，不能作为所有模块的单因素比较器。

完整链路诊断使用已存在入口：

```powershell
D:\conda\python.exe -m autoresearch_pi.cli arc-harness-smoke `
  --root D:\autoresearch_pi_project\runs\RUN-ID-CLOSURE `
  --arc-root D:\arc-agi-benchmark\arc-agi-3-benchmarking `
  --game ls20 --provider-mode real `
  --max-actions 20 --max-reported-tokens 200000 `
  --experiment-timeout 600
```

禁止带 `--mock-environment` 作为真实 ARC 验收。此入口的模型/案例矩阵设置必须查验实际 run-config；`--case` 的可用名称在实施时枚举，不在本文虚构。若当前入口不能覆盖新增 thin 能力，需先适配共享生产路径再诊断，不得用另一套脚本工具替代被验收实现。

`arc-thin-smoke` 使用 mock SDK/scripted provider，只作诊断。完整原生链路 smoke 仍不能代替普通真实模型运行中的自主采用和净收益。
