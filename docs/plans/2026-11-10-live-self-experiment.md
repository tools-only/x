# 同一 Pi 会话内的自身反射与进化实验

**日期** 2026-11-10（Asia/Shanghai）

**范围** 隔离分支上的实验。设计依据为[自进化 Agent 设计宪法](https://chatgpt.com/library?file_id=libfile_9a04346b1da481919bc65b1d46a3b3d2&account_id=personal)。

## 问题与命题

现有反射路径以组件文件为身份。Process 引用特定工具版本，而工具更新会先刷新 Binder 的当前绑定，Process 之后只在当前绑定里查找旧引用。源码仍在归档里，执行依赖却可能断开。自身视图、修改目标和执行解析需要来自同一个运行对象。

本次命题是，一个普通任务中的产物或进展可以进入自身审阅窗口。同一 Pi 会话能看见它的完整已建模结构，通过属性上授予的操作修改真实任务能力及自身审阅方法。后续任务和审阅都实际使用修改后的行为。每次修改只需一个反射操作，运行时负责校验和生效，不需要 Agent 编辑组件文件、发布或再装配。

## 设计与职责

| 宪法要求 | 实验中的实现与可反驳结果 |
| --- | --- |
| 完整 Agent 与自动 Mirror | 一个根对象属于一个 Pi 会话。持有任务行为、进化方法与可见的受保护运行部分。已建模属性全部进入审阅视图，指向实际定义和执行关系。宿主负责投影和注入。若只能看到可写条目，或在实际模型请求中缺少视图，则失败。 |
| Workspace 作为能力作用域 | Workspace 是会话内受控执行和对象访问的边界。用户授予具体属性操作，Mirror 从同一操作契约生成可用操作和引用。可读可写分离。视图内没有独立可写表、文件路径或另一个绑定对象。跨作用域、越权、撤权和旧修订调用不能改变执行。 |
| 单次反射与执行一致性 | `reflect` 接收对象或操作引用及类型化的新行为。运行时按当前会话、授权、修订和契约校验，在安全边界替换生效行为。执行、Mirror 和回执读取同一修订。已经开始的工作继续按其捕获版本归因。 |
| 任务进入自身审阅 | 任务工具产生可评估证据时，运行时在已有模型轮次中提供审阅机会、证据与自身视图，并区分已审阅与漏审。Agent 可选择修改、保持或暂缓。预算用尽允许正常结束，记录未审阅。宿主不替 Agent 做优化价值判断。 |
| 修改进化方法本身 | `evolution.loop` 的可替换值必须被解释执行，决定如何取证、比较或筛选能力缺口。新版方法在下一窗口实际产生不同的审阅输入或比较结果。仅改提示文字、触发时机或计数不能通过这一项。 |
| 通用性 | Pi 扩展、Mirror、授权、反射和审阅生命周期复用。任务适配器仅提供原始输入、任务工具和证据。用两个语义不同的任务域诊断复用。 |

**实现选择。** 使用仓库锁定的 Pi Coding Agent 0.87.0。TypeScript 扩展持有每会话的反射对象和授权。首轮行为以可校验的数据或受限执行器表达，避免向生成行为暴露宿主进程或任意文件权限。对于已有 Pi 扩展，实验以单独可加载扩展验证机制。历史 ARC 和 PPT 路径保留作为现状比较，后续迁移要逐一替换其执行入口及版本解析，不能另做一份视图放在旧 Binder 旁边。

### 实际接口

- [会话对象](../../demo/live_self_core.ts)以 Pi session ID 限定 `self` 与 Workspace。当前修订持有 `task_harness` 和 `evolution_loop` 的真实源码及其输入输出契约，并包含只读的 `kernel`。Mirror 由这份对象生成。操作引用附在各属性的 `operations` 上，Workspace 只提供作用域身份。
- [Pi 扩展](../../demo/live_self_extension.ts)用 `context_with_system` 把 Mirror 放入模型实际请求。同一回复产生的任务调用持有该请求的修订。宿主启动时可经 `LIVE_SELF_GRANTS` 授予一个或两个属性的 `replace`，`[]` 产生只读视图。该配置不发送给模型。一次 `reflect({ref, replace:true, value:{type:"text", value:source}})` 执行合法替换。旧引用随修订切换失效。
- [WASI 方法执行器](../../demo/live_self_wasi.ts)复用已有 CPython/WASI。`task_harness(task, source_text)` 输出文本。`evolution_loop(task, source_text, draft, mirror)` 输出 JSON 审阅证据，输入包含同一修订的只读自身结构。Agent 可以编写新的取证算法。预提交校验授权、修订和 Python 源码语法，执行时校验实际输出。审阅方法出错时，仍可使用任务输出并记录失败的审阅状态。
- `draft_item` 自动产生任务结果及审阅证据 ID。`submit_item(evidence_id, self_review, content?)` 交付指定草稿。`self_review` 记录对自身方法的决定，`content` 可覆盖任务产物。提交回执记录产物是否直接来自草稿。中途有独立审阅需要时可用 `review_self`。任务结束时缺失的决定仍记为未审阅。

**成本与错误。** 复用现有模型请求，增量提供短视图与审阅证据。收集窗口、实际模型输入、审阅决定、反射结果和行为版本。陈旧编辑明确失败。异常和预算退出独立计入；运行时不能把未生效回执算作成功。对已发生的任务操作只向前修订。

## 运行前实验协议

1. **功能与接线诊断。** 用 Pi 0.87.0 和明确标记的本地脚本模型驱动普通任务入口。至少观察两个审阅窗口。先用初始任务行为产生证据，再通过同一个反射入口修改任务行为与进化方法。继续执行并提交任务产物。记录实际模型输入、任务回执、修订和审阅方法的输出。增加一个保持现状样例以及权限和版本负例。脚本只选择工具调用，任务、反射和审阅执行由 Pi 路径完成。
2. **模型探索。** 若可接通，另启不带实现上下文的 GPT‑6 Luna high，通过本地实验传输读取同一 Pi 扩展生成的模型请求、返回模型决策。任务只描述业务产物及质量约束，模型可使用正常的自身审阅协议。每次任务最多 18 次模型响应，单次等待至多 240 秒，调用用完或任务提交即结束。该传输属于工具中继，不是原生模型 API，暴露的附加说明和历史要在记录里注明。没有付费端点调用。
3. **主要判据。** 确认同一会话身份、完整已建模自身结构、自动审阅、真实任务行为与进化方法双重修改、随后真实语义使用、继续任务并有产物。模型实验不要求必须修改，合理保持和未识别机会分开记录。已有任务目标仍应独立检查，禁止按修改次数计成功。
4. **收益比较。** 只有在匹配任务初态、同模型、相近预算的基线和实验运行都完成时，才比较产物质量与总开销。单次小样只报告观察。记录请求数、模型输入的可用尺寸指标、延迟、修改和审阅开销；没有 provider 计费数据时明确记为未测。

模型小样采用同一份英文研究幻灯片文案任务，要求标题、两条比较和一条限制说明。独立运行的两组分别开放两个写操作和完全只读，使用相同初始方法、材料、工具和传输预算。产物核对固定 20 步预算、8/30 对 13/30、3/10 对 4/10、同模型条件和样本量限制。任务请求不要求自我修改。只读组仍会收到自身视图和审阅证据，以便观察 Agent 能否通过手动调整产物弥补自身缺口。

## 实现与验证

### 第一轮模型探索与修订

初版在每次任务草稿完成后自动提供自身视图和审阅证据。模型可调用独立的 `review_self`。开放修改和只读两组的 Luna high 都完成了同一页文案的任务，但都手动补齐文案，无修改、无显式自身审阅。两组均停在修订 1。开放组 4 次模型响应，输入中继记录 58,465 字节；只读组 3 次，40,628 字节。开放组有一次提交的任务标识与草稿不一致，响应次数差异不能归因于权限。提交内容均保留所要求的数字和限制。

断点发生在审阅证据已经进入实际模型请求之后。第二轮把 `keep`、`defer` 或 `change` 及理由合进 `submit_item`，由系统把它关联到刚提交的草稿证据。模型仍可在任务中途通过同一视图做反射，也可随时记录中途审阅。没有走到提交边界的证据保留为未审阅。此修订专门验证能否把审阅决定纳入普通任务路径。提交字段是系统要求，不能计作自主采用；模型是否主动用它改变自身另看反射和后续实际行为。

第二轮重跑同一份单页任务的两组，另加一轮三卡片任务探索重复工作是否给模型更多理由投资可复用能力。三卡片任务要求分别使用现有草稿与提交工具，任务请求依然没有指定自我修改。额外小样用于定位机会，不能与第一轮合并做因果比较。

第二轮两组都提交了审阅决定和合格文案。单页两组均有一次因重述任务名称导致的提交失败。开放组和三卡片组将手工修改产物填为 `change`，实际反射提交为零。因此最终版本以已有证据 ID 绑定交付，并把 `self_review` 和产物 `content` 分开。再用同一三卡片任务验证普通运行，另做一个明确要求双重修改的 Luna high 诊断，比较同一份素材的 r1 与 r3 结果。后者只能作为模型执行接线证据。

### 复现

安装仓库锁定的 npm 依赖和 Python 的 `wasmtime==49.0.0`、`pytest`，让 Python 环境在 `PATH` 中。以下命令从仓库根目录运行：

```bash
node --experimental-transform-types --test tests/live_self_core.test.ts
PYTHONPATH=src python -m pytest -q tests/test_live_self_pi.py
```

独立模型实验使用 [Luna 本地中继](../../tools/live_self_luna_relay.ts)。中继从真实 Pi 请求读取模型输入，将 Luna high 的回复送回 Pi 执行。实验中的编号 JSON 是传输与取证材料，反射对象及实现从不经此路径读取或装配。中继不提供可用的模型计费或 token 数据。

### 结果

GPT‑6 Luna high 参与实现和测试。另启七次独立 Luna high 运行，每次只读取 Pi 的实际请求并提交模型响应。下表响应数包含所有工具往返。记录的字节数是中继序列化后的请求总量，可用于排查上下文开销，不能当作模型 token。

| 版本与样本 | 模型响应数 | 自身反射提交 | 自身审阅与任务结果 |
| --- | ---: | ---: | --- |
| 初版单页，开放／只读 | 4／3 | 0／0 | 两次均未审阅，均手工补齐文案。 |
| 审阅合入提交的单页，开放／只读 | 4／4 | 0／0 | 有决定，均有一次任务名称匹配重试。开放组用 `change` 指代改文案。 |
| 审阅合入提交的三卡片，开放 | 7 | 0 | 三张均完成，三次 `change` 都是手工修产物。 |
| 最终按证据 ID 提交的三卡片，开放 | 7 | 0 | 三次提交无标识重试，均保留数值。三次 `keep`，三份提交都覆盖了原草稿。理由却声称原方法保留了测量值，和实际草稿冲突。 |
| 最终版双修改诊断，开放 | 6 | 2 | 同一 Pi 会话从 r1 切至 r2 的任务方法、r3 的审阅方法。r3 输出直接交付，无文案覆盖。 |

双修改诊断的实际 Mirror 修订为 `1,1,2,3,3,3`。r1 仅输出第一项比较。Luna 编写两段新的 WASI Python 程序，r3 使用同一输入生成标题、两项比较和限制说明，按顺序保留全部九个数字及同模型条件。新版审阅报告检查数字缺失。把该方法另行回放到 r1 草稿，它报告漏掉 `3, 10, 4, 10`，对实际 r3 草稿报告无缺失。这是方法对同一材料的区分能力验证，不能证明它能检查数字语义或衡量整份 PPT 的质量。诊断的原草稿窗口没有独立审阅决定，最终窗口记录 `change`。其运行使用明确的双修改指令，所以只用于验证模型能够完成该链路。

原始材料为[双修改 trace](../../runs/live-self-luna-dual-probe-20261110/trace.jsonl)、[回放反例](../../runs/live-self-luna-dual-probe-20261110/review-counterexample.json)、[最终普通三卡片 trace](../../runs/live-self-luna-id-batch-20261110/trace.jsonl)。两项最终运行的输入分别为 112,773 和 138,763 字节，中继等待累计分别约 127 和 98 秒。等待时间包含实验传输和模型操作，并非服务时延估计。

| 功能正确 | 通过本次检查 | 授权、撤权、过时引用、无效源码、旧修订归因、审阅异常不阻塞交付 |

## 交付边界

保留为可复现实验。它接通了真实 Pi 生命周期中的自身视图、能力授权、直接反射与两类可执行方法，并在交付中区分审阅决定与产物变化。实验只建模了一个通用草稿方法、一个审阅方法和受保护内核，尚未覆盖原有 ARC/PPT 运行中的全部自身结构。审阅边界现由草稿与提交工具提供，整个进化流程的阶段调度及跨会话恢复仍需另验。

普通任务的证据指出，下一个可证伪因素是 Agent 能否区分「自身草稿已满足要求」和「模型手工补齐后满足要求」。可以在可比的重复工作中提供版本关联的原始产物与覆盖记录，观察模型是否基于真实重复负担选择修改。把该试验和生产路径迁移分开，便于归因。相关后续是[环境适配边界和上下文连续性](../deferred-research-todos.md)，本实验不更改其验收状态。
