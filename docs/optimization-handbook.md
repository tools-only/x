# Agent 系统优化经验手册

日期：2026-10-06。适用：Auto-Research、self-harness、上下文、工具接口、推理分配与真实模型实验。

目标是用可承受的总成本推进任务。优化应减少重复劳动，保留下一次决策的依据，并让 Agent 更早获得有效反馈。

本文是[48 小时回顾](reports/2026-10-06-48h-optimization-review.md)的经验归纳，供开发者按需查阅。[开发流程](development-workflow.md)仍是权威标准；变更复用[既有记录模板](templates/meta-harness-change.md)，不另建运行时表单。文中的设计建议需要独立实施和验收，本手册本身不改变 runtime，不加入游戏 Agent 上下文。

## 1. 一次优化怎样推进

| 步骤 | 做什么 | 结束条件 |
| --- | --- | --- |
| 找断点 | 查看失败轮的实际请求、回执、后续输入、usage与时间；定位最早未完成的转移 | 能指明哪条证据支持观察，哪些解释尚待检验 |
| 保基线 | 冻结已成功参考、当前候选及实际配置，核对恢复后生效源码 | 同一模型／环境下有可追溯比较器；没有成功参考时采用当前最小可运行版 |
| 定命题 | 写一个主要变量、预期变化、反驳条件和总预算 | 不看结果也能判断本次该保留、修订还是撤下 |
| 低成本验证 | 先用已有轨迹和相关负例验证机制，再补与声明相称的真实链路／provider证据 | 已实现路径确实生效，付费样本能区分命题的两种结果 |
| 判收益 | 同时看任务质量、父子成本、延迟、管理轮和认知连续性 | 达到预定标准；失败、合理不使用和未知项也进入记录 |
| 作决定 | 保留正确性修复；将收益不足的候选修订、撤下或保留隔离实验状态 | 明确当前候选、成功参考和下一项尚未验证的命题 |

变更记录只维护一份。诊断发现、代码实现、运行结果和决定在同一处增量更新；每次实际付费请求都计入该问题的累计实验投入。

### 为什么先保基线

stage90曾17动作、78,066 reported tokens通过首关；随后stage91–112的18次真实运行消耗5,374,347 tokens，全部零关。后续候选没有建立足够的增量收益证据。教训是：**新版本的解释更丰富，不等于它比成功参考更有效。**

基线需要源码manifest、依赖／Pi版本、provider/API、推理和输出设置、实际工具surface、初态及运行产物。恢复源文件之后，再核对最终发送的请求。目录名、配置意图和模型实际收到的参数可能不同。

单次成功是优先验证的线索，先做预算内重复检验。provider超时、缺usage或环境不一致先按各自故障处理；它们不足以支持改玩法prompt。无法复现时如实记录不确定性，保留成功版本；不要继续把多个新机制叠到同一候选上。

### 连续优化怎样判断

连续提交版本、逐项修改和持续净改善分别判断。每个候选在同一变更记录中对照上一个已接受版本和成功参考，交代保留了哪些收益、增加了哪些成本、净效果得到哪层证据支持。新功能与正确性修复可以有成本，但新增常驻负担需要披露；仍低于预算上限不能替代收益证明。

上下文比较采用同初态／阶段、同序列化与计量口径，分别列初始常驻内容、运行中工作集和全部实际调用成本。新证据可以扩大工作集；检查的是有用依据是否保留、重复内容是否消退以及任务成本是否改善，不要求每轮机械变短。已得结论跨版本仍可用、已省成本不被未解释的新增内容抵消，才支持优化的连续性。

版本晋升时，在原记录中说明三件事：继承了哪些已验证收益；本次在相同口径下增加／减少了什么；质量和总成本是否达到事前标准。功能正确性修复单独登记，性能未验证时保留候选身份。上下文增加需要具体用途及成本说明；仍在CH上限内不足以证明这种增加值得。初始长度、运行中历史增长、新生成reasoning、总付费消耗分别比较，避免用一个下降数字替代其他项。

本次反例：stage130→132的初始whole context从29,627增至29,767字符，133保持不变；新增typed trial契约增加了常驻成本，真实任务净收益仍未证明。过去的局部缩短不能据此称为连续下降。上述对照方法是后续开发指导，尚未实现自动化版本晋升检查。

stage134与132／133的工具schema完全相同；只对齐实际cwd和7条message timestamp后，整个初始context相等。实际本地o200k估算7,012对参考7,004，不能报告为token下降。这次改动是减少重复绑定契约的功能候选，不能计为上下文优化收益；见[同口径审计](../tmp/arc-stage134-initial-audit.json)。

stage135初始内容与耐久132参考对齐后仍相等；135a仅限定完整性检查的API范围，没有改变prompt/schema。135a真实短窗26,928reported、零组件：模型在名字错误后的一次修复又产生非法JSON，执行被正确拒绝。正确拒绝保护了完整性，却未解决作者负担或任务推进；该问题累计97,351known，继续保留候选身份。见[真实审计](../tmp/arc-stage135a-real-evaluation.json)。失败后不追加付费请求，从已有调用定位下一断点。

stage136进一步移除安全Tool snake_case的纯命名拒绝，原合法调用无需改AST即可在native脚本中发布、试用并交付正确值。真实新窗却先遇到非法JSON，没有到达名称校验；新增27,402reported、零组件，累计124,753known。这支持保留命名正确性修复，不能支持真实创作或任务收益。见[136审计](../tmp/arc-stage136-real-evaluation.json)。纯格式约束应有身份或权限理由，避免迫使模型整树重写；改变格式后仍要逐一核对精确名称、引用和注册碰撞。

stage138继承137去重，缩短整条纯Tool作者接口：相同计算的完整call为1657→566字符，creator完整回执为5692→3844字符；分别是作者输出负担和按需读取负担，不能相加充当初始上下文或实际账单下降。Python表达式只解析为既有IR，运行/重启执行冻结IR；省略schema使用较弱默认JSON契约，显式强schema仍校验，需披露这一取舍。见[整条接口审计](../tmp/arc-stage138-authoring-burden-audit.json)及[同一变更记录](plans/2026-10-02-context-tool-reasoning-design.md#138a-实现表示成本及证据边界2026-10-06)。138a离线阶段paid0；后续真实负结果另列如下，不能沿用该阶段的零成本描述。

stage138真实Qwen/off引导诊断只完成1动作/0关，3完整响应41,740known tokens，另有第四在途请求成本未知。去图像请求内容28,385→58,807字符（2.071763倍）；同一5,236字符SDK错误在工具回执和pending状态重复，约97.52%是参数全文回显。初始text+schema低于CH、reported reasoning为0，仍然发生严重运行增长。见[成本审计](../tmp/arc-stage138-live-tool-cost-audit.json)。这直接说明：初始合格、作者表达变短、关闭thinking都不能替代后轮去重与完整接口验收。

stage139对齐已存在的空parameters/bindings默认值，原生同例错误5,236→407字符，schema每请求−37字符，creator读取1→1，原源码保留；21唯一针对性检查通过、paid0。见[表示审计](../tmp/arc-stage139-defaults-representation-audit.json)与[结果记录](plans/2026-10-02-context-tool-reasoning-design.md#139a-实现实际请求表示与冻结决定2026-10-06)。它修复最早校验障碍，不补缺失网格、不改算法，原失败程序仍被拒绝；全ARC接线、普通采用和净收益未验证。下一付费实验之前，应从已有失败一次性检查数据、source、预算、装配和语义使用整条路径，避免逐字段付费发现障碍。

stage140按需准备准确numeric final-grid绑定，较早捕获帧明确action/level/gap，避免手抄和误取动画首帧；索引类型匹配公开schema。初始常驻增量0，creator回执增加151/327字符，读数仍1、resource读数0；这项成本换取准确输入，是否值得仍需真实行为检验。完整坐标差分压力输出45767字符，逐行计数查询仅523；它是选择合适的查询粒度，不能称无损压缩或删掉canonical观测。21唯一功能诊断通过；官方矩阵16通过/1在SDK初始空帧退出，单独复测该情境22/22通过，全部425门槛跨两次runner覆盖，原失败保持。见[成本审计](../tmp/arc-stage140-grid-handoff-cost-audit.json)、[接线覆盖](../tmp/arc-stage140-coverage-audit.json)与[统一记录140](plans/2026-10-02-context-tool-reasoning-design.md#140a-实施与中断后核验2026-10-06)。此阶段paid0，自主采用和净收益未验证。

回答“是否连续优化”时，先列实际反例和同口径差值。当前证据支持部分收益的增量继承，不支持初始上下文单调下降，也不支持父子总成本、行动效率和通关率持续改善。运行中的新观测/必要反证可以增长；重复回执、过时全文和可按需读取的手册增长则必须定位。为了数字变小而丢掉必要状态、导致重复读取，同样属于退化。

## 2. 按症状选择诊断分支

| 观察到的症状 | 先查什么 | 优先尝试什么 | 如何判定 |
| --- | --- | --- | --- |
| 少数动作消耗大量tokens | 父子usage拆分；每个实际请求的system/schema/history/result/image | 对最大且重复的输入项去重，或定位新生成reasoning | 同任务质量下总成本降低；不能只看单个payload |
| 上下文越跑越长 | 实际序列化结果、latest事务保护、动态schema寿命、重复手册 | 区分已完成事务与未完续接；静态资料按需驻留 | 后续真实请求缩短，关键反证保留，恢复重读没有增加 |
| 压缩后重复读同一资源 | 哪条决策依据被删；exact ref是否可用；已读内容何时过期 | 修复工作集保留／恢复后的寿命；精确读取相关片段 | 同一认识持续可用，读取成本与错误决策没有转移到后轮 |
| 首token快、完成很慢 | 新输出reasoning、length、生成速度、实际thinking控制 | 缩小需要回答的问题，先取有区分力的反馈；按provider验证投入配置 | 首次有效行动更早，质量符合标准，长度续接成本可承受 |
| 大量动作仍无进展 | 目标假设、实验预测、实际变化、被否定的解释、重复状态 | 选择能区分竞争解释的实验，或用精确计算核验易错事实 | 获得可用于后续决策的新证据；最终仍以任务结果验收 |
| 研究完成但父没有推进 | 是否交付、是否消费、证据截止点、对当前选择的影响 | 短增量交付核心结论和条件，核查下一真实父轮 | 父修订解释／选择实验／有理由不采用，并记录环境反馈 |
| 作者反复创建失败 | 实际creator/schema、完整错误、host绑定与caller字段边界 | 复用规范化／校验入口，明确错误归属，减少重复表达 | 真实原调用可修复、原生执行值正确；源码手修不算模型修复 |
| pending／续接无止境 | 生命周期事件、错误是否传播、预算与cancel、agent_settled | 修复纯拒绝、超时、撤销、完成边界；保留明确终态 | 新进程和后续父轮也停止／恢复正确，不只看内存内状态 |

一次优化选最早断点。输入、输出和任务判断同时存在问题时，先判断哪一项使本次实验无法继续，再改变一个主要因素。

## 3. 上下文：保留决策工作集，压缩重复材料

### 工作集怎样分层

| 材料 | 驻留方式 | 容易出现的错误 |
| --- | --- | --- |
| 当前canonical observation、必要状态版本 | 按用户约定提供完整当前观测，清楚标识时间和ref | 用旧帧代替当前帧；为了省字丢失应有像素 |
| 当前认识、关键反证、下一实验及理由 | 短而完整，复用既有checkpoint／decision／finding | 只留下“下一步”，丢失为什么这么做，导致重复探索 |
| 最新必要回执、失败与尚未完成事务 | 保留推进或恢复所需内容 | 把已解决错误长期当义务，或压缩未完成工具续接 |
| 静态手册、creator、完整研究、旧候选 | 按需正文＋精确版本引用，明确恢复后的寿命 | 每轮全文驻留，或刚读完就过期，迫使再次读取 |
| 历史原始轨迹／可编辑推理 | 归档原文，驻留有用摘要；遵守provider协议 | 将“有archive”误认为后轮已经保有认识 |

归档前检查：下一次选择需要哪些事实、已排除解释、尚未完成实验和有效引用？这些内容要留在工作集；暂时无关的论证和原始材料可以归档。未来推翻当前判断所需的反例不能随过时假设一起丢掉。

恢复应针对精确问题，复用已存在的refs和读取接口。一次恢复后，让内容覆盖后续实际用途；动态内容按状态／版本失效，静态内容按需求失效。反复重读时，先检查生命周期和信息遗漏，再考虑扩大窗口或加提醒。

### 三种成本分别测

- JSON字符测传输／表示大小；base64和文本分开。
- 本地tokenizer只给相应编码下的估算，不代表Qwen或图像计费。
- 实际usage测模型调用，连同cache、输出和取消未知片段记录。

本项目初始上下文遵循用户的Continual Harness 1×上限。比较同一公开帧、同类工具能力、完整text＋schema及whole context；保留全4096 pixels和原生64×64 PNG。运行中增长另测，初始合格不意味着后续合格。

压缩验收需要查看**后续真实请求和决策**：信息是否仍在、反证是否被用、原假设是否被无依据重建、读取次数和总费用是否增加。可逆像素重建证明表示完整；它不证明模型理解正确。

## 4. 推理：先区分历史驻留与新生成

stage118r1同输入回放减少37.31%字符，真实样本却仍生成52,486 reasoning tokens并耗时约815秒。**历史压缩减少输入负担；新生成推理由问题、模型和投入配置决定。**

### 历史推理处理

可编辑推理只在明确支持的provider/API范围处理；成功配对事务、公开决策材料和原文归档分别核验。签名、opaque、encrypted及未完length／工具事务按协议保护。短摘录不是语义摘要的保证，关键认识应优先复用公开决策状态。

### 新推理投入

先回答“增加计算有望改变哪个选择，怎样获得反证”。有具体竞争解释、可用证据和剩余预算时投入；缺少区分材料时，先选择可授权、可观测的小实验。新反馈出现再修订，而不是对同一错误读数反复思考。

把延迟拆成请求开始→首delta、首delta→生成完成、工具／环境、编排等待。首delta很快而生成很慢，重点检查新输出；没有首delta，先查provider／传输。并发区间计算墙钟时间，父子时长之和另作计算负担。

对thinking、effort、输出上限和length续接，核对最终HTTP参数、响应usage及native行为。参数名字存在不代表生效，`low`不等于短输出。`off`可以减少reasoning，但只有目标质量同时达标才支持净收益。

## 5. 工具与schema：减少重复决定和翻译

简化按这个顺序考虑：删除重复说明／手续，复用已有入口，合并同一授权事务，改进接口，最后才考虑新增字段、提醒或worker。每项都算首次获益之前的父决策、调用往返、schema输入和失败恢复成本。

工具设计应让Agent表达一次完整意图，由runtime处理可确定的机械事项：

- 参数使用真实类型和清楚的互斥关系；按需披露高级能力，发现入口与实际验证保持一致。
- 区分caller参数、host绑定数据、发布／装配信息和科学程序语义；避免要求同一事实在多个层次重复填写。
- 在无歧义、已有授权及明确校验边界内规范化；冲突明确拒绝，保持权限、CAS、exact version和环境完整性。
- 能独立判定的preflight错误用一份短回执报告，说明字段、原因、修复方向及是否写入。依赖未准备数据的错误不能假装已经检查。
- 创建前失败不产生已发布组件；发布后trial失败说明组件已提交、试用未成功，让父能按真实状态恢复。错误标记需要验证Pi实际传播，不能只检查nested `isError`。

首次工具收益可考虑复用create＋显式assembly＋trial，减少额外管理轮；设计仍由Agent决定是否值得，runtime不替它选择组件或科学结论。

不同版本／模型反复在同一机械字段失配时，优先检查接口是否要求重复表达或模糊翻译，再判断模型能力。错误聚合能减少逐项报错，但仍要用真实样本验证修复率；把人工修正后的候选跑通，只能定位接口与算法的边界。

价值评估用剩余任务中的预期复用：**首次投资＋后续调用＋恢复成本**，与直接做同样工作的成本比较。一格已经可见的读数，也可能值得用于纠正感知；但为了它投入十万tokens，通常需要更强的后续收益证据。工具调用多、schema更短或组件更多都不是奖励目标。

## 6. 研究结果怎样推进后续行动

复用[Auto-Research ADR](plans/2026-10-01-auto-research-mechanism-and-workers.md)与[实现验收记录](auto-research-workers-implementation-2026-10-01.md)：父负责当前任务判断、研究授权、组件创作／装配；研究worker承担具体研究和持续追踪；runtime推进授权内的机械路由、调度和反馈。研究线延续不要求模型进程永久运行，新证据窗口不必创建新worker。

核心交付围绕**这条新证据会改变哪个当前选择**。用现有finding／progress／experiment_request表达：结论和证据截止点、支持／反证、适用条件、对选择的影响、必要实验与详情ref。它们是语义内容，不是新增必填schema。

逐个检查下列转移，允许有理由的不采用、放弃和纯研究结论：

| 转移 | 谁推进 | 看什么证据 |
| --- | --- | --- |
| 新证据→研究更新 | 授权worker；runtime分发 | 精确批次被分析，结论修订／维持及理由 |
| 更新→父消费 | runtime交付；父理解 | 实际后轮包含增量，父决策使用或解释不使用 |
| 结论→实验／候选 | 父或获授权研究者作语义判断 | 实验有区分条件；组件有复用价值和停止条件 |
| 候选→装配／语义使用 | 父显式授权；native runtime执行 | 精确版本、实际输入／输出，而非只有completed |
| 使用→行动／反馈 | 父选择动作；环境反馈；worker复查 | 后续行动与结果能支持、反驳或修订该结论 |

报告被读到、局部算法正确、组件被创建、动作被执行是不同事件。stage71报告确实进入过第10步对照行动，但最终零关；因此下一问题是实验和目标判断的质量，不能一概归因于“交付没工作”。

组件生成不是每条研究的终点。`system_prompt`、skill、memory、tool、subagent分别看后续影响：改了哪次判断、复用了什么方法、避免了什么重算、取得了什么正确值、由谁承担了什么职责；暴露／读取不足以单独证明利用。五类型全链路验收仍依仓库标准执行。

## 7. 实验：先让失败便宜，再判断收益

### 命题和比较器

把“让Agent更聪明”缩成一个可判定的问题，例如：

> 同一静态手册在完成消费后按精确ref过期，是否减少后续真实输入，同时保持必要契约、减少或不增加重读，并维持任务质量？

实现前确定主变量、比较器、provider／模型／推理配置、预算和停止规则。范围复用现有变更记录；付费样本从能区分命题的最小窗口开始。功能检查先复用已有失败轨迹；同一改动检查通过后，只有新失败、变化或疑点才扩大／重复检查。

判断收益时使用同模型、相近预算的独立运行；记录任务初态、种子、图像和提示差异。按预定样本和顺序运行，披露provider波动和轨迹混杂。在线更新不能回退环境历史；离线重放不能证明未执行动作会有实际收益。

### 指标与费用

任务指标先看成功、有效进展和固定资源下的质量；成本同时看父子总tokens、墙钟、首次有效行动延迟、管理轮和重复取证。有效进展需要任务依据，例如检验了可区分预测、排除了影响下一选择的解释或完成子目标；像素变化、动作数和工具频次只作诊断。

provider的input若已经包含cached tokens，缓存只作为其中的子项；Pi分别给exclusive input和cache时，再求和。reasoning若含在output中只拆分、不再加总。失败、pending、continuation、compaction和取消片段均纳入；缺计量保留unknown。日志副本／汇总不重复计入；逻辑request ID可跨length续接，结合进程、实际HTTP尝试和完成事件区分。

开发Agent的分析／工具读取成本与benchmark父子成本分别记账，再在需要时报告整体投入。已报告tokens、不同价格的cache费用和实际现金账单保持各自口径；缓存命中也有输入处理与费用，不能视为零成本。

预算检查覆盖父子实际请求和所有可能产生计费的入口。并发时把在途预留纳入共享准入，防止同时看到同一剩余额度。为预定的length恢复／可靠修复留空间；预HTTP拒绝与已发请求未知成本分开。usage通常在响应后才可见，估算预留和本地停止不能宣称供应商硬计费上限。

停止条件围绕命题、预算和信息增益预先制定。结果反驳命题、可判别条件没有出现、计量失效或资源不足时，结束该范围的付费试验并记录原因；下一试验需要具体的新故障解释。累计投入按问题计算，避免换版本／文件名就重置账目。

### 保留与晋升

权限、计量、版本和错误传播的正确性修复，可按相应证据保留；它们不会自动成为任务性能改进。性能候选的晋升需要质量与成本达到预定标准。质量相当时比较总成本／延迟；成功率提高但成本上升时披露权衡，按用户预算判断。净收益、稳定性和泛化各自需要证据。

功能正确、全链路、自主采用、净收益按[四层标准](development-workflow.md#3-四层验收与声明边界)分别报告。ARC全链路仍走真实bridge／Pi／child／router／native mutation／action／后轮，覆盖五组件和Auto-Research、普通delegate两类length；scripted provider的通过只证明接线。显式能力探针不能替代普通自主采用。

## 8. 把本次教训应用到下一候选

stage130／133的Qwen算法在独立解释中正确，真实调用却漏closed schema中的host-bound grid。当前断点是候选契约，不是科学表达式能力；下一候选优先检查能否减少参数／绑定的重复声明。

**stage134已实现，真实采用与收益未验证：** 在显式pure create＋assembly＋trial范围内，从实际授权绑定机械补齐漏声明字段的JSON根类型。既有声明、程序语义和冲突检查保持，记录额外preparation成本；不从单帧推断科学含义或自动替父选择装配。72项功能诊断和官方SDK/Pi确定性17场景／425检查通过；[当前证据](../tmp/arc-stage134-final-audit.json)不代表通关效果。

唯一真实窗口失败（3请求／26,937reported／0原生结果）：原始工具参数JSON非法，宽松解析丢失尾部assembly／trial，补全路径没有收到binding。下一诊断先对照raw与parsed参数；不要仅凭parsed调用归因“模型未选择试用”，也不要用更多提示掩盖输入完整性问题。见[134b记录](plans/2026-10-02-context-tool-reasoning-design.md#134b-唯一真实窗口失败及原始参数诊断同日)。本次未取得新上下文节省或任务收益，未启动长场。

先用已有真实错误输入及未知caller字段、冲突声明、过期ref、权限／CAS、取消、预算负例验证。再做预算内真实能力检查，看原生结果是否正确进入后轮。能力成功后才检查普通任务中的机会识别和复用；即使成功，也仍需相近预算对照判断组件成本是否值得。真实失败则保留证据，回到具体断点，避免通过增加修复轮或预算掩盖接口负担。
