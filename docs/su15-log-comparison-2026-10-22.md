**2.1 旧关事实被写成子 Agent 的长期职责。** A/B 的 session.jsonl 第 63 行在 L1 创建 `agents/analyst.md`，时间为 `2026-10-21T11:45:28.940Z`。正文明确要求分析“diagonal line of 3s”“two 15-blocks”“small 0-diamond”。L2 consult 仍使用 version 1。冻结版 `demo/arc_thin_native_runtime.ts:641` 将 refs 展开到用户消息，`:661` 将 `agent.body` 放入 systemPrompt。独立上下文因此并不代表没有继承错误前提。另有 A 的问题正文持续宣称 ABSORBS... 为 confirmed mechanic，进一步限定了研究方向。

补齐方向：复用现有 subagent 定义和 refs，将角色保留为通用分析职责，将本关对象/假设放入带当前 level/action 的可替换证据；问题中的机制判断写成待检验解释。已有授权内由 runtime 附现有阶段/动作编号，parent/研究 Agent 判断关系，避免新增“再找一个审查 Agent”。

**2.2 工具可运行被当成跨关仍成立。** `tools/block_progress.py` 硬编码 L1 目标 `(48,15)` 和单个 color-15 块；在 L2 目标为 `(33,27)`、主要需要多个块合并时仍自动运行。`arc_thin_level_carry.ts` 的 view 分支在 first ok run 后标记 held；R2-B 的 level_carry 实际在 #64 将该工具标为 held。这仅证明执行成功。

## 综合优化方案：问题、减负路径与验收对应

2026-10-22 补充，回应“记录并进行其余要点的分析”。本节为最终设计记录，沿用前面的真实事件、成本及四层证据状态。这里的“当前”限定于 R2h 冻结版本及其实际配置；不能自动外推为主工作区或其他 r04 checkout 的现状。

### 1. 用成功历史检阅机制，而非复制成功动作

四条成功轨迹提供了三个稳定见证：局部对象互动可以被重复利用；目标接触失败后需要改变解释或检验条件；在资源耗尽前将已验证机制接成中间状态序列。共同结果是 `4 个 6 → 2 个 15 → 1 个 11 → 入目标`，并不共同具备逐格预测、consult 或某种固定复盘流程。

因此应检阅当前机制是否帮助以下转移，而不把研究次数、预测命中率或坐标新颖度当作任务能力：

| 能力转移 | 历史成功的可观察见证 | 当前断点 | 优化落点 |
|---|---|---|---|
| 变化事实 → 关系候选 | 多个低阶对象消失、一个高阶对象出现后，转向合并解释 | 默认没有 CH 转换差分；A 自算后仍把合并解释成吸收 | O1 交付事实；O6 检验归因，二者分开验收 |
| 反例 → 下一检验 | g61 点目标无效后转向同类块互动；较慢历史样本最终也修订路线 | 目标接触失败被保留为“还没试这个坐标/顺序” | O5 撤销机械候选的实验权威；O6 保留主解释反证 |
| 局部规律 → 可重复子目标 | 两侧分别得到 15，再合成 11；reset 后复用已知部分 | A 已出现 15，却没有转化为另一侧可重复构造 | O6 在已有 strategy 里表达中间状态；O8 只对已验证部分复用执行 |
| 当前事实 → 可靠辅助 | 成功的关键证据来自当前 grid 与动作结果 | L1 对象留在长期角色，旧目标工具继续常驻 | O2/O3 纠正内容来源与有效性判断 |
| 证据反馈 → 及时动作 | g61 12/16 动作完成；慢样本最后一次尝试 17/27 动作完成 | 反复研究、重置与微调消耗预算，关键机制仍未变化 | O4 降低往返；O5/O6 改善实验选择，保留合理重试 |

12 步样本继承 16 步源跑的 L1 前缀，四条成功又都经过结果筛选；它们是能力见证，不是某机制净收益的独立对照。也不能把历史 Qwen 的最后 27 步认定为“当前再给 27 步就够”。

### 2. 错误开销分层：先分清能修掉什么

**接口往返是最容易界定的一类。** A/B 分别有 33/12 次 refine.focus 超长拒绝，A 有 17 次 arc_action 错误。修复一次调用格式不产生游戏信息；应减少重新写摘要、再次请求模型的往返。动态动作表和拒绝回执本来已经存在，RESET 重试究竟是模型忽略、当前输入缺失还是版本/时序问题，仍需逐次对应 provider payload；不能先假定“缺动态 schema”并重做一套。

**默认后台计算和失效内容是另一类。** block_progress 在 L2 的 A/B 分别运行 108/113 次，其中 104/113 次返回 no moving 15-block，另外 A 的四次还指向旧目标 (48,15)。累计 observer ms 为 206,905/239,253；这是组件耗时之和，不能当作可消除的墙钟时间。没有当前对象也可能是正确且有用的负结果，不能只按文字不变自动停用；本案还同时具备旧对象假设与旧目标坐标的独立证据。

**研究投入没有交付是交付和调度问题。** A/B 未形成最终答复的 consult 已知消耗 110,791/133,474 budget tokens；当前六轮工具调用用完后直接抛错，只有正常 final 才写 consult_runs。失败释放 review 门禁仅作用于当前 review，后面仍可能重新支付。不能称这些计算全无价值，但 parent 没得到可用于下一动作的结论或明确未知。

**物理变化也可能是昂贵的认知重复。** B 的 112 个动作中，26 次 changed=0、8 次 bbox 只在 row63；A 对应为 5/6 次。其余多数动作确实移动对象，却仍服务于同一个未修订的目标接触解释。因此用零变化率、new 比例或“每动作都有 delta”衡量探索收益都会漏掉主要成本。这里的 row63 分类是本次 su15 诊断，不应写成所有游戏的通用无效判定。

**重置和重复执行应计入检验总成本。** RESET 不只是一次动作，还包括恢复实验前提的动作、模型请求及资源消耗。历史 g56/Qwen 的最后一次尝试保留了局部规律，重建用于新计划；最新 B 多次恢复四个 6 后继续同一类目标尝试。应比较“新结果会改变哪项判断”与重建成本，而非一律禁止重置。

### 4. 方案取舍、责任与首次获益路径

比较三条路径：

1. **增加提醒和强制步骤**：要求每步写对象表、竞争假设、预测，再追加 reviewer。会增加 resident 内容、管理轮和失败修复义务；当前已有研究与检查却未发生关键修订，优先级最低。
2. **简化并复用现有能力（推荐）**：让已有差分到达；长期角色只留可迁移职责；旧工具改为按需；取消普通复盘的必做研究；使用已有 memory/strategy 承接反证。这条路径针对具体断点，通常不需新 schema/worker。
3. **增加对象跟踪/关系推断引擎**：可能减轻对象对应负担，但会引入遮挡、多帧、同色断连、图例与游戏区区分问题。只有 O1 已交付、O6 仍明确卡在对象对应而非因果解释时才考虑。颜色分组本身不足以认定对象或因果。

责任沿既有生命周期分配：runtime 在真实 action 边界收集 canonical 状态、编号与机械差分；parent 或已授权研究者识别机会并决定是否投入；研究者在已有预算内交付核心结论/未知与引用；parent 使用既有 memory/strategy 或修改组件形成候选与装配；runtime 保持版本、权限、预算和真实动作检查；后续 parent 根据实际结果保留、修订、缩小范围或撤下。研究线连续性保留在已有 durable 记录，失败或一个窗口结束不等于必须换一个 worker。

首次获益目标是“下一父轮直接看到当前差分 → 一次选择/修订 → 真实动作反馈”，而不是“读取差分手册 → 创建组件 → 等待 reviewer → 必做 consult → 写完整报告 → 激活”。语义选择不能省为 runtime 对自然语言的猜测，但纯事实交付无需 parent 另做装配决策。对已有稳定步骤，允许一次计划携带多个动作，并在当前停止条件触发时交还控制。

设计默认新增常驻 worker、逐动作必填字段和语义硬门禁均为零；短差分是明确的新增输入成本。移除/替换项为过时角色事实、无用途的默认 view 执行、机械 novelty pin、普通 review 的强制咨询，以及普通文字的拒绝修复。以上是候选行为；本轮没有改变任何默认开关。权限、预算、版本、可用动作和环境历史完整性检查保留。

放弃/恢复：无新证据、剩余预算不足或已有稳定路线时允许不研究、不封装；组件适用性失效时复用已有 off/按需/版本恢复入口；不把历史数据删掉，也不通过回退 harness 声称回退真实环境或撤销模型已知信息。出现净负担就撤下该候选，不能以追加提醒补救所有失败。

### 5. 有界评估与交付决定

**当前已完成的验证**是只读核对六条 canonical 轨迹、实际 provider 输入、冻结源码与 CH 原函数；补算 L2 动作分组及部分成本。文档改动不需要为此启动真实 provider。候选功能、全链路、自主采用、净收益仍分别未验证，provider/environment 状态沿用上文证据表。

后续第一项可证伪检查建议为 O1：从相同 query 基线只增加已有颜色转换摘要，比较当前证据是否直接进入后续父请求，以及自写 diff 的请求/计算是否减少。先在 #94、零变化、仅资源条变化、超过 6 组转换、超过 50 格变化及多帧事件上检验格式、截断声明与引用；离线正确只算功能诊断。完整 ch 切换同时改变图片、网格编码、帧与动作接口，不能拿它单独估计差分因果收益。

若后续获得运行授权，每次只选择上述一个主要因素：同一 L2 初始快照、yibu/qwen3.8-27b/thinking=off，当前冻结基线与单因素候选各 2 次独立续跑，按基线/候选/候选/基线交错；每次上限 1M budget tokens、64 个新增环境动作、20 分钟，先到即停，单个因素合计上限 4M budget tokens。父子、refiner、失败片段和管理轮全部计入；出现新增未知成本先停止核账，不默认为零或自动重试。原生 length 恢复仅在既有额度与权限内进行。该预算是设计提案，未运行，也不自动授权后续所有因素各花 4M。

主指标为 L2 完成与固定预算下的任务进展；“得到一个 15”等 su15 中间状态由开发侧对轨迹事后核查，不作为注入模型的提示或运行时奖励。诊断指标对应每行窄命题：取证往返、旧对象建议、失效 view 执行、未交付研究、反证后同机制重复、已有规律的后续使用。成本同时记录 parent+child tokens、失败/unknown、总墙钟、模型/工具时长、管理请求与首次有效检验延迟。跨压缩还要看后续输入及行动保留了哪些反证/未完成检验；B 的一次 compaction 不能单独证明遗忘是根因。

判定提前固定：若任务结果更差，或同等进展父子总成本更高，不保留为默认优化；局部错误减少但任务无改善，只接受该局部声明；两次重复不足以证实泛化或小幅收益，无法判断则记录不确定。节省百分比必须来自干预对照，不由上述 17.6%/26.6% review 子账直接推算。若 O1 减少手算但依旧误归因，下一因素是 O2 或 O6，不能将对象语义引擎和更多研究一并加入后归因于差分。

负例必须包括：旧组件跨关仍通用；当前对象暂时不存在但负结果有意义；位置/顺序确实决定结果；合理重置能产生新反证；绕路和对象合并使目标距离暂增；研究无新证据或临近预算；未知事件批量执行的错误放大；大/动画差分的截断；压缩后需恢复反例。没有这些检查，少调用或少动作不构成减负收益。

本轮交付决定：**保留诊断，优化方案处于设计状态；不声称性能已优化。** 优先核准 O1 的实际生效路径，再分别评估 O2/O3 和 O4 的低成本修订，随后 O5/O6；O7 只在重复计算有价值时封装，O8 最后处理已验证计划的执行效率。每次实现前重查目标 checkout，避免拿 R2h 的历史问题修已变化的主分支。涉及 ARC self-harness 闭环声明时，另执行根 AGENTS.md 要求的真实 bridge/Pi/child/router/native mutation/action/后续父轮完整 smoke，覆盖五类组件、两类 length continuation 和语义输出；本报告不替代该验收。

关联 backlog B/C/D：研究结论是否改变后续行为、父子总成本是否下降、反证和计划是否跨阶段/压缩延续，均保持开放。本次新增的是可定位的问题与单因素方案，没有关闭这些质量问题。

复用现有 chView：RECENT HISTORY、OBSERVATIONS SINCE LAST QUERY、CURRENT STATE、hex 网格和支持图像时的 PNG，以及带 reasoning/actions 的 ARC 接口与 env.act 路径。保留显式 query/inline 兼容入口；不增加混合观测模式。当前 graph/任务研究/组件装配架构不变。

动作挂载统一到现有 submitAction 和共用回执函数：逐动作 predict、predict_skill 与 idea 采用既有语义，列表级旧字段仅作为首动作兼容；goal outcome 和 carry delta 在每个动作完成后交付，不丢给下一次不确定的读取。机械路由由 runtime 推进，解释/采纳仍由 parent。RESET、动态可用动作、预算、预测失败停止、换关/终态停止及环境错误恢复保持原边界。

新增常驻 worker、语义门禁、强制填写项均为零。CH 图像、完整网格和关键帧的输入成本属于完整适配本身，按实际配置和 payload 记录，不把它描述成单独差分优化的因果收益。失败时保留已执行前缀和拒绝/停止原因；显式 query/inline 可作诊断比较，但不改变已发生的环境历史。
