# Meta-harness 开发流程与证据标准

生效日期：2026-10-02（Asia/Shanghai）。用户已确认采用本流程。

适用范围：meta-harness、Auto-Research、Agent 可见 prompt/tool、组件创作与装配、调度、上下文管理的设计、实现、评审和完成声明。根目录 [AGENTS.md](../AGENTS.md) 是开发 Agent 的必读入口；[README](../README.md#开发) 是人工开发入口。本文是流程标准的唯一详细来源，已有计划保留历史证据，不作为最新实现的替代。

本次决定：采用“真实问题 → 窄命题 → 低成本生命周期 → 分层验证 → 按证据保留或修订”的开发方式。优先简化现有机制；增强提示和增加管理 Agent 都需说明额外收益与成本。规范约束开发工作，不向 Pi 游戏上下文注入开发手续，也不自动改变当前 runtime。

## 1. 成功标准

每项改动说明：在什么情境下，谁的哪项负担减少，预期带来什么可观察任务收益，哪些结果会推翻该预期。成功由任务目标和资源约束决定；报告数、组件数、调用次数和测试数量只是诊断指标。

使用一份 [变更记录](templates/meta-harness-change.md)，或在已有计划/报告中使用同样栏目。设计、实现、验证在同一记录增量更新，避免另建重复真值源。记录是开发产物，不是运行时必填字段。

小型文档修正、局部诊断和保持行为的维护按风险缩减记录与检查。本流程不要求每次改字都启动真实 provider，也不要求每次实验覆盖全部组件；ARC 闭环声明仍执行根 AGENTS.md 的完整矩阵。

## 2. 开发步骤与完成条件

| 步骤 | 工作 | 完成条件 |
| --- | --- | --- |
| 诊断 | 读取当前代码、实际生效配置和可用真实轨迹；区分观察、解释和猜想 | 能定位失败/机会、对应生命周期环节和证据出处；没有真实轨迹时明确诊断缺口 |
| 定义 | 提出一个主要命题，写明负担、适用条件、预算、负例、比较方法和推翻条件 | 在实现前能判断实验什么结果支持、反驳或不足以判断命题 |
| 设计 | 比较简化/复用、改进接口或提示、增加职责承担者；核对权限及生命周期 | 明确每个转移的责任主体、成本、失败恢复和放弃条件，方案不依赖未注册能力 |
| 实现 | 一次改变一个主要因素，复用版本、资源和证据体系 | 改动与命题对应；保持必要完整性检查；明确新增/移除的决策、提示、schema 和管理往返 |
| 验证 | 做与改动相称的诊断、真实链路及真实模型实验 | 四层证据分别有结果/未验证标记、产物和局限，异常及失败样本完整计入 |
| 决策 | 根据预先声明的标准保留、修订、撤下或保持实验状态 | 完成报告匹配证据；未测层级和下一检查留在同一记录，涉及延后事项时更新其状态链接 |

“代码实现完成”“真实接线验收通过”“真实模型会自主使用”“已证实净收益”分别陈述。用户授权范围只覆盖实现或文档时，可以完成该范围，并保留行为/收益未验证；不能为提高证据层级扩大授权、重启用户已关闭的运行，或隐去剩余问题。

## 3. 四层验收与声明边界

| 层级 | 最低证据 | 可以声明 | 仍需验证 |
| --- | --- | --- | --- |
| 功能正确 | 针对性组件/协议检查，包含相关负例与失败恢复 | 给定输入的功能、权限、版本或恢复行为正确 | 真实链路与模型行为 |
| 全链路可达 | 实际 runner/bridge/Pi/child/router/native mutation/装配/action/后续父轮产物 | 验收情境下的接线与生命周期可达 | 无脚本引导的采用与任务收益 |
| 自主采用 | 真实 provider 在普通运行中自主识别机会、作决定、完成适用路径；审阅漏用与合理不使用 | 在已测情境下的采用行为及边界 | 重复性、泛化与净收益 |
| 净收益 | 相近预算的独立重复对照，任务效果与父子总成本共同评估 | 已测模型/任务/预算下的收益，附差异和不确定性 | 未测情境和更广泛性能 |

每层分别记录状态：未验证、通过、失败、不确定，或不适用（说明理由）。高层观察不能替代低层完整性检查；不同产物的 provider/environment 是否为真实实现、test double 或 mock 必须分别标注。

ARC 全链路声明必须执行 `arc-harness-smoke`，保留五类组件、两类 provider `length` continuation、语义工具输出及后续真实父轮的既有门槛。pytest、手写 JSONL、离线父脚本和组件 fixture 是诊断证据。确定性 provider 的真实 runner smoke 证明接线，不证明真实模型行为或游戏质量。

自主采用实验使用普通运行；显式闭环探针、指定必须调用某工具/创建某组件的任务、脚本替模型选调用顺序都归入诊断/接线。记录实际引导条件；窄能力任务可诊断使用问题，但不据此声称一般自主识别能力。

研究完成、组件创建、装配/暴露、实际使用、局部正确性、任务成功和因果贡献分别记录。Tool/Subagent 核查真实语义输入输出；Memory/Skill/System Prompt 的读取或暴露不等于实际利用，需检查后续决策/行动证据，无法确定使用归因时保留不确定。

## 4. 生命周期与减负设计

沿“机会 → 识别 → 投入 → 候选 → 装配 → 语义使用 → 反馈 → 保留/修订/撤下”检查。纯研究可交付结论而不生成组件，父自主创作也不必先发起研究。组件版本回退只影响未来配置，不能回退环境或消除已获知信息。

每个转移说明：推进者、可观察输入、权限、完成证据、等待/失败/过时处理及停止条件。给定职责后由 runtime 推进机械证据路由、已授权调度、版本校验和恢复；科学结论、价值判断和采用选择由获授权 Agent 承担。遵循 [Auto-Research ADR](plans/2026-10-01-auto-research-mechanism-and-workers.md) 和当前父作者/显式装配边界。

诊断采用漏斗时分别计数：适用机会、识别、投入、候选、装配、实际使用、反馈。适用性基于可见证据的外部审阅或显式条件，不能用“工具存在”推断必有价值，也不能由 runtime 从自然语言猜出适用性。保留机会分母、判断理由和未知项；合理不使用、放弃及负收益样本都进入报告。

降低首次获益所需的父模型决策和往返。设计中列出从发现到首次语义使用需要哪些模型决策，哪些手续可合并/复用，哪些属于权限、预算、版本或环境的必要检查。减少手续时保持精确引用、原子性、失败回执和可恢复性。

评估投入应考虑剩余任务中的复用收益，也应允许因任务变化、证据不足、剩余预算不足或试用失败而停止。新增“选了开发就必须完成”“必须读/回顾/使用”等义务前，检查沉没成本与任务延误；既有运行规则的调整另行实现和验证，文档不能冒充已经修改的行为。

## 5. 提示、门禁与上下文预算

新增提醒、必填字段、review、action gate、worker 或工具 schema 前，先找真实缺失环节，比较删除重复内容、按需引用、机械事务和现有职责复用。记录常驻成本、预计新增决策/管理轮、触发与失效条件，以及对应收益证据。

运行时硬阻断由权限、预算、版本/数据完整性和环境边界支持；能力发现、研究机会和复盘优先采用不阻塞的短事件。新语义门禁须有具体任务必要性、时间/失败/放弃路径和真实验证，不能用强制触发率代替收益。

当前任务工作集优先保留最新 canonical observation、有效认识/反证、当前计划与下一步、预算和当前必要失败。创作手册、研究细节、候选目录和旧结果按精确引用恢复；同一变化避免重复交付、完整展开和要求逐项确认。当前观测表示遵循用户最新约定，不因缩短上下文删减应提供的网格/PNG。

同时测量输入 token/图像、system/schema/历史/结果占用、隐藏 reasoning、输出、检索与管理轮次。JSON 字符、含 base64 的请求大小和模型输入 token 是不同口径；缺失计量写未测量，不能当零。缩短输入不自动等于减少当前输出推理。

压缩/恢复验收核查实际后续 provider 输入和决策：关键假设、已排除解释、反证、未完成实验及决策理由是否保留；遗漏时能否恢复。存盘、ref 存在和成功读页只证明可恢复数据，不证明认知连续性。

## 6. 真实模型实验

在运行前填写变更记录的实验协议，明确模型/provider/推理设置、任务/配置、引导条件、主要变量、比较器、独立样本与运行顺序、时间/动作/父子计算预算、停止规则、主要指标和可接受退化。具体阈值按任务确定，不添加无依据的全项目调用配额。

优先选择一个小的可证伪循环，例如“重复计算出现时，自主创建并使用工具，后续同类计算的总成本下降”。先做短运行确认观察条件与命题可判别，再按预定重复样本做对照；诊断途中改变协议要注明，探索样本与确认样本分开。

需要性能/净收益结论时，用相同模型、相近任务和预算的独立重复运行。按命题选当前实现、无机制的最小基线或单因素消融；比较新旧机制时直接加入旧版对照，避免把多个差异都归因给本次改动。记录任务/初态/种子是否可对齐，无法对齐时解释限制；单次成功作为线索。

ARC 单次生命只有一条不可回退 canonical 历史；RESET 也是有成本的真实事件。独立对照运行各自产生轨迹；离线重放可检查计算和接口，不能模拟未执行动作的真实收益。Harness 撤下不撤销历史，因此在线前后比较需披露状态、阶段和剩余预算混杂。

最低测量项如下；无法测量的项附原因和结论限制：

- 任务：成功/失败、有效进展、环境动作与失败/无效动作、固定时间下的进展。
- 行为：机会漏斗、合理不使用、首次语义使用、试用失败、放弃/修订/撤下、重复取证。
- 成本：父及所有 child 的 input/output/reasoning、可用的计费/cache 数据、模型/工具/编排耗时、管理轮与首次有效行动延迟。包含 pending/失败片段；output 已含 reasoning 时不重复相加。
- 连续性：研究截止点/过时结果、跨阶段反证、压缩/恢复后的认识和行动一致性。

总墙钟时间按区间核对并发重叠，父子调用时长之和作为计算负担另报。响应头、首 token 和 stream 完成分别记录；不完整关联标注估计。失败、取消、超时和未完成流保留，不只统计成功 child 或已完成消息。

任务质量与成本共同决定净收益。降低 token 而损害预定任务质量，或提高分数但违反预算，都按预先标准判定，不能事后挑选指标改称优化成功。报告各次结果及离散程度；样本不足时保留探索性结论。

## 7. 评审、交付和后续工作

评审检查命题、负担、生命周期、实际生效路径、四层证据、负例和成本。真实行为失败时，定位到具体转移，先排查未暴露、调用摩擦、前置成本、过时/丢失材料和价值不足；每次只改一个主要因素，避免用更多提示/门禁掩盖断点。

完成报告引用变更记录，简述改了什么、移除了什么负担、运行了哪些验证、每层证据和局限。声明收益必须有真实行为/对照产物；“实现完成，采用和收益未验证”是合法而明确的交付状态。

尚未评估的机制保留实验状态，新增常驻义务/默认启用需与用户授权和证据匹配。失败或无收益时简化、修订或撤下该改动；调整配置前保留诊断证据。预算内无法判断时记录下一项可证伪检查，避免继续扩建来掩盖不确定性。

涉及 [延后事项](deferred-research-todos.md) 的父子通信、总成本和跨压缩认知质量时，在原 backlog 留链接及精确证据状态；仅流程落盘或接线通过不勾选这些质量问题完成。后续路线图优先采用一个窄循环验证，再扩展组件类型和研究职责。
