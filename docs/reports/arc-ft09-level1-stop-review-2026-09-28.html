组件与研究内容

  • Memory：27 条版本记录，25 条 level scope、2 条 state scope；其中大量是 arc-action-probe-record-v1，保留父 agent 的假设、预测、反证和 action 回执，claim_status=basis_cited_unverified。它们多数是 trace，而不是已确证规律；本轮未被显式装配。若只读取 summary，诸如“某位置会响应”容易误读成事实，实际 delta 全为 0。
  • Skill：controlled-action-variation-after-noop@v1，提供记录坐标约定、只变一个因素、立即检查 delta、无效时停止重复的流程。它是方法而非单纯轨迹；已入池、装配、投影，并有一次父 agent 的使用效果评估。该评估称诊断纪律有所改善，但 3 个后续试验都无变化；随后的多次重复坐标也限制了这个正面判断。
  • Auto-Research：2 次完成。第 1 份报告为空且 inconclusive；第 2 份指出相同无效探测只支持狭窄的诊断原则，不能推出目标选择规则，并提出单因素变更试验。它支持 Skill 形成，却没有交付可验证的“哪里、为何可点击”模型。
  • Subagent：一次性 delegate_task 调用 120 秒超时；没有持久 Subagent 组件。一次性委派与持久组件的回执已区分，不应把前者算成入池。
  • Tool / System Prompt：没有持久候选或版本；系统提示存在初始装配记录，但没有主 agent 作者化的任务级策略 segment。

审计的完整方法演进链仍为 complete=false。虽然 Skill 从第 2 份研究报告导出并被装配，方法审计未形成一致的候选→采用→实际使用→效果评估→研究反馈链；这需要按精确 ref 检查审计归因，不能只凭“已有 Skill”宣称闭环。

主要机制问题与建议（待确认）

  1. 动作证据没有成为下一轮的硬事实。“该坐标在当前状态零变化”应作为精确的局部证据索引送到下一轮，而不是只留在未装配 Memory。对完全相同的动作、坐标、状态指纹，运行时可给出明确的重复提示；是否重试仍由主 agent 决定，不设置动作 gate。
  2. Memory 的 trace 摘要混合预测与观测。保留大量轻量记录符合原设计，但投影和检索应分别显示“预测/假设”与“实测 delta”；尤其不应把“预计会响应”写成事实口吻的 summary。scope 继续由证据边界决定。
  3. Skill 的适用条件与效果评估需要更严格对齐。该 Skill 写“至少两次相同 no-op”时触发，而早期动作并非相同坐标；后续又重复已失败坐标。建议在 creator 指导中要求操作性触发条件、一次试验后的停止条件和下一轮观测绑定，仍不增加准入门槛或 review adapter。
  4. 研究应服务于当前能力瓶颈。在连续零变化后，下一份研究需要提出可由公开帧检验的坐标/交互表征或最小区分试验，而非重复“换个点试”。父 agent 可直接选择 Tool、Skill 或规划 System Prompt 承载方法，研究报告本身不自动升级。
  5. 目标级规划没有升级。主 agent 直到中断仍停留在“寻找任意可响应点”，没有把成功条件、候选解释、坐标约定和反证结果综合成新的 scoped System Prompt；应在连续无进展但证据充分时提供显著的规划重估机会，是否作者化由主 agent 决定。
  6. 运行恢复需针对瞬时 provider 拒绝。当前 runner 对首次 provider error 退出，避免无限重试是合理默认；但并发限制中断了在线状态。建议仅对明确可重试且未提交 ARC action 的错误做有限退避、保留同一 bridge/checkpoint，次数用尽再显式失败；对配额耗尽和未知错误继续立即停止。

边界保持不变：ARC adapter 只返回公开状态并执行 action；主 agent 决定语义、组件创建与装配；runtime 仅提供精确证据、版本校验、提示与回执。没有新增 review adapter、固定阶段配额或自动作者化。
