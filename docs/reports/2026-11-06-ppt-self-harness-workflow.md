# PPT 任务中的 self-harness 流程

## 目标

Agent 通过持续构建、使用和改进 self-harness 完成 PPT，并以实际作品的叙事、设计、美学与视觉传达质量检验工作系统。资料准确性是基础要求。Agent 自主选择能力、方法、组件和协作方式；数量、版本或评分文字本身不能证明进化。

## 运行过程

1. 开始任务时，Agent 根据受众、目标和已有资源，分别判断生产与评阅能力缺口，组装可执行的工作方法。
2. 在制作与评阅过程中，任何发现都可以触发 harness 思考：现有能力、策略、方法、工具、角色、协作或记忆是否足以支持下一步？哪些解释和反例值得比较？
3. 每个制作、渲染、评阅和能力发展的完整轮次中，Agent 分别改进生产侧与评阅侧。评阅侧从用户目标和作品证据出发，自主扩展与修订树状评价维度。两侧方法都要应用于后续真实工作。
4. 对每项改进留下证据链：观察、关于能力缺口的假设、候选策略、组件与版本、后续实际使用、改变的决策、对比结果与仍未验证的问题。记录可由 Agent 使用现有组件或 memory 完成。
5. 评阅方法尽量用应通过与应拒绝的案例检验，生产方法用可比较的真实结果检验；结果不支持预期时，修订或淘汰方法。

## 边界

- PPT 页面问题是任务反馈；把页面调好不自动证明 harness 进化。一个版本被保存也不代表已使用或提高了质量。
- 一轮是具有制作、真实渲染审阅和两侧能力发展的完整周期，不是一次工具调用；阶段被中断或证据缺失时保留待办，不编造闭环。
- Agent 决定具体拆分、触发机会、组件和实验。每轮两侧都应推进，但不能用无意义改字、堆组件或虚构改善替代实际能力变化。
- 当前接入由系统提示、ADAPT 提示和查看页面时的提醒完成，没有运行时强制门禁或语义质量裁判。真实模型是否执行、使用和受益须由后续运行证据判断。
- 单次运行只能观察关联与具体案例；同一底稿的前后对比仍可能受其他变更影响。没有可靠评分或盲评时不声称获得高分或证明因果提升。
