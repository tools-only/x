1. 判断与推荐

问题判断建议
Auto-Research 的定位是否合理？合理。持续问题、研究职责与有界执行分开，核心结论交付父、详细分析留在研究线，适合长任务。保留机制；把价值标准明确为减少任务决策负担、改善进展。
当前机制是否合理？授权、只读快照、增量交付、版本和停止机制合理；新证据触发、父侧转化和时效之间仍有成本张力。优先检查交付到决策、候选到语义使用的转移。
更合适的功能形式？日常使用宜围绕“哪个选择尚不确定、什么证据会改变它”；持续研究保留为需要跨阶段跟踪的形式。按决策组织短研究，持续职责按需承担长问题；两者复用同一后端。
是否要整体重构？目前缺乏收益证据支持替换成熟调度和版本体系。采用渐进收敛；仅当父侧语义转写或过时交付持续占主导，才调整权限合同或交付架构。
在线不可回退下最有潜力的方向？反证与依赖连续性、当前状态上的纯计算、能区分解释的有界取证、反馈驱动的短行动程序。先验证前两项中的一个窄循环，再进入实验请求或行动程序。

我的核心判断是：研究机制有价值的原因，是它让父 Agent 获得更及时的证据和更便宜的判断能力。研究产物可以直接改变行动，也可以成为方法、工具或持续职责。创建组件只是其中一条路径；某些正确结论只影响一次选择，强行组件化会增加成本。

此外，单次生命任务的剩余复用机会不断减少。一个完整、可复用的能力可能来不及回本；一次短反证检查却可能马上避免损失。因此，判断研究投入时应同时考虑当前决定、结果到达时间和剩余任务长度。

主推荐：保留 Auto-Research 的研究线、授权、broker、证据游标、短交付与反馈基础。把它作为“按需证据与方法支持”的后端，默认由当前决策需求驱动；持续 worker 只承担确需跨阶段维护的问题。Harness 演化优先吸收参数化计算、条件性方法和有效认识，收益证据不足的管理步骤按需退出。

2. 当前实际机制与证据

2.1 已经实现了什么

2026-10-01 ADR 的最终更新和源码一致：Auto-Research 是机制，可以由多个研究 worker 承担职责。research_line_ref 表达持续问题，worker 表达分工和授权，session/run 表达有界执行；窗口是证据批次。不能继续用 ADR 中实施前的第 7、10 节描述今天的缺口。[S2][S3]

环节当前行为边界

证据与调度新行动、验证、组件使用与评估按种类入队；父 context 边界推进。默认最多 2 个 worker 并发，一批最多 32 个新 ref。active 输入固定；新证据排入后续片段。入队、授予访问、读取和分析消费分开。
连续性pending 等待新证据；completed 后可创建同线后续 session。保存 checkpoint、前序报告、反例和未完成检验。有恢复入口不等于真实模型恢复了关键认识。

反馈与停止实际使用/评估回到授权证据流；按 output/run 预算、连续无消费、complete/drop、失败、撤销、终局停止。无消费是机械诊断，不是科学无进展的充分定义；共享预算另由 provider/runtime 约束。

2.2 今天的简化必须计入现状

当前 ARC 路径已在首次研究时准备并登记方法读取，继续执行，不再要求父模型先接收手册、下一轮重试。默认工具面经 registerManagementTool 投影隐藏计划字段和 enqueue / inspect_plan / release，保留共用 skip；完整 canonical 参数仍在执行前校验。读取完整 TypeBox 定义中的 14 个 action，不能推断最终 provider 仍常驻全部 action。[S6][S7]

B9 的同脚本确定性测量记录 Auto-Research schema 从 3385 降到 3293 序列化字符，默认 24 个字段、11 个 action；全部工具定义 24823→24285 字符，约减少 2.17%。两版各 7 次请求、语义值 2。这是接口披露的局部证据，不是模型 token 节省或净收益结论。当前完整研究指导是按需材料；ARC 日常投影已经是短入口，不能把整份操作手册都算成常驻成本。[S9]

一些按需文档仍写旧的 read→retry 或 creator 前置。这是合同与描述一致性的维护问题；应该纠正文档分叉，不能再加常驻提醒来补偿。本文把 B9 当作最近可恢复局部证据，未假定正在变化的全部工作区已经完成同版全矩阵验收。

3. 关键张力与故障位置

3.1 组织研究的粒度与行动需求的粒度不同

研究线关心跨阶段的问题；父当前面对的是一个具体选择。例如“目标规则是什么”可长期追踪，“此刻操作 A 还是 B”只需要能区分这两个选择的证据。已有 parent_relevance、experiment_request 和 planning_implications 能表达这种关系，但一个报告、方法候选或索引不一定把父的下一步判断变得更便宜。

设计缺口是默认交付应如何服务选择，而非新增 topic 数据结构。可以在现有字段中优先表达“哪些判断改变、影响哪个选择、什么尚未知、需要什么证据”。不要求父另填 decision 表，也不强制每份研究即时改变行动。

3.2 父拥有最终判断，并不要求父重复推导全部内容

目前方法候选仍需父写完整可执行 body，再装配与试用。所有权和权限边界很清楚，代价是研究者已经理解的算法或方法，父可能还要重新理解、重新表述、重新满足接口。这是潜在成本，并非已证实的主因：当前已有 source 简化、准备默认值和合并试用，需要先测这些改进后的父侧负担。

若父转写仍是主要断点，有两种层次：先让方法候选保留参数化算法说明、最小输入/预期输出和已有实现的精确引用，父继续作者化。当前研究 child 合同禁止返回 Tool 程序/实现；若需要研究者提交代码片段或隔离完整可执行草案，必须另作合同变更与验收。父选择精确草案后提交仍保留最终选择权，但作者职责已经改变，需要单独 ADR 与 scoped acceptance。异步 worker 不能直接改当前 Harness。

3.3 新 ref 和已消费 ref 不能代替信息价值

当前调度在有新证据时可续研，连续两片段无消费会停止。这对机械循环有用，但一个 worker 可能消耗了很多 ref，却只确认已知现象；反过来，一个旧 ref 中的关键矛盾可能值得重审。建议由获授权研究者维护待辨别问题和等待条件，runtime 只匹配确定的资源/事件条件。科学上是否值得继续仍由 Agent 判断。

因此，不建议增加 runtime 的“相关性评分器”去读所有 prose，也不建议为每个新窗口再开一次研究。优先复用 checkpoint 的 pending 问题、已有 queue 与授权。

3.4 异步收益取决于结果的有效时间

异步可以重叠计算，不能自动减少总成本。父继续行动可能使结果失效；父等待则付出延迟。结果必须区分：绑定某帧的数值、绑定某阶段的认识、仍跨阶段有效的规则、影响尚未提交选择的反证。精确 cutoff 能证明研究看到了什么，不能单独证明今天仍适用。

短卡限额已存在。下一步应测当前相关结论是否在有用的决策边界到达，以及父恢复详情的费用。增加 worker 数量会放大过时队列和共享 provider 配额竞争。

3.5 存储连续与认识连续不同

当前保留反例、checkpoint 和精确引用已经合理。问题是恢复后模型是否仍知道“某解释为什么被排除、哪个实验尚未完成、当前计划依赖什么”。短结论与 archive marker 可能保留来源，却丢失否定理由。应检查实际后轮输入和判断，再决定是否需要额外 consolidation；无需先造第二份知识真值。

3.6 管理能力应按需求付费

多 worker、计划 DAG、节点 release、周期窗口 review 对某些长任务有用，默认研究不应先变成项目管理。当前默认 schema 已减少部分负担；仍应区分单次提问、持续职责、复杂依赖三类用途。评价单位是任务收益与父子成本，不能是研究启动率、完成数或组件数。

诊断边界：以上既包含源码可见的结构张力，也包含历史失败。没有新匹配实验，不能把其中任一条宣布为当前全部浪费的因果主因。下一轮应只选择最早且可观察的转移断点。

4. 不可回退环境改变了什么

在线单次生命中，行动改变下一步状态、证据分布与可达机会；RESET 也可能是有成本的真实事件。撤下一个 Harness 版本只改变未来配置，不能消除已经采取的动作、损失或获得的信息。

Single-Life Reinforcement Learning 为单次 episode 完成任务提供了相关问题设置；本项目没有因此使用其中的 QWALE 算法，也没有论文性能可直接迁移的依据。Learning to select computations 则支持把有限计算的选择和停止本身当成决策问题；这里借用问题视角，不声称实现 BMPS。

4.1 计算、取证、能力建设有不同回报期限

投入可能收益主要成本在线判断
读轨迹、独立分析、纯计算当前选择更准确或更便宜父子 token、延迟、恢复与整合有机会在一轮内回本；需要结果及时、正确且相关。
真实动作取证区分解释，同时推动任务动作、状态改变、不可逆损失与时间尽量选择兼有进展与辨别作用的动作；不能当免费实验。
创建 Tool/Skill/角色/策略后续同类任务更可靠、减少重复推理作者化、校验、装配、试用、维护与驻留剩余复用机会足够时投入；临近终局可以只算一次。
研究/计算的预期价值 ≈ 当前决策质量的预期改善 + 剩余任务中的复用节省
− 父子计算成本 − 等待与整合成本 − 信息过时造成的损失

行动取证还需计入：动作机会成本、不可逆损失和未来选择空间的变化。

这是设计判断框架，不是 runtime 自动估值公式。收益难以标定、目标优先级不同，不宜把几项未经校准的数字加成一个强制分数。先声明主要指标与硬预算，再比较质量和成本。

4.2 认知分支可比较，环境分支不可凭空存在

两个 worker 可以对同一公开历史独立解释；在冻结帧上比较两个纯函数也可重复。这些是认知或计算对照。未执行的真实动作只能保留为预测；模型想象的后续轨迹不能当环境反馈。不同 worker 的一致意见不构成新增环境证据。

在无法可信估计灾难性损失、且一次错误会关闭后续任务机会时，应优先使用已有证据、只读检查或保留选择空间的行动；必要时等待或放弃该试探。这里不宣称无条件 safe exploration、no-regret 或最优在线学习保证。

4.3 Harness 的价值是改善后续决策过程

在这类环境中，Harness 很有潜力的部分包括：稳定获得当前状态、准确计算、保留关键反证、让旧认识正确失效、缩短后续选择路径、在变更时停止旧方法。它可以体现为原生 runtime 能力、作者化组件、已有研究职责或更短的上下文投影；不必全部生成一个新组件类型。

某个机制比 Auto-Research “更适合”，通常意味着更贴近具体负担；它也可以由现有 Auto-Research 承担，无需成为竞争系统。最有价值的组合是：研究解释未知，确定性工具处理稳定计算，当前工作集承载有效认识，父决定真实行动。

5. 三种可选择的功能形式

路线功能形式适用情境成本与局限建议
A. 保留当前机制并精简start、assign、短交付和现有父作者链继续；清理描述滞后和重复交付，量化时效。研究量不大；问题常跨阶段；最新接口尚未做真实评估。迁移最小，仍可能需要父组织问题和转化候选。近期默认实施方向。B9 已做的披露等直接复用。
B. 专门化的研究职责按目标辨别、反例复核、方法评价等分配职责；各自维护同线或独立线。一个长期问题确实反复消耗父决策，且并发分析有清楚价值。职责重复、盲审泄漏、通知与配额竞争。固定多个常驻岗位容易净增管理。按需使用，不能先启动一组角色再寻找工作。
C. 围绕当前选择组织证据与方法父表达待决选择/核心不确定性；短研究服务它，长问题沉入原有研究线；结果优先以判断差异、反证或可用计算交付。在线不可回退、预算紧、行动时效明显；报告多但难以转成选择。需要校准交付语义和过时处理；狭窄关注当前选择可能忽略长期潜在规则。推荐目标形态。保留少量真正长期的问题，不把所有研究缩成下一动作。

推荐 A→C 的渐进迁移，B 作为已有可选能力。先用一个当前研究问题验证结论的交付与后轮使用，再决定是否改变默认接口。A 与 C 初期可以共享全部持久对象和工具名；“围绕选择”先是交付约定，不需要新增 decision database、总控 scheduler 或 mandatory review。

如果任务短、没有重复不确定性、父已能低成本决定下一步，完全不研究是合理基线。如果独立计算已经足够，调用现有工具更便宜；如果问题跨阶段持续变化，assign 比反复 start 更合适。对于重大规则或长期目标，仍允许开放研究，不能只让 worker 回答父已设定的 A/B。

6. 推荐的目标结构

6.1 三类用途，复用现有对象

短研究：支持一个当前判断

复用 start。父给可见困难、准确证据和有限预算；worker 可先纠正问题本身。达到有用中间结论即可交付，证据不足就返回辨别性请求或未知。

持续职责：维护一个长期问题

复用 assign 与研究线。新事件机械路由；worker 保留关键反例、依赖和等待条件。没有值得分析的新材料就休眠，有界 session 延续职责。

第三类用途是方法改进：父或授权 worker 发现重复判断/计算值得参数化时，用现有候选、作者合同、组件版本和装配路径。它不应成为每条研究的结尾。

这是现有职责的收敛方式，不代表新增六个服务。完整当前 grid/native PNG 保持；派生特征与研究解释始终可追溯到原始证据。

6.2 结果按用途分流，不要求组件化

  1. 判断变化：“旧解释被哪条反证削弱，哪个选择需要重估”。直接服务后轮决策；有效内容可进入已有 checkpoint/finding。
  2. 证据需求：“哪些解释仍区分不了，什么观察会区分它们”。走现有 experiment_request 或只读资源请求；父选择真实取证。
  3. 可复用方法：确实存在重复成本时，提供适用条件、参数、预期结果与失效条件；进入父作者和装配链。
  4. 无当前收益：结论后续相关、问题过时、证据不够或不值得继续。保存精确详情，父无需逐项批准或补做组件。

这些是报告语义的优先顺序，不是四类新增必填 schema。先复用 conclusion、counterevidence、planning_implications、experiment_request、method_candidates 与 research_progress。某报告不包含全部内容也可以成立。

7.1 有效认识、反证与依赖连续性

窄命题：在同类不确定性反复出现或发生压缩时，复用已有 checkpoint/finding 的最小认识状态，比仅恢复长报告更便宜，并减少被早期反证推翻的旧解释再次进入行动。

由父或获授权研究者维护几项真正影响选择的主张：已观察事实、仍竞争的解释、排除解释的原因、当前计划依赖的前提、下一辨别点。原始证据保持一份；runtime 维护准确引用和机械版本失效，Agent 判断语义矛盾。引用同一旧证据的多个报告不能重复提高可信度。

依赖关系尤其有价值：当“对象身份”被推翻时，依赖它的“目标规则”和“下一动作”要重新估计。并不需要完整知识图谱；先把几个关键依赖表达在既有文本和 depends_on_refs 中，测是否真正改变后轮判断。

不用条件与推翻：短任务、没有关键旧证据时直接保留小工作集。若新增状态重复另一份真值、每轮维护比读报告更贵，或反证在输入中仍被忽略，应修订表示与用途，不能继续扩大摘要。

7.2 当前观测上的纯计算提取

窄命题：重复对象提取、区域计数、位移匹配或候选比较出现时，一个小的参数化纯 Tool 在后来输入上复用，可以减少总计算和错误，不依赖固定场景知识。

Agent 决定算法与语义，runtime 绑定授权的准确帧、准备数据、执行限额、返回具体值并记录来源。父根据结果决定真实动作。当前 source、host/grid 内部绑定和 pure trial 已经有基础；先证明复用，避免再加新执行引擎。

Tool 最好输出与选择直接有关的小结果及必要见证。例如两种候选操作影响的对象集合和可检验差异，而非永远返回完整派生图。完整当前观测保持，详细结果可按 ref 恢复。具体算法是否符合真实目标仍由任务证据验证。

不用条件与推翻：只需算一次、剩余预算不足、目标语义尚未明确时，可用现有计算或继续取证。若创建/修复成本大于剩余复用收益，停止建设；正确局部数值没有影响决策时，不宣称任务收益。

7.3 按当前选择组织短研究

窄命题：对一个明确待决选择，把已有 report 优先投影为判断变化和必要反证，比要求父读完整研究再组织行动，减少管理轮与首次有效行动延迟。

父不需要先写全套假设，只表达困难和可用证据。worker 可发现选项定义错误、目标本身未知或需要重新表述问题；返回“问题尚不成立”也有价值。长期价值保留在研究线，当前卡只包含当前相关变化。

示意交付：“当前证据排除了 H1 的某项预测；H2/H3 仍兼容。暂时无法支持原计划步骤。差异可由一次当前状态的 P 观察检验；无需创建组件。依据与 cutoff 见原 ref。”这可以用已有字段表达，不是新的固定报告表单。

不用条件与推翻：开放发现或长问题不强求当前 A/B。如果短卡诱导假确定性、父频繁恢复全文，或判断改善没有抵消 child 与整合成本，回到更合适的研究形式。

7.4 辨别性取证与证据请求

窄命题：当多种解释都符合当前历史时，研究者请求一个能产生不同预测的观察，父按预算和不可逆成本选择执行，比继续总结相同轨迹更有助于更新认识。

先用公开历史、准确资源读取、当前纯计算补缺；需要真实环境变化时，研究者提供候选 probe、不同解释的可见预测、适用状态和停止条件，父判断是否值得行动。取证结果按精确 ref 经 runtime 直接回到同线，父只接收当前关键变化，减少全文搬运。

升级顺序：只读证据请求→父选择一个真实 probe→新的 canonical 结果→同线修订。只有逐次父转发成本被证明明显时，才评估受限动作 lease。普通 delegate 已有显式 lease，Auto-Research 仍只读，不能把当前能力继承成研究动作授权。

不用条件与推翻：预测无法区分、目标已明确、风险不清楚且无法承受，或探测关闭重要选择时不用。若所谓实验只有多个模型同意、没有新环境证据，应保持未验证。

7.5 预测差异驱动的注意与修订

窄命题：利用已经存在的 expected outcome 与真实结果，对当前选中方法的明确差异投影一次短事件，可减少旧方法在反证后的继续使用，避免按固定窗口重复复盘。

先复用已有 validation/effect 证据。runtime 只比对已明确且可计算的预测、版本和结果；Agent 判断差异意味着假设错误、观测不足还是正常例外。没有结构化预测时，不强迫每动作补一张预测表；让 Agent 在值得检验的节点提出。

注意事件默认不阻断行动，不设置“看过才可行动”的新门禁。只在具体授权、预算、版本或状态边界上硬拒绝。

推翻：变化太频繁、误报多、通知引发无效研究、总成本增加但没有减少错误坚持，应收窄或撤下触发。

7.6 短时域、反馈驱动的行动程序

窄命题：某方法在多次当前状态中确证有效后，把它表达为参数化的短程序，并在每步重新观察与检查停止条件，可以减少成熟操作的父管理成本。

与保存旧 action 列表不同，程序需要明确何时开始、从当前观察读取哪些变量、如何选下一步、何时停止或退回父。阶段切换、不可解释效果、状态指纹变化、预算触达和动作错误会结束程序。纯计算可重复，真实 action 不能静默重放。

现有 arc_actions 是已计划动作的上层批量执行，不自动等于反馈闭环的 option；普通 delegate 的 lease 提供权限基础，也不证明子模型程序更好。应先做条件 Skill，父逐步使用；成熟后才测试短 lease 的收益。单个环境写者与 canonical 顺序继续保持。

推翻：错误状态下仍执行旧坐标、程序未读必要反馈、损失动作或收缩任务机会，即使 token 下降也拒绝晋升。这是高潜力但风险与验收成本均较高的候选。

7.7 独立视图的反例复核

共享父结论可能造成共享偏差。需要复核高影响解释时，可授权一个有界 worker 先读原始证据、隐藏父结论，独立提交竞争解释后再揭示分歧。复用研究线、上下文 recipe 与真实 read 权限，先确认盲审条件确实生效。

它的收益是减少错误坚持，不是投票增加“置信度”。只给局部证据也可能误判；结论必须明确可见范围。没有重大解释分歧时，不常驻一个审查 Agent。

7.8 有界计算选择与停止

父在行动、研究、建能力之间的投入选择本身需要优化。先复用任务预算和 remaining horizon，做一次简短判断：“缺什么、能否改变当前决定、结果能否及时到达、复用能否回本”。runtime 继续强制机械预算和取消；不新增常驻计算总控。

可以由授权 Agent 给持续职责设科学等待条件与停止理由，机械调度处理无新材料/预算/终局。如果最终要训练或自动估值，需要可归因的真实数据、校准与独立对照；目前没有这些证据。

7.9 不建议作为近期默认的机制

  • 每窗口建 worker、固定全岗位研究团队、每动作强制 review 或预测报告：先支付持续管理成本，价值仍未知。
  • 用多个 LLM 一致意见自动升级规则、由 runtime 从 prose 判定科学结论：混淆独立证据与模型重复。
  • 让研究直接写并选中父 Harness，或让多个 child 同时写共享环境：破坏授权、时效和可归因性。
  • 把想象 rollout、保存帧重放、旧成功动作序列当新状态可执行收益：未真实发生的环境结果仍是假设。
  • 同时替换 scheduler、知识库、组件 DSL 和执行引擎：多因素变化无法定位收益；现有可达基础应先复用。

推荐结构仍覆盖机会→识别→投入→候选→装配→语义使用→反馈→保留/修订/撤下。纯结论可跳过组件候选和装配，直接进入行动反馈；父自己创建工具也可跳过研究。每次不使用应按条件判断，不能被解释成系统失败。

8.1 时效不能只靠版本号或固定 TTL

帧上计算绑定 observation identity 和 frame/cutoff；阶段假设绑定适用范围；跨阶段规则保留支持与反例。旧 ref 精确可读，不代表旧规则已适用于新状态。runtime 能检查机械身份和已声明的版本依赖；语义适用性仍由 Agent 判断。暂不新增“一过 N 动作全部过期”的硬策略。

urgent 只能在合法父决策边界提示；已提交动作不能因后来结果被取消成没发生。仅与过去帧相关的值可进入历史索引，当前反证优先短交付。若报告需要关键详情才能改变计划，按原 ref 恢复，恢复费用计入总成本。

8.2 动作、研究和 Harness 作者边界

Auto-Research 当前只读；普通 delegate 的有限动作授权与研究 assignment 分开。新研究 probe 或草案权限若将来引入，必须准确表达 scope、预算、state/version、撤销与结束条件，不由职责名称暗中继承。研究 worker 的停止不代表底层请求已成功取消；取消失败与在途未知继续记录。

建议继续遵循：ARC adapter 只执行公开环境合同；证据权限、lease、调度和语义选择放在 Agent runtime/Agent 一侧。派生对象、shape、motion 是 Agent 能力，不作为隐藏状态或因果真相注入。[S15]

9. 优化与重构路线

阶段 0：冻结证据并定位最早断点

复用当前 development-workflow、已有源码快照、成本与机会漏斗。区分“没有值得研究的机会”“已识别但不投入”“研究结果过时”“父转化失败”“用后没有任务贡献”。不修改全部提示去提高调用率。

已有改进直接保留：ARC 首次研究准备、默认高级 schema 披露、source/准确帧绑定、取消和完整参数校验。根据当前状态修正旧按需文档。B9 已完成的项不重新排成新的重构任务。

阶段 1：一个低成本窄循环

优先选择实际轨迹中的一个重复负担。若是目标解释错误，试“原 report 的判断变化/反证短交付→真实后轮修订”；若是重复纯计算，试“现有最短作者路径→正确语义值→后续不同输入复用”。一次只改一个主要因素，不把两种结果混为一个优化。

停止点：在组件表达或基础权限完整性处失败就回到该断点；已用但无决定价值就缩窄用途；普通样本无适用机会判不确定。没有必要继续展开更复杂研究计划。

阶段 2：把持续研究调到合适的证据节奏

已有 worker 保持，研究者在 checkpoint 中表达等待何种证据和当前相关性。先测原有触发的费用，再决定是否引入可计算的事件过滤。通知仍用现有短卡和 exact publication；关闭不值得继续的职责。

父子通信优先复用直接只读资源路由、现有 experiment_request 和反馈同线，避免大结果每次先经过父模型全文再转给 child。这属于既有延期 C 项的窄验证，不需要重新定义 ARC adapter。

阶段 3：条件进入的较大重构

升级条件可进入的改动必须保留/先验证
最新短路径下，父反复转写仍占主成本，合法候选经常转换失败调整作者合同：允许明确授权 child 写隔离完整草案，父审阅精确草案后提交。另立 ADR；当前父作者规则确实被改变。无自动采用、无直接写父 Harness；内容权限与版本验收。
短交付频繁过时或父必须反复读全量报告收敛为按当前选择投影的 read view，复用原报告与研究线。原始证据、分歧、长期问题恢复；不再维护第二套认知库。
父逐次 probe 转发形成已测成本，且动作有可验证边界评估已有普通 lease 合同的受限研究用途。研究动作权限的独立变更；单写者、状态绑定、不可逆成本与取消竞态。
当前受限 source 引擎仍阻断主要纯计算，非机械合同问题在冻结输入上比较受限执行与受约束普通代码执行。先测表达、隔离、权限、限额和总成本；没有结果前不替换引擎。

较大重构的本质应是减少父重做工作和错误状态传播。重命名研究平台、增加一组模式标签或统一所有对象为一个新框架，缺少任务收益理由。

与当前 P0–P7 方案的关系

现有 P4 已覆盖输入/生成成本与连续性，P5 已覆盖持续研究与采纳反馈，P6/P7 覆盖普通采用、对照与退休。本文补充功能定位和优先级，应并入其语义交付、时效与实验切片。无需再开第二条全面实现路线，也不能把本次方案落盘当作 P5 或延期 B/C/D 完成。

新增与移除的运行负担应按候选分别核算。近期目标是不增加常驻 worker、提醒、强制字段或语义 action gate；可能增加的是按需交付的必要信息，可能减少的是重复详情、父搬运与过时研究。若引入隔离草案、lease 或新计算引擎，单独计入开发/运行/恢复成本。

10. 有界评估与推翻条件

以下是未来协议建议，本次不执行。现有其他 chat 的运行授权和预算不能被本文自动重复分配。模型、provider、有效配置和版本必须在执行前锁定；无法对齐的任务初态应披露比较限制。

10.1 先选一个可推翻命题

候选命题比较器与主要变量支持信号推翻/不确定
判断差异短交付比原投影减少整合成本同一研究内容：原 report 投影 vs 当前判断变化投影；其他权限、预算、工具不变。实际后轮利用反证，首次有效决定更快；总成本和质量满足预定标准。恢复全文变多、丢关键反证、成本不降且质量无增；缺少真实机会判不确定。
反证/依赖状态减少认知回退复用原 checkpoint，仅改变关键认识的投影；固定生成设置。真实压缩/恢复后避免重采已排除解释，必要证据准确恢复。只有文件可读而判断未变化；新增摘要造成驻留和错误固化。
小纯 Tool 在剩余任务回本同类计算：现有方式 vs 一个参数化 Tool；固定观测与任务语义。至少一次后来不同输入正确复用，父子总成本下降且决策正确。只在 guided 冻结帧成功；首次建设后没有使用机会；结果错误或无选择贡献。
辨别性证据请求能结束重复研究相同待辨别问题：继续读历史 vs 一个父选择的取证；动作成本计入。真实新结果支持排除/修订，任务预算内进展改善。预测相同、证据被污染、损失不可接受、反复请求但不更新。

10.2 分层验证顺序

  1. 功能诊断：冻结公开输入验证版本/权限、状态绑定、短卡完整性、超时/取消、过时/重复、空结果、length 与恢复。纯函数可核对真实数值；数据来源不泄漏隐藏状态。
  2. 接线验收：若宣称研究→路由→任务内 self-harness 闭合，执行真实 arc-harness-smoke，覆盖官方 ARC bridge、Pi 父、broker/child、结构化返回、router、native mutation、五类组件、action、后续真实父轮及两类 provider length。判定语义输出，不能仅看 completed。
  3. 普通采用：普通任务中自主识别与投入，观察合理不使用、放弃、修订和后轮影响。显式“请用机制”样本只用于诊断。
  4. 净收益：独立新 run 的匹配对照；每局各自产生不可回退历史。没有真实 provider，最高只证明接线/诊断。

10.3 建议的预算与样本分配

为与当前项目最新验收口径保持可比较，未来可采用每 run 最多 50 个实际动作或 30 分钟，先到者停止；同时保留单次父子 reported 上限，例如现有 120k。预算、取消或提前终局若更早停止，明确记录，不能声称达到 50 步/30 分钟。usage 阈值是止损口径，存在供应商结算与未知在途成本，不是硬计费承诺。

一个候选先做有限诊断，然后用当前冻结版 vs 单因素候选，不同时展开三臂。可先 1 对探索确认协议可判别，再预登记 6 对确认样本，两个游戏各 3 对：12 个 run、最多 1.44M known reported（若每 run 120k）。探索与确认分开计；若探索也用 2×120k，总候选预留最多 1.68M known，另保留未知费用状态。具体额度须在未来执行授权内重新核对，不能复用尚被其他实验占用的余额。

模型可先选择现有 yibu / gpt-6.1-sol；确认后再独立检验 qwen3.8-27b，不把两种模型样本混成机制平均收益。API、effort/thinking、输出上限、观测模态、依赖和 Pi 版本均固定；有效 provider 请求与源码 manifest 对齐。运行顺序交错或随机化，初态/种子可对齐时配对，不能对齐时分别列限制。6 对只是小样本检查点，通常不足以证明泛化。

主要质量指标按游戏预先选择：任务成功/关卡进展优先，无依据的对象接近距离不当奖励。候选若只降低 token，但显著损害任务进展，应否决。建议把“成本至少降 15%，主要质量非劣”作为效率假设的预登记候选标准；质量容忍幅度必须由任务规则给出，样本不足以确认非劣时结论是不确定。质量提升路线则在相同总预算比较成功/进展，不事后换指标。

10.4 必须同时测量的东西

  • 任务：真实动作、失败/无效动作、成功与阶段进展、固定墙钟下的进展；保持原始 canonical 历史。
  • 行为：适用机会分母→识别→投入→结论/候选→装配→实际使能→语义使用→反馈；合理不使用、弃用、过时报告也进入审阅。
  • 总成本：父及所有 child 的 input/cache/output、可用 reasoning、失败/取消/pending、恢复与管理调用；output 已含 reasoning 时不重复加。
  • 时效：首次有效行动延迟、研究响应到父决策的间隔、过时/漏交付、CPU/模型计算时长和实际墙钟；并发重叠不按调用时长之和当墙钟。
  • 连续性：关键假设、已排除解释、反证、未完成实验与决策理由是否跨压缩/阶段仍影响真实判断。
  • 维护：默认常驻 schema/prompt 增减、必要父语义决定和管理轮、开发验证投入。宿主开发成本与游戏父子成本另报。

tokens、图像计量、JSON 字符、传输 bytes 与现金费用保持不同口径。缺 reasoning 或取消账单保持 unknown。离线重放可检查工具与接口，不能替未发生的真实动作计算因果收益。

10.5 必须有的负例与停止规则

负例覆盖无价值机会、一次性问题、无新证据、ref 很多但无科学进展、过时阶段、独立分歧、错误/空结构化报告、预算不足、撤销竞态、length、压缩后早期反证、候选发布后装配失败，以及 Tool 正确却无任务贡献。

必要完整性失败立即停止该候选并定位断点。预算到达、未知费用无法控制、关键材料缺失时停止；两个系统都无可判别进展时保留不确定，不无限扩样。收益失败时先改变一个主要因素或撤下候选，不能靠增加 worker/提醒掩盖。
