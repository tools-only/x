## 1. ARC-AGI-3 in 2026: what the practical systems did

The benchmark launched publicly in March 2026 (ARC Prize technical report, [arXiv 2603.24621](https://arxiv.org/abs/2603.24621)). The frontier-model scores went 0.5% (Opus 4.6, Feb) → 7.8% (GPT-5.6 Sol, Jun) → 30.2% (Opus 5, Jul) on the official harness; third-party aggregators list GPT-6 Astra at 62.7% in Oct ([ARC results page](https://arcprize.org/results/anthropic-claude-opus-5), [benchlm](https://benchlm.ai/benchmarks/arcagi3)). Several research harnesses now clear essentially all public levels. The findings that matter for us:

**1.1 Harness continuity was worth more than a model generation.** OpenAI's post "How enabling two settings tripled our scores" ([openai.com](https://openai.com/index/how-two-settings-tripled-our-arc-agi-3-scores/); summary via [umesh-malik](https://umesh-malik.com/blog/agent-harness-design-arc-agi-3), [GIGAZINE](https://gigazine.net/gsc_news/en/20260731-how-enabling-two-settings-tripled-arc-agi-3-benchmark/)): GPT-5.6 Sol went 13.3% → 38.3% on the public set with ~6× fewer output tokens, same weights, no tools. The two settings: (a) **retained reasoning** — reasoning items carried across turns instead of dropped at the action boundary, so the model stops re-deriving its hypotheses each turn; (b) **compaction** instead of rolling truncation — the oldest turns replaced by a summary of "rules established so far" and "hypotheses ruled out", triggered near 175k tokens. Their stated diagnostic: diff the payloads of turn N and N+1; if N's reasoning is absent from N+1 it is being discarded. The 13.3% baseline differs from ARC Prize's 7.8% without explanation; self-reported, public set only.

*Relevance.* Our thin path rebuilds context per decision and our ft09 runs spent 8–24k reasoning tokens per decision re-deriving the board mapping. That is the exact failure signature OpenAI describes. Whether `yibu`/qwen exposes any retained-reasoning channel is unknown; the fallback is to make the agent's own conclusions (not its transcript) the carried state — which is what our working set tries to be. See §6.

**1.2 The winning Kaggle agent on a 27B Qwen used almost no harness machinery.** Milestone Prize #1 ([arcprize.org](https://arcprize.org/blog/arc-prize-2026-milestone-1)): Tufa Labs' "The Duck" runs Qwen 3.6 27B FP8 locally, converts the game state to Python variables, and plays by writing code in a live REPL. Context is managed by **evicting the oldest messages**, keeping only the system prompt and recent history. The team reports gains came from multimodality and better base models, and that **hand-crafted tools hurt**: letting the model improvise was better. Second place (Reki, Gemma-4-31B) used a reflection memory refreshed every ~10 steps, a click heuristic for small rare-colored shapes, and a "dead-signature" rule that stops clicking object types that never cause change. Third place found that the best run **disabled all its extra machinery** and that local public-game checks were not a reliable leaderboard proxy.

*Relevance.* Our model class (qwen3.8-27b via yibu) is the same class. The strongest practical evidence for a ~27B model is: thin harness, REPL, eviction, no bespoke tools. This supports the thin-path direction and argues against adding management surfaces. It does not tell us what the Duck does about hypotheses across levels — the page gives no detail.

**1.3 Executable world models with a hard replay gate: Twin.** [Twin, arXiv 2608.14490](https://arxiv.org/abs/2608.14490) (full text read): a coding agent (GPT-5.6 Sol/Codex) maintains one Python "digital twin" with `step(grid, action) -> grid` and `goal_reached(grid) -> bool`. The harness **mechanically forbids any scored action until the twin reproduces every logged transition cell-for-cell**; each mismatch is a counterexample that invalidates the twin and forces repair. Every scored action requires a rationale tag (`MODEL:` or `PROBE:`), a validated twin, and a **hash-committed next-frame prediction made before the outcome is seen**. Result 179/183 levels, more action-efficient than humans on 88% of cleared levels; cost ~224k tokens per scored action (2.6B tokens over 25 games). Their headline lesson: *"building a usable world model turned out to be simpler than expected, whereas the harder problem is inferring the right goal."* Goal inference: when the twin validates but planning finds no route, they search the twin and rank reachable states by generic change signals (colour gone/new, local burst, big change, frontier), write a tentative goal predicate that must be false on every logged frame, and test candidates in ranked order with **permanent exclusion of rejected candidates**. Both uncleared games were goal walls, not dynamics walls.

**1.4 Transition match does not predict usefulness: Tycho.** [Tycho, arXiv 2607.28287](https://arxiv.org/abs/2607.28287) (full text partly read) compares four orchestration policies for when to build a world model: none / single actor edits it / **actor-requested delegation to a builder** / harness-triggered builder on verification failure. Actor-requested delegation won (88.49 RHAE with Opus 4.8; 100 with GPT-5.6 Sol and Opus 5). The automatic trigger reached 88% pre-action transition match versus 14–16% for the others and still scored **lower**, spending early and heavily (1,192 builder calls vs 147). Their conclusion: transition match shows the simulator reproduces dynamics, not that it has found the objective or helps the next move. Plans from the model are surfaced only while the model is unchanged and the observed frame matches a stored hash; otherwise the actor re-observes. Goal inference was the weak point: pre-action level-complete recall 20–78%, game-over recall 0% for every policy.

**1.5 Ablation of the three mechanisms.** [Rodionov, arXiv 2607.15439](https://arxiv.org/abs/2607.15439) (abstract) ablates executable world model / simplification prompts / fixed-interface replay verification across gpt-5.4–5.6. Model and effort scaling dominated; variant differences were "smaller than anticipated". Executable models were not universally better than a textual hypothesis (textual beat flexible-interface code twice). Replay **verification ranked first in every setting, sometimes narrowly, at substantially higher cost**. At max effort the plain textual variant also cleared every public level. Public-set saturation only; no held-out test.

**1.6 Programmatic memory: PRO-LONG.** [arXiv 2607.20064](https://arxiv.org/abs/2607.20064) (abstract): keep the **complete structured interaction log** and let the coding agent query it programmatically instead of loading summaries into context. +18 points over a plain coding-agent baseline across frontier models, up to 76.1% pass@1 with 4.2–5.8× fewer tokens than specialised harnesses. [Prime Agent](https://arxiv.org/abs/2608.23552) adopted its prompt and reports RHAE Best@1 30% → 95.5%.

**1.7 Benchmark critique relevant to our evaluation design.** [AERA, arXiv 2605.25931](https://arxiv.org/abs/2605.25931) (full text read) reports that every one of the 25 public games is reachable by a non-intelligent strategy: 10 in a single blind step, 5 after one probe, 8 by a single action repeated 50–200 times, 1 by repeated ACTION1. They conclude the public set cannot discriminate intelligent exploration from trivial heuristics. Their own agent is a three-phase EXPLORE / VERIFY / PLAN loop with free-text hypotheses, a VERIFY phase of 1–3 targeted falsification actions against the MAP hypothesis, and exploration stopped when the `UNCERTAIN` field is short (self-described as "a weak heuristic proxy"). Notable: a 1.5B model solved ft09 by planning alone, while the 0.5B solved it by accidental diverse exploration; three games are won by one ACTION6 that the LLM never chose.

*Relevance.* Our arm comparisons on ls20/ft09 need a **blind-strategy negative control** (repeat each action k times; one probe then ACTION6) reported next to each arm. If an arm's level count is matched by the blind control, the result says nothing about the mechanism. This is cheap and environment-agnostic.

**1.8 Other.** [Graph-based exploration](https://arxiv.org/pdf/2512.24156) (preview-era), [DiG-bench](https://arxiv.org/abs/2608.12593) (70 string-encoded discovery games with hidden rules *and* hidden win conditions, 49 private — a possible held-out family for us that is not ARC), and the community repos [leejianrong/solve-arc-agi-3](https://github.com/leejianrong/solve-arc-agi-3) (27–30B model, "hybrid hypothesis ledger and replay-verified executable world model") and [BDR-Pro](https://github.com/BDR-Pro/arc-prize-2026-arc-agi-3) (no LLM at runtime; volatility-masked state hashing — same idea as our ticker mask).

## 2. Digging patterns from history

**2.1 Failure-derived memory items.** [ReasoningBank (Google, arXiv 2509.25140)](https://arxiv.org/abs/2509.25140): after each task, an LLM judge labels the trajectory, and memory items (title, one-line description, actionable content) are distilled from **both successes and failures**; failures yield negative constraints ("confirm save state before navigation"). Retrieval by embedding similarity into the system prompt. Memory-aware test-time scaling: parallel rollouts give contrasting traces that sharpen items. Gains on WebArena/Mind2Web/SWE with fewer steps. [Code](https://github.com/google-research/reasoning-bank).

**2.2 Grow-and-refine playbooks, delta updates.** [ACE (ICLR 2026, arXiv 2510.04618)](https://arxiv.org/abs/2510.04618): Generator / Reflector / Curator roles maintain an evolving playbook with **incremental delta updates** rather than monolithic rewrites, to avoid *brevity bias* (summaries drop domain insight) and *context collapse* (iterative rewriting erodes detail). +10.6% on agent benchmarks, DeepSeek-V3.1 matching a GPT-4.1 production agent on AppWorld; adaptation latency −91%. Limitation: needs a reasonably strong Reflector. Builds on [Dynamic Cheatsheet (EACL 2026)](https://arxiv.org/abs/2504.07952), which stores strategies and executable snippets curated for correctness, generality, brevity.

**2.3 Workflow/insight induction.** [Agent Workflow Memory](https://arxiv.org/abs/2409.07429) induces reusable sub-routines from successful trajectories, abstracting instance details; noted risk: a workflow induced from a lucky run becomes a confident bad habit. [ExpeL](https://arxiv.org/abs/2308.10144) edits an insight list with ADD / UPVOTE / DOWNVOTE / EDIT from success/failure pairs; critique: all insights are concatenated into every prompt regardless of relevance. Newer: MUSE-Autoskill ([arXiv 2605.27366](https://arxiv.org/abs/2605.27366)) with per-skill memory and unit-test evaluation; Memento-Skills guards skill mutations with an auto-generated unit test before saving (+13.7 points on GAIA, per the survey summary).

**2.4 Library learning (symbolic).** [DreamCoder](https://ml4code.github.io/publications/ellis2021dreamcoder/) alternates solving tasks and compressing solutions into library abstractions (wake-sleep); [LILO (ICLR 2024)](https://arxiv.org/abs/2310.19791) adds Stitch compression plus LLM auto-documentation so the synthesizer can actually use the learned abstractions. The lesson that transfers: **compression of repeated structure across solved instances, plus documentation, is what makes a library reusable** — a raw skill list is not.

**2.5 Programmatic memory instead of resident text.** PRO-LONG (§1.6) and Prime Agent's RLM REPL (§5.3): keep everything, query it with code. [ACM](https://arxiv.org/abs/2607.23809) gives the agent memory tools to offload and later query, never discarding originals.

*What this suggests for us.* Our memory tool asks the agent to write condition-scoped evidence by hand, and 114 refusals show the cost. The papers above move the **extraction** step out of the decision turn: a separate, cheaper reflection pass over the log produces items, and the decision turn only reads. ReasoningBank's point that failures must produce items is directly our 19/24 problem — a deletion without a refutation should at least leave a note (which the lifecycle change now does). PRO-LONG/Prime Agent suggest the opposite trade for raw history: stop projecting it into the working set at all and let `run_skill`-style code query a complete log in the sandbox. We already have the persistent Python host; the missing piece is a queryable transition log in it.

## 3. Governing the trajectory

**3.1 Mechanical gates that the agent cannot talk past.** Twin's two gates are the strongest practical examples (§1.3): no scored action without a validated model, and a **hash-committed prediction before every action**. The second is environment-agnostic: the harness records `H(predicted next observation)` before acting and scores it after. It costs no extra model call when the prediction is part of the action call. It turns "I expect X" into a scored event, which is what our `expect` free text ([ledger design](../plans/2026-10-09-lightweight-hypothesis-loop-with-critic.md) §3) lacks. Rodionov's ablation (§1.5) is the caution: verification helped in every setting but at substantial cost, and the margin shrank with model strength.

**3.2 Critics: when to speak, and persistent notes.** [Opera (arXiv 2609.33987)](https://arxiv.org/html/2609.33987v1): a critic organised around a **persistent note** — one diagnosed issue, its current guidance, and a fixed resolution criterion — so follow-up is judged against the original problem rather than the latest advice. [SAG (arXiv 2610.07335)](https://arxiv.org/html/2610.07335): action-level ambiguity gates whether to query a critic (value-of-information), and critique usage falls as the actor improves. [CAST (arXiv 2608.30147)](https://arxiv.org/pdf/2608.30147): Reflexion/Self-Refine critics condition on later observations the actor never had; a critic must judge each action with only the prefix available at that step. [LogicGuard (arXiv 2507.03293)](https://arxiv.org/pdf/2507.03293): temporal-logic critic that blocks redundant/failed actions.

*Relevance.* Our critic (revision 2) already has a notebook and `evidence_through`/`delivered_at`. Opera's addition is the **fixed resolution criterion per note** — a note is closed only when its stated criterion is met, not when the parent says "noted". Our C2 observation that the parent wrote "my plan is to keep grinding" after the critic spoke is the case Opera targets. CAST's prefix-only rule is already respected by our dossier (no parent transcript).

**3.3 Loop and stall detection.** The production literature converges on cheap signals: repeated action signature (identical argument hashes), flat progress, same state across consecutive steps; [HORIZON](https://arxiv.org/html/2604.11978v1) names sub-planning errors and *state desynchronisation* (the agent believes the environment changed when it did not) as dominant long-horizon failures; one stress benchmark defines "circular retry loop" as re-executing an identical failing command 3+ times with minor variations. [IAL-Scan](https://arxiv.org/html/2607.01641v1) reasons about *bound coverage*, not whether a limit exists. Our repetition detector (masked state, action, outcome ≥2) is in this family; the ls20 finding that the move-budget bar makes every state unique is why masking must be learned or declared, not fixed (BDR-Pro's "volatility-masked state hashing" does exactly this: mask cells whose change rate is high across the log).

**3.4 Process-level training signals** (RePro, Agent-R, IPR, CompactionRL) need training; out of scope for a frozen provider, listed for completeness.

## 4. Maintaining and tracking competing hypotheses

**4.1 Analysis of Competing Hypotheses (Heuer).** The intelligence-analysis method: hypotheses as columns, evidence as rows, each cell consistent / inconsistent / n.a.; **work across the matrix one piece of evidence at a time**; sort evidence by *diagnosticity* (evidence consistent with all hypotheses has none); prefer the hypothesis with the least inconsistent evidence, not the most consistent. [EMR-ACH](https://github.com/ApartsinProjects/EMR-ACH) automates this with LLMs: indicators are generated contrastively (each must separate at least two hypotheses), diagnosticity weights are computed from the variance of an indicator's row, and non-diagnostic indicators get weight ≈0. [Dhami et al. 2019](https://onlinelibrary.wiley.com/doi/full/10.1002/acp.3550) show information gain is a usable formal proxy for diagnosticity.

*Relevance.* Our `tests=[{action, condition, observed, verdicts:{hyp: verdict}}]` is one row of an ACH matrix. Two mechanical additions follow with no new agent obligation: (a) report, per `question`, which recorded tests are **diagnostic** (verdicts differ across rivals) and which are not; (b) render the question as a small matrix rather than per-hypothesis lists, so "all my evidence is consistent with everything" is visible. This is exactly the ls20 #5 failure: the bar hypothesis was "supported" by evidence that did not discriminate it from `hyp.move`.

**4.2 Sequential falsification with error control.** [POPPER (ICML 2025)](https://arxiv.org/abs/2502.09858): an experiment-design agent proposes falsification tests of a hypothesis' measurable implications; an execution agent runs them; p-values become e-values and are combined sequentially with Type-I error control, deciding reject / continue / stop. Single-hypothesis against a null; no rival adjudication. [Code](https://github.com/snap-stanford/POPPER). The transferable idea is the **stopping rule**: accumulate evidence per hypothesis and act only when a threshold is crossed, rather than deleting on one observation.

**4.3 Experiment choice by expected information gain.** [BED-LLM (arXiv 2508.21184)](https://arxiv.org/pdf/2508.21184): maintain a hypothesis set filtered for consistency with history, choose the query that maximises EIG over it. [Model Discovery Agent](https://arxiv.org/html/2608.09696) and [LLM-IDEA](https://arxiv.org/html/2610.11253) do the same for mechanistic models; LLM-IDEA finds D-optimal, information gain and a Fisher heuristic choose the same design 95–100% of the time. [BoxingGym](https://arxiv.org/pdf/2501.01540) measures *expected information regret* and reports that LLMs sometimes "make an overly strong assumption and do not revise it after more experiments". [FalsifyBench (arXiv 2606.04751)](https://arxiv.org/html/2606.04751): on 2-4-6-style rule games, **the capacity for negative testing is the primary driver of success**. Counterpoint from [sciagent](https://github.com/ebinezer-rajaram/sciagent): EIG only discriminates hypotheses already entertained; falsification-seeking design may beat it in the open world.

*Relevance.* We should not compute EIG over free-text hypotheses. But when a `question` has ≥2 live rivals and the agent has written `tests` with conditions, the runtime can list, for each available action, which rivals currently predict different outcomes (from the agent's own recorded verdict history) — a cheap "this action is diagnostic / not diagnostic for Q" line. Semantic judgement stays with the agent.

**4.4 Weighted products of programmatic hypotheses.** [WorldCoder (NeurIPS 2024)](https://proceedings.neurips.cc/paper_files/paper/2024/file/820c61a0cd419163ccbd2c33b268816e-Paper-Conference.pdf) refines one Python transition program against unexplained transitions. [PoE-World (NeurIPS 2025)](https://arxiv.org/abs/2505.10819) and [OneLife (arXiv 2510.12088)](https://arxiv.org/abs/2510.12088) represent the world model as an **exponentially-weighted product of small programmatic experts / conditionally-activated laws**, each with a precondition and effect, weighted by agreement with observed transitions; OneLife targets a *single-life, no-reset* setting with a tight exploration budget (abstract only; full text fetch failed). [TheoryCoder](https://arxiv.org/abs/2503.20124) refines the low-level model after a failed plan using a replay buffer labelled by the high-level abstraction. [CASSANDRA](https://arxiv.org/pdf/2601.18620) and [OPINE-World](https://arxiv.org/html/2607.01531v1) extend to stochastic and ontology-error-prioritised exploration. Curated list: [Awesome-Code-World-Models](https://github.com/lxycopper/Awesome-Code-World-Models).

*Relevance.* This is the principled version of our `skill` + `predicts` idea from the [evidence board](../plans/2026-10-08-self-harness-evidence-board.md): many small predictors, each scored by the runtime against canonical transitions, none ever deleted by code. The board never got a `predicts` declaration from qwen in 2/2 real runs. Twin and Tycho suggest the fix is **not** a declaration field but a contract: the harness requires a prediction (hash) per action from whatever the agent uses — a skill, a program, or its own head — and scores it. Nothing about this is game-specific.

**4.5 Goal hypotheses are the hard part** (Twin §1.3, Tycho §1.4). Both systems keep rival **goal** candidates with permanent exclusion of rejected ones and generic change signals for ranking. Our ls20 failure (bar read as goal) is of this kind. Generic, non-ARC signals they used: colour disappears / appears, local burst of change, large change, frontier of reachable states. These are representation-level facts an adapter can expose without interpretation.

## 5. Self-harness: agents that build their own prompts, skills, tools, memory, subagents

**5.1 Runtime self-evolution.** [Live-SWE-agent (arXiv 2511.13646)](https://arxiv.org/abs/2511.13646): starts from a bash-only scaffold; a lightweight **step-reflection prompt asks at each step whether creating or revising a tool would accelerate progress**, making tooling a first-class decision alongside ordinary actions; no offline training, model-agnostic; 75.4% on SWE-bench Verified. The authors contrast with offline self-improvers (SICA, DGM, HGM) that need costly benchmark loops. [Hyperagents / DGM-H (Meta, arXiv 2603.19461)](https://huggingface.co/papers/2603.19461): the meta-level modification procedure is itself editable; introduces `improvement@k`; improvements like persistent memory and performance tracking transfer across domains. [Mendel Gödel Machine](https://arxiv.org/pdf/2608.07645) frames runtime vs. population-level evolution.

**5.2 Harness-held component types with no gate.** [Prime Agent (Prime Intellect, arXiv 2608.23552)](https://arxiv.org/abs/2608.23552) (full text read) is the closest architectural match to ours: a Continual Harness with four typed entries — **prompt notes, memories, skills, subagent specifications** — created by the agent during a trajectory or by a background `/refine` call over relevant events, applied only at turn boundaries, versioned with provenance and rollback, local-to-session or marked global. **No evaluation gate** before persisting: in Factorio the agent found an RCON exploit, used it despite an anti-cheat heartbeat, and *saved it as a reusable skill*. Their listed limitation: "models struggle with allocating subagents, managing retained information, and refining reusable state; many capabilities go underused because models weren't trained to operate them." Their ARC-AGI-3 result (30% → 95.5% RHAE) comes from the REPL and PRO-LONG prompt; the paper does not say what components the agent built there.

*Relevance.* This is independent confirmation of our month-long observation (zero autonomous adoption): a frontier-model harness with the same five component kinds reports that the model under-uses them. The two mitigations in the literature are (a) Live-SWE-agent's per-step *question*, cheaper than our resident catalogue but still a resident obligation, and (b) moving creation out of the decision turn into a background refinement pass over the log — which is what our consolidation step and analyst already are. Prime Agent's exploit-as-skill case is the argument for our `trial`/`predicts` scoring, but as scoring, not as a gate.

**5.3 Skill gates and the capability ratchet.** MUSE-Autoskill and Memento-Skills gate skill mutations with generated unit tests. [Safety in Self-Evolving LLM Agent Systems (arXiv 2606.23075)](https://arxiv.org/pdf/2606.23075) names *capability monotonicity*: evolution almost never selects for capability reduction, so a harmful or wrong tool that once proved useful persists — "an irreversible ratchet". Our 2 skills / 5 versions / 183 executions in the 319-action run, with outputs never semantically re-checked, is a small instance.

**5.4 Who decides when to build.** Tycho's four policies (§1.4) are the only controlled comparison I found: actor-requested delegation to a builder beat harness-triggered building, which spent heavily early. [Prime Agent] and [The Duck] both leave strategy construction to the model. This matches our development rule (no new workers or gates) and argues against an automatic "build a predictor now" trigger.

**5.5 Surveys** for orientation: [Gao et al., TMLR 2026](https://arxiv.org/pdf/2507.21046); [Xiang et al. 2026 + repo](https://github.com/XMUDeepLIT/Awesome-Self-Evolving-Agents); [Self-Improvements in Modern Agentic Systems](https://arxiv.org/pdf/2607.13104); [agent system and harness design survey](https://arxiv.org/pdf/2606.20683).

## 6. Cognitive continuity across compaction

**6.1 Keep conclusions and ruled-out branches, not transcripts.** OpenAI's compaction (§1.1) summarises into "rules established so far" and "hypotheses ruled out". [Context-Folding (ICML 2026, arXiv 2510.11967)](https://arxiv.org/abs/2510.11967): `branch`/`return` actions open a sub-context for a token-heavy subtask and collapse it to a model-written summary; 10× smaller active context at equal or better task performance than summarisation baselines. [ReSum](https://arxiv.org/pdf/2509.13313): fixed-threshold external summariser (no retrieval of originals). [ACM](https://arxiv.org/abs/2607.23809), [AutoCompact (arXiv 2610.02163)](https://arxiv.org/abs/2610.02163), [Self-Compacting Agents](https://arxiv.org/pdf/2606.23525): the agent decides *when* to compact, tied to task stage rather than length (length triggers "compact in the middle of an unresolved stage whose evidence is still needed"); originals stay retrievable.

**6.2 What compaction silently drops.** [Governance Decay (arXiv 2606.22528)](https://arxiv.org/pdf/2606.22528): continuity-optimised compaction has no reason to keep a standing constraint that is "old" and not the current sub-goal. [Execution-instability study (arXiv 2608.06503)](https://arxiv.org/pdf/2608.06503): after compaction the summary is the only record for later compactions, so errors compound. [Slipstream (arXiv 2605.08580)](https://arxiv.org/pdf/2605.08580): trajectory-grounded validation of a compaction against the log.

*Relevance.* Our thin path drops the transcript every decision and rebuilds from memory + working set, which is the extreme form of "compact every turn". Our 319-action diagnosis — conditions lost, left/right tests later claimed never done — is the compounding-summary failure. The two mechanisms that address it directly: keep a **complete transition log that code can query** (PRO-LONG, ACM) so a claim like "never tested" can be checked mechanically; and make the carried state an explicit *established / ruled-out* structure rather than prose — which is what `question` + `tests` + dropped-notes already is, so the next check is whether the agent's `tests` rows actually survive and get cited, not whether more structure is needed.

| 3 | `expect` is free text no one scores; `predicts` never declared | Hash-committed prediction per action (Twin §1.3) | The action receipt records whether the agent supplied a predicted next observation (any form the adapter can hash); the runtime scores it after the action. No requirement, no gate. | +1 receipt line | Share of actions with a prediction; prediction accuracy vs. later deletion-without-refutation rate. |
| 4 | Evidence "supports" a hypothesis without discriminating it | Diagnosticity (ACH §4.1) | Per `question`, mark `tests` whose verdicts differ across rivals as diagnostic; show the question as a matrix | ~1 line/question | Share of deletions preceded by ≥1 diagnostic test (baseline: 5/24 had any refutation). |
| 5 | "Never tested left/right" claims contradicted by the log | Queryable transition log in the sandbox (PRO-LONG §1.6, ACM) | Expose the canonical transition log to `run_skill` code; the agent (or analyst) can ask "actions taken under condition C" | none resident; sandbox file | Count of memory claims of the form "never tested X" that the log contradicts, before/after. |
| 6 | Critic notes ignored ("keep grinding") | Persistent note with fixed resolution criterion (Opera §3.2) | Each critic note carries a criterion; it stays open until met; REVISIONS shows open notes | ≤1 line/open note | Share of notes resolved by criterion vs. silently dropped. |
| 7 | 2 skills, 183 executions, outputs never re-checked; exploit-as-skill risk | Score skills by prediction agreement, never delete (PoE-World/OneLife §4.4; ratchet §5.3) | Reuse the board's replay scoring for any skill that returns a predicted observation; show agreement rate next to the skill | 1 number/skill | Whether skills with low agreement stop being called. |
| 8 | Goal misread (bar as goal) | Generic change signals for goal-candidate ranking (Twin/Tycho §4.5) | Adapter exposes representation-level facts per transition (regions disappeared / appeared, change burst size, new-state frontier) — facts, no interpretation | already partly in P1 feedback | Does the agent write a goal `question` with ≥2 rivals earlier (decision index) than baseline? |

Items 1 and 2 are diagnostics that cost nothing and should precede any paid arm. Item 3 is the single mechanism with the strongest independent evidence (Twin, Rodionov, Tycho all score predictions mechanically), and it fits the existing `arc_action` call. Items 4–6 reuse existing structures.

**Not recommended from this reading:** automatic world-model builders on a trigger (Tycho: worse and dearer), EIG over free-text hypotheses (no distribution to compute over), unit-test gates on every skill write (a gate; Prime Agent and the Duck show the model under-uses creation already), and any ARC-specific goal heuristics in prompts.

**Relation to deferred items** ([deferred-research-todos](../deferred-research-todos.md)): B (research purposes and observable conditions) — §4.2–4.3 give the falsification/EIG framings; C (hypothesis → experiment → revision) — §4.1 diagnosticity and §3.1 committed predictions are the mechanical carriers; D (continuity) — §6 is the direct literature, and the compounding-summary risk is now documented by others. A (adapter boundary) — §4.5's "facts not interpretations" rule matches the backlog's canonical-observation requirement. Status of A–D unchanged.
