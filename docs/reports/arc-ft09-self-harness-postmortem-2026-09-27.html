2. 实际 Harness 组件明细

最终 assembly revision 5 精确选中了：system_prompt:induction-policy-phase1@v1、两条 Memory、tool:frame-cell-query@v1、subagent:level1-completion-audit@v1 和 skill:mosaic-answer-set-computation@v1。Research report、方法候选与复盘记录仍是各自的研究/证据数据，不是第六种 Harness 组件。

System Prompt：induction-policy-phase1@v1

承载能力：早期探索规则。要求以当前画面和确定性差分为准；维护 2–3 个关于 ACTION6 与目标的竞争假设；每次动作只变化一个区分条件，记录预测与反证；从灰色边框、彩色区域、画布/答案区、状态条、图案格等类别覆盖探测；证据未支持时不臆造完整目标；目标明确后替换本阶段策略。

观察：这条 prompt 与早期探索阶段匹配，也被后续 assembly 选中。但运行一直只有这一版 phase 1 prompt；在 Level 0/1 规则已逐渐清晰、进入 Level 2 候选答案规划后，没有看到对应的 phase 2 任务级计划 prompt。阶段切换条件写在 prompt 里，未成为实际的自适应切换闭环。

Memory：4 条版本记录，当前 3 个 key

  1. action6_requires_coordinates@v1，active，task scope：“x、y 必须是 0–63 的整数；不带坐标会收到复杂 ARC action 的 400 错误。”依据 execution-observation-1。这是有明确接口证据的事实。
  2. action6-probe-0000-noop@v1，active，task scope：对最初位置的 ACTION6 探测没有可见格子变化，依据 observation-2、3。随后同 key 的 v2 被退休。
  3. action6-probe-0000-noop@v2，retired：保留版本历史，退休原因字段为“父级判断被反证或过时后重新考虑”。
  4. action6-probe-series@v1，active，task scope：“所有已探测区域均无变化”。这条总结缺少 basis_refs，且表述比证据范围更广；后续答案区点击确实改变了 6×6 区块。因此它应按关卡/探测条件限定或更新，不能作为当前全任务事实继续使用。

生命周期判断：所有这些事实都标为当前 task scope，没有清晰区分跨关卡长期接口知识、Level 0/1 规则和单次尝试状态。版本退休机制存在，但被反证的宽泛 Memory 没有同步退休。

Skill：mosaic-answer-set-computation@v1

用途：从当前帧 RLE 解析 ft09 马赛克格，计算候选答案 12 色集合并规划 ACTION6 点击，避免手工块索引和中心坐标错误。它是具体的计算流程，而非观察日志。

Skill 正文的中文要点

  • 每个块为 6×6 像素，间距/步长为 8；块中心使用当前帧重新计算。均匀块与混色图案块分开识别，灰色边框/分隔线不可当成答案块。
  • 每关先从当前帧读取中心图案，枚举身份、翻转、旋转等变换，将图案值映射为目标颜色；遇到重叠面板时显式处理所有权与优先规则。
  • 把候选集合与当前目标色集合做差，按最小差异优先试验。每次点击前重读当前块颜色；点击后核对 36 格变化、差分包围盒和 level_changed。候选完整但未通关时淘汰该假设并重新规划。

作用边界：适用范围写为 ft09 同类 6×6 块马赛克关卡，色彩映射需逐关重验。该 Skill 在 Level 2 创建并装配，但它所支持的 Level 2 候选规则没有得到通关验证，不能把 Skill 创建/投影算成效果已证实。

坐标公式存在待核对差异：Skill 正文写块中心 x=8c+6, y=8b+6；Level 2 复盘的 next_attempt 则写 x=8c+14, y=8b+6。这可能来自两套不同的列索引基准，但日志中没有把坐标原点统一解释。下一轮应在 Creator/Skill 中明确“逻辑块坐标”与“64×64 像素坐标”的转换，并以真实 observation 验证。

Tool：frame-cell-query@v1

预期用途：从 64×64 当前帧返回给定坐标颜色及每种颜色计数，减少反复手工解码 RLE。

实际实现与效果：程序表达式是 { "op": "input" }，即把输入原样返回；五次 completed 调用的日志均为 semantic_effect_observed=false、output_not_input=false。另有 26 次 failed，均因绑定快照扫描量超过准备上限（日志例值约 1.2–1.7 MB；其中一次报 1,536,551 bytes）。因此它虽然入池且被 assembly 选中，但没有实现其说明中的查询功能。

结论：本次最明确的组件实现缺陷。状态“completed”不能当作语义成功；应重新用 Tool Creator 作者化真正的 cell lookup / color-count 变换，并让 Runtime 只绑定当前帧的精简视图，避免每次扫描全量日志。

Saved Subagent：level1-completion-audit@v1

用途：只读、盲审候选完成条件；接收结构化证据后输出排序结论、区分性试验和风险，不拥有 ARC action 权限。7 次委派中 4 次完成、3 次失败；失败的 3 次均报告 300 秒 runtime budget exceeded，任务包含整帧/大量矩阵的穷举审计。

有效贡献：一个独立算术审查指出 180° 候选集差分应为 12 而不是原先写的 10；全局 180° 因重叠面板冲突无法从给定信息验证。它为 Level 1 的 M1 结论提供过审查，但第 3 关审计超时率表明委派必须拆成单面板/单候选/单统计量的短任务。

4. 关卡复盘记录：中文翻译与证据边界

以下是 task-level-reviews.jsonl 四条记录的译文摘要。Level 编号按日志内部索引：日志 level=0 对应第 1 关；level=2 对应第 3 关。

第 1 关（level 0）· 第一次尝试后 RESET：未通关

复盘摘要译文

第一次尝试共 6 次 ARC action，屏幕格子没有变化。缺参调用在零预算代价下揭示 ACTION6 需要 0–63 的整数坐标。随后测试灰边、棕红色内容块、底部色条和图案格，均为 changed_cells=0、bbox 为空、关卡未变化。RESET 也没有可见像素变化，但被消耗，之后可用 action 集合只剩 ACTION6。镜像规则与 BR 答案区异常格仍是未验证假设。

不足与经验译文

  • 3 次 validation assessment 因 target_version/evidence 引用契约失败，未完成验证账本。
  • 两次 Tool 创作失败（名称格式、表达式解析）；手工读 RLE 曾把 (44,44) 错当环格，实际是图案格中的 0。
  • 一个坐标的 no-op 只能支持该条件；需要跨区域类别覆盖，不能推出全局 no-op。RESET 在本游戏的每次尝试中是一次性的，应把每个动作按信息价值排序。

记录的下一步

装配并调用 frame-inspector 查询工具，核实镜像规则和蓝框 BR 真实违规格；再检查答案面板中心。如果仍无变化，再检验坐标是否映射到逻辑网格而非像素网格。

第 1 关（level 0）· 成功：产生 success_path 候选

复盘摘要译文

64×64 画面由 6×6 像素块构成四个 3×3 面板。蓝框 BR 面板是答案区，环绕块需镜像其中心图案：0→8、2→9。发现四个环块为 9，但规则要求 8；依次点击 (39,39)、(39,46)、(54,46)、(39,54) 后通关。

成功路径四步译文

  1. 把当前帧解析为 6×6 块，识别四个面板与蓝框答案面板，读取其 3×3 中心图案。
  2. 对 8 个环块按中心镜像映射计算目标色，并列出块坐标、当前色与目标色。
  3. 对每个违规块点击其中心坐标，检查该块变化 36 格及进度条变化。
  4. 每次点击后读公开状态；最后一个正确修复应使 level_changed=true。

适用范围与不确定性：适用于同样布局形式，但每关都必须重新识别答案面板和中心图案；不能把 Level 0 的 0→8/2→9 规则直接套到 Level 1。

失败模式译文

“任意有颜色的格子都可编辑”被证据推翻；可编辑性取决于格子在面板中的区域角色，不是是否非灰色。四次 no-op 探测与一次 RESET 消耗了动作，但之后建立的区域分类方法改善了探测。

第 2 关（level 1）· 成功：产生第二份 success_path 候选

复盘摘要译文

共使用 31 次本关 action，累计 40 次。最终规则 M1 是两个重叠的 12 中心面板 A、B 的环镜像并集：0→12、2→9、12 保持 12，答案共 13 个位置（7 个 12、6 个 9）。最初按相反映射 M2 涂了 13 块，之后整体撤销并重做；盲审 subagent 的 M1 建议帮助收敛。每次点击都会自动判定，不存在单独提交动作。

成功路径四步译文

  1. 从当前帧恢复块网格、面板中心，以及每个环块属于哪个面板。
  2. 按每个所属面板中心镜像值计算目标色，生成一致的目标表。
  3. 按目标表逐块执行 ACTION6，并检查 36 格变化；最终正确块到来前 level_changed 应保持 false。
  4. 点击后读取公开转移；最后一个正确环块应触发关卡推进。

不足与经验译文

  • 在独立审计之前先执行了错误的 M2 补集方案，造成整组撤销重涂。
  • 多次低信息 no-op 探测发生在重新解析帧和委派审计之前。
  • 重叠面板所有权规则直到 M1 确认后才被整理为可复用条件。
  • 下关应先验证唯一归属块，再碰重叠区，并在关卡切换时重读中心图案。

适用范围：适用于两个重叠的 12 中心面板；未知后续关卡中 8 中心面板是否会成为答案参与者，复盘建议在批量点击前用唯一归属块确认。

第 3 关（level 2）· RESET 后仍未通关：失败模式记录

复盘摘要译文

第一次尝试约 90 次本关动作。ACTION6 的块切换语义已确认：点击会在基础色与 12 之间切换整块；Level 2 的基础色为 8；环境每次点击后自动判定。没有单独提交动作。由于 bbox 同时带上右侧空白与第 63 行进度条，单看包围盒会高估格子范围。多组候选集合没有触发通关，最后 RESET 恢复了干净画面。

已否定集合：C0 的 A/D 镜像 10 集；A/D 的 180° 10 集；四面板 180° 及其补充集合；复制规则在四面板上的并集；底部条作为提交按钮等假设。准确集合达到 12 或 17 个目标后仍没有 level_changed，说明规则至少有一处不匹配。

RESET 与清洁状态：RESET 产生 416 格对称差，约对应 10 个块加进度条带，恢复了干净实例；但复盘明确指出旧值到新值的方向仍未由单独试验确认。运行随后在干净状态继续探索，但未能在超时前完成 Level 2。

失败模式译文

症状：按完整候选集合涂色后仍未推进关卡。
触发：假设集合被完整组装，环境却未触发 level_changed。
已反证：C0、180° A/D、180°全局及复制并集候选。
恢复/下一试验：RESET 后从干净帧重新定位中心，枚举镜像/翻转族，按候选与当前集合的最小差异排序逐一试验；每次动作验证 changed_cells 与 level_changed。
适用范围：Level 2 及同类马赛克关卡；置信度 high，边界来源为环境确认。

复盘指出的短板

  • 在被反复 toggle 污染的帧上测试大集合，没有及时回到干净基线。
  • 后续确定性 delta 与手工帧解码发生矛盾，提交候选前没有再次交叉核对。
  • frame-cell-query 因绑定快照准备大小限制不可用；全帧委派又触发 300 秒超时，迫使父 agent 手工解码 RLE。
  • 3 次块索引计算滑移；复盘要求固定转换公式、每次点击前复读目标块，并按最小 delta 排序。

5. 失败汇总与第 3 关的难点分析

本轮可核实的故障

  • 运行时限：runner 写出 TimeoutError: timed out；Pi return code 1、timed_out=true、run_complete=false。action-200-stop 记录 163 次 agent action，未达到 200 检查点。provider_error_count 和 summary environment_error_count 均为 0，但最后一条动作观察含 UND_ERR_HEADERS_TIMEOUT；遥测汇总未体现该条错误，计数口径需要校验。
  • Harness 操作失败：task-operation-failures.jsonl 共 21 条：11 条 contract_error、7 条 operation_failure、3 条 version_conflict。包括 System Prompt 名称曾使用下划线而不符合小写连字符命名规则，以及 validation assess 漏传当前 target_version 等。
  • Tool 调用失败：26 次输入绑定扫描超限；工具虽有 5 次完成，但 5 次都没有语义变换。工具的声明能力与实际程序实现不一致。
  • Subagent 不稳定：7 次调用中 3 次超过 300 秒委派预算，通常因为要求整帧分析、枚举大量候选或读取大量记录；4 次返回结果。
  • 第 3 关模型空间更大：四个面板，两类中心，多个重叠区域和变换候选；错误候选每次都需要反复 toggle 才能还原。若不固定清洁基线，下一轮 delta 计算会在污染状态上继续漂移。

为何第 3 关特别难

  1. 规则从单答案面板扩展成重叠面板集合推断。Level 0/1 的成功经验提供“中心图案映射到环块”的先验，但 Level 2 有 12 中心和 8 中心面板；哪些面板参与、重叠区谁优先、使用哪种旋转/镜像变换都需要实验证据。直接复用上关公式会误导。
  2. 界面差分不等于目标规则。ACTION6 确认会整块在 8 与 12 间切换，环境逐次点击自动判定；然而候选集合全量完成后仍未通关。每个候选都必须由精确集合和逐步证据支持，不能把涂色动作成功当成假设验证成功。
  3. 集合试错代价高且状态易污染。候选集合中常有 10–17 个块；一次错误答案要逐块撤销/重涂。约 90 次本关动作后才 RESET，清洁基线恢复较晚。下一候选前应先计算对称差，选一个或少数能区分假设的块，别先执行整套集合。
  4. 辅助组件没有按设计提供足够的计算能力。frame-cell-query 把输入原样返回，无法替代 RLE 解析；大帧绑定还连续失败 26 次。整帧 Subagent 任务超时，实际只靠一次短算术审计发现了 delta 算错和重叠冲突。
  5. 方法出现但 adoption 没跟上。Auto-Research 总结出类别覆盖探测方法，Skill 也包含候选枚举流程；不过 Research 方法链没有父 agent 接纳记录，方法和高阶 Skill 之间缺少可追踪的来源/效果闭环。
关键区分：第三关不是“完全没有策略”。存在竞争假设、集合排序、subagent 审计、RESET 恢复和 Level 2 Skill；失败在于策略候选没有在剩余运行时间内收敛出可通关集合，工具与委派又没有稳定降低每次试验的解码成本。

6. 下一步优化方向（按优先级）

  1. 先修复真实运行期限与恢复路径。定位 runner 超时来自哪一层，分别记录 Pi turn、ARC bridge request 和全局 runtime 时限；保存可恢复 checkpoint，使 163-action 超时后能从最新干净状态续跑，而不是把 max-actions=0误认为没有任何期限。
  2. 重做 frame-cell-query 的 Tool 程序。在 Tool Creator 指导下实现真实点查询与颜色直方图，并验证输出和输入不同；解析路径只取精确 observation snapshot 的 frame 节点，不扫描整个 run 目录。验收要断言语义输出、绑定字节数、超限后的有界错误和实际调用成功。
  3. 把第三关从“枚举并执行整套”改成“候选集合＋最小区分试验”。状态表记录每个候选集合、当前目标色集合、对称差、唯一归属块、预测格数、反证条件。只先执行能区分候选的最小块；候选失败后 RESET 并重算，不在未知污染状态继续。
  4. 把坐标系单一化。Skill 的 8c+6 与 Level 2 复盘的 8c+14 必须用同一组逻辑块索引/物理帧坐标例子逐项验证，再决定唯一公式，避免让已创建 Skill 固化新的坐标错误。
  5. 让阶段升级实际发生。System Prompt v1 是探索阶段策略。达到“动作语义已证实、成功条件已有至少一个可检验模型、约束范围可表述”时，主 agent 应重构到任务级规划 prompt：保留竞争性目标模型、选择试验策略、明确预算、维护回退点，并在每次关卡切换时更新。
  6. 建立 Research→Harness adoption 闭环。父 agent 读完 Auto-Research 方法候选后，判断它该变成 Skill、Tool 或 System Prompt；使用各自 Creator 作者化，创建入池，精确 assembly，后续 ARC action 引用版本，随后评估同一预测/反证，最后把效果反馈给同一 Research line。
  7. 提升 Memory 的生命周期和证据粒度。把通用 ACTION6 参数契约标为 task 级；把面板映射、目标集合标为 level/attempt 级。所有 Memory 必须引用 observation；一个坐标的 no-op 保留精确坐标、区域类别和当前状态，出现反证时自动进入退休/修订候选。
  8. 缩小委派任务并给出可判定输出。拆成“核对一个变换的镜像索引”“检查一个重叠区冲突”“审核一个候选集合 delta”这类任务，输入用结构化矩阵而非整帧长日志；300 秒超时后立即重试缩小任务，并把研究结果保留为候选证据。
  9. 验证成功路径真的减少后续工作。Level 0/1 路径现在是有证据的候选方法。后续同格式实例应读取相应路径、执行并记录动作/工具/Token 成本；只有可比条件下复用成功，才能把 proposed omissions 记为实际节省。
