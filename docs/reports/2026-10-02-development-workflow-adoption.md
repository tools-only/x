# 开发流程采用与下一轮验证

日期：2026-10-02（Asia/Shanghai）。状态：流程已采用；运行时收益未验证。

## 问题与命题

用户报告机制反复在功能/冒烟测试通过后出现真实运行未触发、上下文负担和能力退化。本轮目标是把开发、评审和完成声明统一到 [开发流程](../development-workflow.md)，让后续变更通过真实问题、低成本生命周期和分层证据接受审查。

本轮命题限于可检查的工程结果：开发入口能够找到同一流程，变更有可复用的运行前协议和分层完成标准，既有 ARC 接线门槛不被削弱。它不声称文档已改善 Pi 游戏表现或保证所有未来 Agent 遵循。

## 设计与成本

根 AGENTS.md 保留短约束与强制读取指针；README 开发入口提供步骤；模板可复用已有计划/报告。详细标准只在 development-workflow.md 维护。本轮不增加 Pi 常驻提示、tool/schema、管理调用或 runtime gate，不改变创作/装配权限和观测契约。模板属于开发记录，不要求父 Agent 在游戏中填写。

采用简化与证据分层优先方案；强化提示和增加管理 Agent 仍可作为有成本的候选。完整规范常驻会增大开发上下文，因此按任务触发读取。文档提供持久约束入口；尚未用真实开发会话验证其遵循效果，也没有将语义收益判定伪装成 CI 检查。

## 下一轮最小实验协议（尚未执行）

候选命题：“面对任务中重复的可确定性计算，父 Agent 能自主创建、装配并语义使用一个工具，后续同类计算的任务质量保持，父子总计算与管理成本下降。”这是一项候选检验，不预设一定应创建工具，也不授权实施所有减负设计。

1. 先按当前代码和最新可用真实轨迹审阅机会：计算是否重复、输入输出是否可定义、未来是否有足够复用、现有工具是否已解决。标明适用/不适用/未知及证据。若找不到适用机会，缩小命题或选择新诊断任务，不强迫游戏产出组件。
2. 用当前版普通真实 provider 运行观察漏斗，不使用闭环 probe 或必须创作的指令；定位首次授权、候选、装配、使用及反馈的断点。窄能力任务用于诊断时单独标注，不能替代 ARC 自主采用证据。
3. 只为已发现断点选择一个主要改动；保留父语义作者和装配选择。测量首次使用前的模型决策/往返及后续复用成本。
4. 在启动前填明实际模型/推理设置、任务/可对齐初态、当前版和单因素 treatment、重复次数/顺序、时间/动作/父子预算、停止规则及质量/成本判定阈值。参数未定前不执行、不选事后阈值。需要整体机制收益时另加无机制最小基线。
5. 覆盖无复用收益、预算不足、负收益/错误输出和过时的相关负例；记录合理不使用与放弃。ARC 用独立运行对照，不能在单次生命中回退模拟未执行路线。
6. 按四层记录结果。自主使用但无收益，或收益以超预算为代价，均不声明优化成功；若仍不触发，继续诊断具体环节，优先降低成本而非增加义务。

本轮仅落地开发流程，未启动真实模型实验，也未重启用户已关闭的运行。下一次相关开发在既有授权范围内按本协议具体化。
