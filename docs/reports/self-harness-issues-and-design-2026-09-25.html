3. 目标结构与资料流

ARC adapter → canonical observation → Agent runtime 的派生视图／checkpoint
                                      ↓
主 Agent：对象／目标／约束／计划的假设与方法机会
   ├─ creator → 父侧候选内容 → task_harness → 版本 pool
   │                                      ↓ 主 Agent 精确装配
   │                                    Skill／Pi Tool／Subagent／Memory／system
   ├─ Auto-Research child（只读）→ 有依据的报告／实验请求
   │                                      ↓ 主 Agent 选择
   └─ arc_action（单一动作所有者）← 计划／已选择的方法
                         ↓
              observation → 使用评估／研究线反馈／组件修订

task_prompt 是装配的输出通道，可纳入从 Memory、研究报告、方法、计划等精确来源产生的内容。它不是 Memory 专属位置，也不是第六类持久组件。整个设计保留父 Agent 为语义作者和唯一环境动作决策者，runtime 只处理确定性边界。

4. 拟议的三项架构决策

ADR-01（拟议）：评估事件绑定“使用版本 + 观察”，而非只绑定未评估创建决定

背景：一次创建的组件可跨多关持续使用，单次 assessment 无法涵盖适用边界。决策：接受显式 decision_id；若输入有 observation_refs，则基于实际引用的精确版本生成候选 decision 列表，允许已有 assessment 的决定重复评估。多个匹配返回候选与完整重试模板。若为 retire／absence 评价，使用投影缺席证据的独立语义，不要求动作引用一个已退役资源。

代价：同一资源可产生多次甚至互相矛盾的 assessment，需按范围、时间和证据展示，而不能取最后一个覆盖旧结论。备选：强迫父 Agent 永远显式填写 decision_id；更简单，但真实调用已反复遗漏，不能修复默认行为。

ADR-02（拟议）：将研究报告变成可选择的决策候选

背景：报告1、2已经有机制判断和实验建议，但“完成→影响行动→得到新证据”的关系需要精确记录。决策：现有 research inbox 增加轻量决策卡，引用报告精确版本、证据、当前状态版本、候选行动、替代结果和停止条件。父 Agent 明确采纳、驳回或延期；runtime 仅转发和记录。过期状态只提示重核，不自动执行。

代价：多一次短的决策记录与少量上下文；可用只展示当前相关卡控制成本。备选：自动执行研究请求；会越过主 Agent 唯一动作所有权，故不选。

ADR-03（拟议）：保留准入边界，缩短创建入口的模型契约

背景：候选缺 key、validity、semantic_kind 或 review 数组形状导致重复失败。决策：公开界面按 change／review／assess 的当前上下文给完整短模板；响应给缺失字段、原输入保留引用和针对性重试；内部仍调用同一 preflight 与原生写入器。Skill 正文、Tool 程序、Subagent instructions 仍须由父 Agent 通过对应 creator 撰写。

代价：模板和实现契约需要同步测试；它不保证模型产出好方法。备选：再加一个完整 method 档案或研究完成门槛；会阻止早期试用，无法解决参数形状错误。

5. 按阶段实施与验收

阶段工作验收证据
一：消除闭环断点修复复评选择和退役评价；给 review/change 的错误增加精确修复提示；保留输入候选。第20步同型场景可自动绑定方向 Memory decision-1 再评估；已评估过的 Skill 仍可跨关复评；多候选返回选择而不误判。
二：研究反馈对报告1、2做父侧采纳与行动引用核查；实现当前相关的建议卡和 outcome 回流；第三个 active session 先核验进程，再判断是否需要恢复。真实 ARC 中至少一条问题链包含：研究报告→父决策→环境 action→新 observation→研究结论修订或明确未决；反例与未采用理由可检索。
三：方法质量检查 grid-delta-probe 的实际触发、失败样本和适用边界；必要时出 v2；评估重复计算是否值得 Pi Tool。展示至少一个有效使用和一个挑战／反例，说明动作选择与 Skill 步骤的关系；若建 Tool，要求实际调用与语义输出，而非只有入池。
四：跨上下文与架构审计压缩前后关键未决假设；把 adapter／runtime 契约落盘并做边界迁移。真实输入侧可看见未完成实验和精确依据；bridge 只负责环境动作与公开结果，Agent 侧研究视图独立。

端到端线路验收仍使用真实 ARC bridge、Pi 父循环、child broker／process、结构化返回、代码路由、原生组件写入、后续 ARC action 和下一次父轮，覆盖 system_prompt、Skill、Memory、Pi Tool、Subagent 及 Auto-Research／普通 delegate 的 length continuation。确定性 provider 测连通；真实 provider 测自主转化、研究收益和游戏表现。每个结论按覆盖范围报告，不用局部绿灯替代整体。

6. 故障模式与成本约束

  • 重复错误修复消耗行动窗口：review 和 change 的最小修复应保持 pending opportunity、原候选及其证据；不要让一次契约错误抹掉方法机会。
  • 研究建议过期：比较 as_of_event 与当前状态；过期时主 Agent 重核前提，不直接执行旧动作。
  • 错误的使用归因：把“版本被选中”“正文被读”“decision 引用”“具体步骤成功执行”分列，工具输出要验证语义。
  • 上下文成本：只向父 Agent 展示当前相关研究卡，完整报告按精确引用读取；保留 canonical evidence 与压缩视图的来源关联。
  • 权限与安全：Pi Tool 仅运行已披露的纯表达式／授权 adapter 操作；child 没有 ARC 写权限；版本引用和 scope 检查维持。
  • 测试漂移：51个现有失败逐类处理，区分真实回归、旧契约预期、测试 fixture 和环境依赖；不能通过放宽语义断言制造全绿。
